# 知识图谱设计方案调研

## 概述

本文档调研业界主流知识图谱可视化设计方案，涵盖布局算法、交互模式、状态管理、性能优化四个维度，为当前系统的知识图谱迭代提供参考。

---

## 一、布局方案对比

知识图谱可视化中，布局算法决定了用户对数据结构的直观感知。三种主流布局对比如下：

### 1.1 力导向布局 (Force-Directed)

当前系统采用的方案。模拟物理弹簧系统，相连节点互相吸引、不相连节点互相排斥。

| 优势 | 劣势 |
|------|------|
| 通用性强，不依赖数据结构预设 | 非确定性：同一数据多次运行结果不同 |
| 自然形成聚类，符合 Gestalt 邻近原则 | 计算成本 O(N²)，节点 200+ 时明显卡顿 |
| 视觉美观，有机形态 | 节点可能重叠，需要后处理 |
| 用户学习成本低 | 低分离度聚类辨识效果差 |

**适用场景：** 社交网络、网络拓扑、探索性数据分析

### 1.2 层级布局 (Hierarchical/Tree)

上下或左右展开的树状结构，父节点在上层、子节点在下层。ELK、dagre、Sugiyama 等算法实现。

| 优势 | 劣势 |
|------|------|
| 父子关系一目了然 | 仅适用于严格树/无环图 |
| 确定性，结果可复现 | 存在交叉边（REQUIRES/RELATED_TO）时不可读 |
| 计算快，结构规则明确 | 宽而浅或深而窄的树浪费空间 |

**适用场景：** 组织架构图、文件系统、分类体系、教学大纲层级

### 1.3 径向布局 (Radial Tree)

以焦点节点为中心，连接节点按同心圆排列。节点距中心的距离编码跳数（hops）。

| 优势 | 劣势 |
|------|------|
| 聚焦单一节点，适合"下钻" | 密集图中心区域连线纠缠 |
| 空间效率高（优于层级布局） | 节点排序对可读性影响大 |
| 2025 年 IEEE TVCG 研究表明其聚类辨识准确率和速度优于力导向 | 图密度增加时星爆效应明显 |

**适用场景：** 以某一课程/章节为中心的子树探索

### 1.4 混合方案

**力引导 + 径向树混合布局**（2022 年提出，2024 年 IEEE VIS 竞赛论文验证）：
- 力引导阶段形成全局聚类结构
- 选中节点后切换为以该节点为中心的径向布局
- 实验表明混合方案在聚类计数任务中准确率和速度均优于纯力导向

```
[初始状态]                     [选中节点后]
力导向全局视图          →      径向展开局部视图
(所有 Course 节点)            (选中 Course 的 3 层子树)
```

### 1.5 布局选型建议

| 场景 | 推荐布局 |
|------|----------|
| 全局总览（所有节点） | 力导向 |
| 聚焦单个课程 | 径向布局 |
| 聚焦章节/知识点 | 力导向（小图力导向效果好） |
| 课程层级结构 | 层级布局（自上而下） |

## 二、交互模式设计

### 2.1 Shneiderman 信息搜索原则

经典的可视化探索三阶段：

```
Overview first → Zoom and Filter → Details on demand
  （概览）         （缩放与过滤）        （按需获取详情）
```

### 2.2 渐进式信息披露 (Progressive Disclosure)

2025 年多篇论文共同指向的核心设计原则：不要一次性展示全图，而是逐层展开。

**实现层次：**

```
Level 0: 仅显示 Course 节点（3-8 个）
    ↓ 点击课程
Level 1: Course + 其下 Chapter（+5-15 个节点）
    ↓ 点击章节
Level 2: Chapter + 其下 KnowledgePoint（+10-30 个节点）
    ↓ 点击知识点
Level 3: KnowledgePoint + 其下 SubPoint/Concept（+15-40 个节点）
```

**关键交互：**

| 交互 | 行为 | 视觉反馈 |
|------|------|----------|
| 鼠标悬停 | 高亮节点及其直接关联节点 | 非关联节点降透明度至 20% |
| 单击（可展开类型） | 以该节点为根展开 3 层子树 | 力导向重新布局，新节点淡入 |
| 单击（叶子类型） | 打开详情侧边栏 | 右侧滑入面板，显示元数据 |
| 双击节点 | 以该节点居中 | 相机平滑过渡到新中心 |
| 面包屑点击 | 跳回任意上级节点 | 图恢复到对应层级 |

### 2.3 面包屑导航 (Breadcrumb)

Obsidian 及其插件的共识方案：

```
🏠 全部课程 > 程序设计基础 > 第3章 > [数组与指针]
  ↑ 点击回到          ↑ 点击回到       ↑ 当前节点
  Course 列表         Chapter 视图
```

- 每一级可点击跳转
- 当前节点高亮不可点击
- 层级颜色编码（课程/章节/知识点用不同色标区分）

### 2.4 侧边详情面板 (Detail Panel)

点击叶子节点（SubPoint/Concept）或全图模式下的任意节点时弹出：

**面板内容：**
- 节点名称 + 类型标签
- 描述文本
- 关联关系列表（REQUIRES/RELATED_TO/IS_PART_OF）
- 关联学习资源（quiz/mindmap/code/doc/summary）
- 操作按钮（生成资源、加入学习路径）

**面板行为：**
- 右侧滑入，不遮挡主图
- 点击背景遮罩关闭
- 在全图模式和聚焦模式下均可使用

### 2.5 搜索定位

```
搜索框输入 "指针"
    → 下拉显示匹配节点列表
    → 选中后图动画居中到目标节点
    → 自动展开 1 层邻接节点
    → 目标节点闪烁/脉冲效果
    → 非匹配节点降低透明度
```

### 2.6 Obsidian Graph View 的借鉴

Obsidian 本地图视图的设计亮点：

| 特性 | 描述 | 可借鉴度 |
|------|------|----------|
| 全局/局部图切换 | 一键切换显示全图 vs 当前节点邻域 | 已实现（聚焦/全图模式） |
| 节点引力中心 | 高连接数节点自动成为引力中心 | 力导向天然支持 |
| 脉冲连线动画 | 选中节点到邻接节点的连线闪烁 | 可添加 |
| 标签/附件节点 | 特殊节点类型用不同颜色/形状 | 已实现（type 着色） |
| 已探索/未探索标记 | 记录节点是否被访问过 | 可添加（对应学习进度） |
| 深度滑块 | 控制展示的层级数量 | 已实现（depth 参数） |

## 三、视觉设计

### 3.1 节点编码

| 属性 | 编码方式 | 当前系统 | 建议 |
|------|----------|----------|------|
| 节点类型 | 颜色 | Course 棕色 / Chapter 橙 / KP 金 / SP 绿 / Concept 灰 | 保持 |
| 重要性/连接数 | 大小 | 固定大小比例 90:55:30:20:10 | 可引入度中心性动态调整 |
| 学习状态 | 边框 | 已完成=绿边框 / 当前=金色 / 未学=无 | 保持 |
| 可展开性 | 光标样式 | pointer + 虚线边框 | 保持 |
| 路径覆盖 | 透明度 | 在路径中=正常 / 不在=40% | 保持 |

### 3.2 边编码

| 关系类型 | 颜色 | 线宽 | 线型 | 箭头 |
|----------|------|------|------|------|
| IS_PART_OF | 浅灰棕 | 1.2 | 实线 | 有 |
| CONTAINS | 浅灰棕 | 1.2 | 实线 | 反向 |
| REQUIRES | 橙色 | 1.5 | 虚线 | 有 |
| RELATED_TO | 浅蓝灰 | 0.8 | 虚线 | 无 |

### 3.3 色板可访问性

- 当前色板（暖棕系 + 绿 + 灰）对红绿色盲友好
- 建议增加色板切换选项（亮色主题 / 暗色主题），已实现
- 高对比度模式可进一步优化

## 四、状态管理

### 4.1 节点状态模型

```
节点状态 = {
    基础属性: { id, name, type, description }
    学习状态: { unexplored | available | in_progress | mastered }
    展开状态: { collapsed | expanded | focused }
    路径状态: { not_in_path | planned | current | completed }
}
```

### 4.2 Obsidian 风格的已探索/未探索追踪

参考 Obsidian 的 Graph Explorer Base View 插件：

- **已探索节点**：学生点击过的节点标记为"已访问"
- **已掌握节点**：完成测验或资源学习后标记为"已掌握"
- **推荐节点**：基于当前知识状态的"下一步"节点，用脉冲动画标识
- **差距分析**：AI 检测学生知识图谱中的"空洞"（未连接的概念群）

### 4.3 状态持久化

```
localStorage 存储:
  - focusState.stack（面包屑导航栈）
  - focusState.mode（focus / overview）
  - 节点已探索标记集合
  - 上次浏览位置
```

## 五、性能优化

### 5.1 当前方案

| 措施 | 说明 |
|------|------|
| BFS 下钻 | 每次 API 仅返回子树节点（20-50 个），而非全图（200+） |
| 缩放阈值 | zoom < 阈值时隐藏小节点及其标签 |
| 自适应力参数 | <30 节点: repulsion=500, >80 节点: repulsion=1200 |
| 单次 chartInstance | 全局唯一实例，避免重复初始化 |

### 5.2 可考虑的未来优化

| 优化方向 | 方案 |
|----------|------|
| WebGL 渲染 | 当前 Canvas 渲染在 50+ 节点时流畅，暂不需要。若扩展到 500+ 节点可引入 ECharts GL |
| Web Worker 布局 | 力导向计算在 Worker 中进行，避免阻塞主线程 |
| 虚拟化节点列表 | 知识点列表（grid 视图）对 200+ 节点进行虚拟滚动 |
| 增量更新 | setOption 时使用 `notMerge: false` 实现局部更新而非全量替换 |

## 六、竞品参考

### 6.1 Obsidian Graph View

- **全局图**：展示所有笔记及其链接关系
- **局部图**：仅展示当前笔记的直接邻居
- **插件生态**：Graph Source Color（按源文件夹着色）、Graph Explorer（已探索追踪）
- **核心优势**：力导向布局美观、交互直觉、深度可调

### 6.2 Neo4j Bloom

- 面向业务用户的无代码图探索工具
- 透视视图 + 短语搜索
- 自动生成图例、按属性着色
- 适合大型企业知识图谱

### 6.3 Cambridge Intelligence (KeyLines & ReGraph)

- 商业级图可视化 SDK
- 时间轴集成、地理图映射、社交网络分析
- 布局算法库（标准/层级/径向/有机/顺序）
- 提供 D3.js 构建的 demo 参考

### 6.4 GraphIT（雷根斯堡大学）

- 大学课程依赖图，学生标记"已完成"或"感兴趣"
- 可视化学习路径
- 学生端可视编辑器 + 管理员端表格编辑器

### 6.5 Knowledge Tree（开源项目）

- React Flow 构建交互式节点路线图
- 概念节点渐进解锁（前置知识完成后才可访问下一层）
- AI 生成每节点的文章和测验

### 7.2 可考虑的后续迭代

| 优先级 | 特性 | 说明 |
|--------|------|------|
| 高 | 径向布局切换 | 选中单个节点后可切换为径向视图，更清晰展示三层子树 |
| 高 | 已探索/未探索追踪 | 记录学生点击过的节点，视觉区分"未探索"概念 |
| 中 | 节点脉冲动画 | 搜索定位或推荐节点时使用脉冲效果 |
| 中 | 度中心性节点大小 | 连接数多的节点自动放大，形成"知识枢纽"视觉 |
| 中 | 边方向脉冲动画 | IS_PART_OF / REQUIRES 关系用连线流动动画表示方向 |
| 低 | 3D 力导向 | 节点数 500+ 时可考虑三维护展更多维度 |
| 低 | 时间轴动画 | 按学习时间顺序动态展示知识图谱的构建过程 |

### 7.3 布局策略建议

当前系统统一使用力导向布局，在小规模子图（<50 节点）下表现良好。建议针对性引入布局策略：

```
全局视图（>50 节点）：力导向 + 自适应参数
聚焦视图（20-50 节点）：力导向（当前方案）
径向聚焦（<30 节点，单一 root）：径向布局（可选切换）
层级浏览（仅看树形结构时）：层级布局（可选切换）
```
