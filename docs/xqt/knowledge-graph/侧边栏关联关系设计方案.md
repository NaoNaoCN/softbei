# 知识图谱节点侧边栏 — 关联关系设计方案

当前实现：ECharts 静态树图，按层级分"上级/下级"两组展示关联节点。以下提供三个方案，由简到丰。

---

## 数据基础

点击节点后，从 `fullGraph.edges` 中筛选出与该节点相关的所有边，每条边包含：

| 字段 | 说明 | 示例 |
|------|------|------|
| `direction` | 方向 | `→`（本节点为源） / `←`（本节点为目标） |
| `relation` | 关系类型 | `IS_PART_OF`, `REQUIRES`, `CONTAINS`, `RELATED_TO` |
| `otherNode.id` | 关联节点 ID | `kp_001` |
| `otherNode.name` | 关联节点名称 | `梯度下降` |
| `otherNode.type` | 关联节点类型 | `Course` / `Chapter` / `KnowledgePoint` / `SubPoint` / `Concept` |

关系方向解读：

```
本节点 → B    = 本节点 包含/依赖/关联 B
A → 本节点    = A 包含/依赖/关联 本节点
```

层级高低判断（`typeOrder`）：

```
Course(0) < Chapter(1) < KnowledgePoint(2) < SubPoint(3) < Concept(4)
```

## 方案 A：分类分组列表（推荐，最简）

纯文字结构，按关系类型分组，每组下列出关联节点。信息一目了然，无需解读图形，实现成本最低。

### 视觉结构

```
┌─────────────────────────────────┐
│ 关联关系 (12)                    │
│                                 │
│ ▸ 属于 (IS_PART_OF)  3          │ ← 折叠面板，默认展开
│    ├─ 机器学习 · 课程           │ ← 节点名 + 类型标签（彩色小圆点）
│    └─ 优化理论 · 章节           │    点击跳转至该节点详情
│                                 │
│ ▸ 包含 (CONTAINS)  5            │
│    ├─ 学习率衰减 · 子点         │
│    ├─ 动量参数 · 子点           │
│    ├─ Adam优化器 · 概念         │
│    ├─ ...                      │
│    └─ 显示全部 (5)              │ ← 超过 5 项时折叠，可展开
│                                 │
│ ▸ 依赖 (REQUIRES)  2            │
│    ├─ 链式法则 · 知识点         │
│    └─ 偏导数 · 知识点           │
│                                 │
│ ▸ 相关 (RELATED_TO)  2          │
│    ├─ 损失函数 · 知识点         │
│    └─ 学习率调度 · 子点         │
└─────────────────────────────────┘
```

### 每条关系的展示内容

```
[彩色圆点] 节点名称  [类型标签]  [方向箭头]
```

- 圆点颜色与节点类型对应（同主图谱配色）
- 箭头表示方向：`→` 指向对方 / `←` 来自对方
- 点击整行 → 切换侧边栏至该关联节点（不关闭面板）

### 关系类型中文映射

| 英文 | 中文 | 说明 |
|------|------|------|
| `IS_PART_OF` | 属于 | 当前节点是对方的一部分 |
| `CONTAINS` | 包含 | 当前节点包含对方 |
| `REQUIRES` | 依赖 | 学习当前节点前需要先掌握对方 |
| `RELATED_TO` | 相关 | 两个节点有概念关联 |

### 排序规则

1. 按关系类型优先级：`IS_PART_OF` → `CONTAINS` → `REQUIRES` → `RELATED_TO`
2. 同类型内按对方节点层级排序：Course → Chapter → KnowledgePoint → SubPoint → Concept
3. 同层级按名称字母序

### 限制

- 每组默认展示 5 项，超出折叠，点击"显示全部"展开
- 总关联数 > 20 时，顶部加搜索过滤输入框

## 方案 B：层级卡片 + 迷你关系网

上半部分保留精简文字列表（方案 A 的缩略版），下半部分放一个迷你的可视化。

### 视觉结构

```
┌─────────────────────────────────┐
│ 关联关系 (12)                    │
│                                 │
│ ┌─────────────────────────────┐ │
│ │      [迷你力导向图]          │ │  ← 150px 高
│ │   中心=当前节点，周围=关联节点 │ │    仅展示拓扑，无标签
│ │   边颜色=关系类型             │ │    hover 显示名称
│ └─────────────────────────────┘ │
│                                 │
│ 上级 (3)                        │
│  · 机器学习 · 课程    IS_PART_OF│
│  · 优化理论 · 章节    IS_PART_OF│
│  · 反向传播 · 知识点  REQUIRES  │
│                                 │
│ 下级 (9)                        │
│  · 学习率衰减 · 子点  CONTAINS  │
│  · 动量参数 · 子点    CONTAINS  │
│  ...                            │
└─────────────────────────────────┘
```

迷你力导向图：
- 中心节点用当前节点类型色，40px，白色边框
- 关联节点 15px，颜色按类型
- 边颜色编码关系类型：
  - `IS_PART_OF`: 绿色 `#6E9466`
  - `CONTAINS`: 蓝色 `#5B8DB8`
  - `REQUIRES`: 橙色 `#C98A2E`
  - `RELATED_TO`: 灰色 `#908A80`
- `roam: false`, `draggable: false`，纯展示

## 方案 C：纯图形 + 图例（当前方案的改进版）

保留当前 ECharts 树图，但增强可读性。

### 改进点

1. **去掉分组虚拟节点**（"上级(N)"、"下级(N)"）——它们占空间且不增加信息
2. **边标签替换为缩略中文**：`IS_PART_OF` → `属于`，`REQUIRES` → `依赖` 等
3. **节点圆点尺寸按类型**：Course(14) > Chapter(11) > KnowledgePoint(9) > SubPoint(7) > Concept(5)
4. **当前节点始终在左侧**，关联节点在右侧按层级从上到下排列
5. **点击树图中任意节点** → 侧边栏切换到该节点

### 视觉结构

```
┌─────────────────────────────────┐
│ 关联关系 (12)                    │
│                                 │
│  ● 机器学习 ──属于── ● 梯度下降  │  ← 根=上级Course
│  ● 优化理论 ──属于── │          │    树状排布
│                      │          │
│           ● 梯度下降 ──包含── ● 学习率衰减  │
│                      ├─包含── ● 动量参数    │  ← 下级分支
│                      ├─依赖── ● 链式法则    │
│                      └─相关── ● 损失函数    │
│                                 │
│  [图例] ●属于 ●包含 ●依赖 ●相关 │
└─────────────────────────────────┘
```

## 对比分析

| 维度 | 方案 A（分组列表） | 方案 B（列表+迷你图） | 方案 C（纯树图） |
|------|-------------------|----------------------|-----------------|
| 信息密度 | 高 | 中 | 低（需解读图形） |
| 可读性 | 极好，一眼看完 | 好 | 一般，需结合图例 |
| 实现成本 | 低（纯 HTML/CSS） | 中（ECharts + HTML） | 中（ECharts tree） |
| 可交互性 | 高（点击跳转，折叠展开） | 中 | 中 |
| 空间占用 | 紧凑 | 需 400px 面板高度 | 需 300px 面板高度 |
| 适用场景 | 关联数任意 | 10-30 条关联 | 5-15 条关联 |
| 一眼看层级 | 中（需看类型标签） | 好（迷你图直观） | 好（树结构清晰） |
| 支持搜索/过滤 | 容易 | 一般 | 困难 |

---

## 推荐

建议采用 **方案 A（分类分组列表）**，原因：

1. **简单**：纯 HTML/CSS 列表，无需维护 ECharts 实例，无 dispose/resize 问题
2. **清晰**：按关系类型分组 + 折叠，结构化程度高
3. **信息全面**：每行展示节点名、类型、关系方向，不遗漏任何字段
4. **可操作**：点击直接跳转关联节点，形成连续浏览体验
5. **久经考验**：这种分组列表模式在 GitHub Issues、Notion 等产品中广泛使用，用户不需要学习

如果后续用户反馈需要空间关系感知，可在此基础上叠加方案 B 的迷你图（列表 + 小图），即混合方案。

## 实施要点（方案 A）

### DOM 结构

```html
<div class="detail-relations">
  <div class="detail-section">关联关系 (N)</div>

  <details class="rel-group" open>
    <summary class="rel-group-header">
      <span class="rel-dot" style="background:#6E9466"></span>
      属于 (3)
    </summary>
    <div class="rel-item" data-node-id="xxx">
      <span class="rel-type-dot" style="background:#D4852B"></span>
      <span class="rel-name">机器学习</span>
      <span class="rel-type-tag">课程</span>
      <span class="rel-arrow" title="本节点 ← 对方">←</span>
    </div>
    <!-- more items... -->
  </details>

  <details class="rel-group" open>
    ...
  </details>
</div>
```

### 样式要点

- `.rel-item` 横向 flex，`gap: 8px`，点击整行可交互
- `.rel-type-dot` 8px 圆点，颜色对应节点类型
- `.rel-type-tag` 小标签，底色 `var(--bg-page)`，圆角 4px
- `.rel-arrow` 灰色小字，hover 显示 tooltip 解释方向含义
- `.rel-group` 默认展开（`open` 属性），每组最多展示 5 条，超出部分用 `details` 二级折叠
- hover 背景色与列表项一致，cursor: pointer

### 交互

- 点击 `.rel-item` → 调用 `showDetailPanel(otherNode)` 刷新侧边栏
- 每组超过 5 条时：渲染前 5 条 + "显示全部 (N)" 按钮，点击展开剩余
- 可选：顶部加 `<input>` 搜索框（关联数 > 20 时显示），输入过滤关联节点名称
