# 文档文件清理方案设计

## 1. 问题描述

### 1.1 当前状态

文件上传后存储在 `uploaded_docs/` 目录，**永久保留，无清理逻辑**。

当前目录状况（2026-05-15）：
- 13 个文件，总计约 65 MB
- 其中 2 份 `d2l-zh.pdf`（32 MB × 2 = 64 MB）为重复上传
- 11 份 `test_pdf_5_9.pdf`（60 KB × 11）为测试文件
- 最早文件日期 2026-05-02，已存在 13 天

### 1.2 文件用途（导入后）

| 用途 | 代码位置 | 文件不存在时行为 |
|------|---------|----------------|
| PDF 预览 | `main.py:441` `GET /documents/file/{filename}` | 返回 404 |
| KG 目录提取 | `kg_builder.py:605` `extract_toc()` | 静默跳过，使用 fallback |
| 重新索引（无 UI） | — | 不支持 |

**结论**：原始文件在导入成功并完成 KG 构建后，仅 PDF 预览依赖它。删除过期文件不会破坏核心功能。

### 1.3 清理目标

- 防止磁盘无限增长
- 优先保留近期上传的文件（预览价值高）
- 安全删除，不误删正在处理的文件
- 可审计（记录每次删除的详情）

## 2. 清理策略设计

### 2.1 三级策略

```
文件年龄
  │
  ├── < 5 分钟 ────────── 保护期：正在处理，不删除
  │
  ├── 5 分钟 ~ 30 天 ─── 保留期：可预览、可提取目录
  │   (有 ResourceMeta)
  │
  ├── 30 天 ~ ∞ ──────── 清理候选：已索引，可安全删除
  │   (有 ResourceMeta)
  │
  └── 7 天 ~ ∞ ───────── 孤儿清理：从未成功索引，垃圾文件
      (无 ResourceMeta)
```

### 2.2 清理规则

| 规则 | 判断条件 | 保留期 | 说明 |
|------|---------|--------|------|
| **规则 1：索引文件过期** | 文件有对应 `ResourceMeta` 记录，且 `mtime` > `retention_days` | 30 天 | 索引成功后保留 30 天供预览/TOC |
| **规则 2：孤儿文件清理** | 文件无对应 `ResourceMeta` 记录，且 `mtime` > `orphan_retention_days` | 7 天 | 导入失败/中断的残留文件，1 周后清除 |
| **规则 3：处理中保护** | 文件 `mtime` < `min_file_age_seconds` | 5 分钟 | 正在写入/解析的文件，跳过 |

### 2.3 文件名解析

当前文件名格式：`{uuid_hex_12}_{original_name}`，如 `aa77bc5f96cf_d2l-zh.pdf`

```python
# 从 ResourceMeta.content 中提取原始文件名
# content 格式："已导入文档：d2l-zh.pdf，共 300 个文本块"
# 匹配规则：正则提取 "已导入文档：(.+?)，"

# 然后拼接为 uploaded_docs/{uuid}_{original_name} 进行匹配
```

**文件名关联链路**：
```
uploaded_docs/ 文件
  → 文件名包含 original_name
  → ResourceMeta.content 包含 original_name
  → ResourceMeta.kp_id = doc_id (如 doc_abc123)
  → ChromaDB metadata.doc_id = doc_id
```

### 2.4 参数可配置

```yaml
# configs/config.yaml
storage:
  cleanup:
    enabled: true               # 是否启用自动清理
    retention_days: 30          # 已索引文件的保留天数
    orphan_retention_days: 7    # 孤儿文件保留天数
```

## 3. 实现设计

### 3.1 模块结构

```
backend/services/cleanup.py    ← 新增：清理服务
backend/config.py               ← 修改：增加 StorageCleanupConfig
backend/main.py                 ← 修改：启动后台清理任务
configs/config.yaml             ← 修改：增加 cleanup 配置节
```

### 3.2 核心函数

```python
async def cleanup_uploaded_docs(
    db: AsyncSession,
    retention_days: int = 30,
    orphan_retention_days: int = 7,
    dry_run: bool = False,
) -> dict:
    """
    Returns: {
        "scanned": 13,        # 扫描到的文件总数
        "deleted": 3,         # 已删除文件数
        "skipped_active": 0,  # 跳过（处理中）
        "skipped_retained": 10, # 跳过（保留期内）
        "errors": [],         # 错误列表
        "details": [          # 每个文件的处理详情
            {"file": "xxx.pdf", "action": "deleted", "reason": "..."},
            ...
        ]
    }
    """
```

### 3.3 流程图

```
开始
  │
  ├── 1. 查询所有 ResourceMeta (resource_type="doc")
  │      → 建立 {original_name → resource} 映射
  │
  ├── 2. 扫描 uploaded_docs/ 目录下所有文件
  │
  ├── 3. 对每个文件：
  │     │
  │     ├── 文件 mtime < 5 分钟前？
  │     │   → Yes: skip ("active")
  │     │
  │     ├── 原文文件名在 ResourceMeta 中？
  │     │   ├── Yes: 文件 mtime > 30 天？
  │     │   │   ├── Yes: DELETE ("expired_indexed")
  │     │   │   └── No:  skip ("retained")
  │     │   └── No:  文件 mtime > 7 天？
  │     │       ├── Yes: DELETE ("orphan")
  │     │       └── No:  skip ("retained_orphan")
  │     │
  │     └── 删除失败？→ 记录到 errors
  │
  └── 4. 汇总并返回 + 记录日志
```

### 3.4 后台任务

复用 `dynamic_chat.py` 的 background task 模式：

```python
# backend/main.py lifespan 中
from backend.services.cleanup import start_document_cleanup_task
doc_cleanup_task = asyncio.create_task(start_document_cleanup_task())

# shutdown 时
doc_cleanup_task.cancel()
```

清理频率：每 24 小时执行一次（与 chat_session 清理相同周期）。

### 3.5 日志格式

```
[Cleanup] 开始清理 uploaded_docs/，保留策略: indexed=30d, orphan=7d
[Cleanup] 文件 d2l-zh.pdf (age=35d, 已索引) → 删除 (过期索引文件)
[Cleanup] 文件 test_upload_fail.txt (age=10d, 未索引) → 删除 (孤儿文件)
[Cleanup] 文件 recent.pdf (age=3d, 已索引) → 保留
[Cleanup] 清理完成: scanned=13, deleted=2, skipped_retained=11, errors=0
```

### 3.6 安全措施

| 措施 | 实现 |
|------|------|
| 处理中保护 | `mtime` < 5 分钟的文件跳过 |
| 路径穿越防护 | `Path(filename).name` 取纯文件名 |
| 只删文件不删目录 | 检查 `is_file()` 且匹配后缀 |
| 异步非阻塞 | 后台任务，不影响主请求循环 |
| 失败隔离 | 单个文件删除失败不影响其他文件 |
| 审计留痕 | 每次清理记录结构化日志 |

## 4. 手动清理接口

提供 `POST /documents/cleanup` API，支持手动触发和 dry-run 预览：

```python
@app.post("/documents/cleanup")
async def manual_cleanup(
    dry_run: bool = True,  # 默认 dry-run，预览不删除
    retention_days: int = 30,
    db: AsyncSession = Depends(get_session),
):
    """手动触发文档文件清理。dry_run=true 仅预览不删除。"""
    result = await cleanup_uploaded_docs(
        db, retention_days=retention_days, dry_run=dry_run
    )
    return {"success": True, "dry_run": dry_run, **result}
```

调用示例：
```bash
# 预览（不删除）
curl -X POST "http://localhost:8000/documents/cleanup?dry_run=true"

# 执行清理
curl -X POST "http://localhost:8000/documents/cleanup?dry_run=false&retention_days=7"
```

## 7. 总结

| 维度 | 清理前 | 清理后 |
|------|--------|--------|
| 文件生命周期 | 永久保留 | 30 天（可配） |
| 磁盘管理 | 手动 | 自动后台任务 |
| 误删风险 | — | 5 分钟保护 + dry-run 预览 |
| 清理可见性 | 无 | 结构化日志 + API |
| .gitignore | `*.pdf` 仅覆盖 PDF | 新增 `uploaded_docs/` 完全忽略 |
