# 文档存储方案设计

## 1. 现状分析

### 1.1 当前方案

文件上传后直接存储在项目根目录的 `uploaded_docs/` 下：

```python
# backend/services/document.py:27-28
UPLOAD_DIR = Path(__file__).parent.parent.parent / "uploaded_docs"
UPLOAD_DIR.mkdir(exist_ok=True)

# 文件名：{uuid_hex_12}_{original_name}
unique_name = f"{uuid.uuid4().hex[:12]}_{original_name}"
dest = UPLOAD_DIR / unique_name
dest.write_bytes(content)
```

### 1.2 文件的生命周期

```
上传 → 暂存 → 格式转换 → 文本切分 → 向量嵌入 → 索引写入
  │                                                    │
  └── 之后仍被读取：                                    │
      · PDF 预览 (main.py:441  GET /documents/file/{filename})  │
      · KG 目录提取 (kg_builder.py:605 extract_toc)     │
                                                        │
      文件实际上 → 永 久 保 留（无删除逻辑）
```

### 1.3 当前方案的 5 个问题

| # | 问题 | 影响 | 严重度 |
|---|------|------|--------|
| 1 | **混合项目代码** | `uploaded_docs/` 与源码同级，容易被误操作 | 中 |
| 2 | **无清理策略** | 文件永久保留，磁盘持续增长 | 高 |
| 3 | **单机绑定** | 无法水平扩展，多实例部署时文件不共享 | 中 |
| 4 | **未纳入 .gitignore** | 虽 `*.pdf` 已忽略，但 `.docx`/`.md`/`.txt` 可能被误提交 | 中 |
| 5 | **无访问控制** | 任何人拿到文件名即可通过 `/documents/file/{filename}` 获取 | 低 |

### 1.4 读取文件的三处代码

| 位置 | 用途 | 读取时机 |
|------|------|---------|
| `services/document.py:55` | `loader.load_file()` 解析文档内容 | 导入时 |
| `main.py:441-462` | `GET /documents/file/{filename}` 返回 PDF 供 iframe 预览 | 查看时 |
| `services/kg_builder.py:605` | `extract_toc()` 提取 PDF 目录结构 | KG 构建时 |

### 2.2 各方案详析

#### 方案 A：本地文件系统（当前）

```
project/
├── uploaded_docs/          ← 文件存放
│   ├── a1b2c3_教材.pdf
│   └── d4e5f6_课件.docx
├── backend/
└── frontend/
```

- 文件路径直接作为 `loader.load_file()` 参数，零转换开销
- `FileResponse` 天然支持，无需中转
- 需要手动管理磁盘空间和备份

**改进版**：将存储目录移到项目外 + 定时清理

```python
# 移到操作系统临时目录或专用数据目录
UPLOAD_DIR = Path("/var/data/softbei/documents")  # Linux
UPLOAD_DIR = Path(os.environ.get("DOCUMENT_STORAGE", "./uploaded_docs"))
```

#### 方案 B：数据库 BLOB 存储

```sql
CREATE TABLE uploaded_files (
    id          VARCHAR(36) PRIMARY KEY,
    filename    VARCHAR(255) NOT NULL,
    content     LONGBLOB NOT NULL,       -- 文件内容
    size_bytes  BIGINT,
    mime_type   VARCHAR(100),
    user_id     VARCHAR(36),
    created_at  DATETIME DEFAULT NOW(),
    INDEX idx_user (user_id)
);
```

- 适合小文件（<1MB），可利用事务保证一致性
- 对大 PDF（50MB+）会严重影响数据库性能
- PDF 预览需额外实现读取接口，数据库往返开销大

#### 方案 C：阿里云 OSS

当前系统已使用阿里云 DashScope（LLM + Embedding），在同一生态内引入 OSS 是最自然的云存储选择。

```
上传 → OSS PutObject → 返回 OSS URL
读取 → OSS GetObject 或 签名 URL
预览 → 前端直接加载 OSS 签名 URL（无需经过后端）
```

- 签名 URL 可实现临时授权访问，避免文件被永久公开
- 支持生命周期策略（30 天后自动转为归档存储或删除）
- 按量计费：存储约 ¥0.12/GB/月 + 流量 ¥0.5/GB

#### 方案 D：MinIO（自建 S3 兼容存储）

```bash
# Docker 部署
docker run -p 9000:9000 -p 9001:9001 \
  -v /data/minio:/data \
  minio/minio server /data --console-address ":9001"
```

- API 与 S3 完全兼容，代码可无缝迁移到云 S3
- 适合需要私有部署的比赛/学校场景
- 自带 Web 管理界面

#### 方案 E：混合方案（推荐）

```
┌─────────────────────────────────────────────┐
│              应用层 (backend)                │
│                                              │
│  StorageService (抽象接口)                   │
│  ├── save(file) → storable_id               │
│  ├── get(storable_id) → bytes               │
│  ├── get_url(storable_id) → str (预览 URL)   │
│  └── delete(storable_id)                    │
│                                              │
│  ┌──────────┐ ┌──────────┐ ┌──────────────┐ │
│  │ LocalFS  │ │  MinIO   │ │  阿里云 OSS   │ │
│  │ Backend  │ │ Backend  │ │   Backend    │ │
│  └──────────┘ └──────────┘ └──────────────┘ │
│                                              │
│  通过 config.yaml 切换:                      │
│    storage.backend: local | minio | oss     │
└─────────────────────────────────────────────┘
```

## 3. 推荐方案：抽象层 + 可切换后端

### 3.1 接口设计

```python
# backend/services/storage.py

from abc import ABC, abstractmethod
from dataclasses import dataclass
from pathlib import Path
from typing import Optional


@dataclass
class StoredFile:
    """存储后返回的文件描述"""
    storage_id: str          # 存储系统中的唯一标识
    original_name: str        # 原始文件名
    size_bytes: int
    mime_type: str
    backend: str              # 使用的存储后端名称


class StorageBackend(ABC):
    """存储后端抽象基类"""

    @abstractmethod
    async def save(self, content: bytes, filename: str) -> StoredFile:
        """保存文件，返回存储描述"""
        ...

    @abstractmethod
    async def get(self, storage_id: str) -> bytes:
        """读取文件内容"""
        ...

    @abstractmethod
    async def get_url(self, storage_id: str, expires_seconds: int = 3600) -> str:
        """获取可访问的 URL（用于 PDF 预览等场景）"""
        ...

    @abstractmethod
    async def delete(self, storage_id: str) -> bool:
        """删除文件"""
        ...

    @abstractmethod
    async def exists(self, storage_id: str) -> bool:
        """检查文件是否存在"""
        ...
```

### 3.2 本地文件系统实现

```python
class LocalFileStorage(StorageBackend):
    """本地文件系统后端（开发/单机部署默认）"""

    def __init__(self, base_dir: str | Path):
        self.base_dir = Path(base_dir)
        self.base_dir.mkdir(parents=True, exist_ok=True)

    async def save(self, content: bytes, filename: str) -> StoredFile:
        import uuid
        suffix = Path(filename).suffix
        storage_id = f"{uuid.uuid4().hex[:12]}{suffix}"
        dest = self.base_dir / storage_id
        dest.write_bytes(content)
        return StoredFile(
            storage_id=storage_id,
            original_name=filename,
            size_bytes=len(content),
            mime_type=_guess_mime(filename),
            backend="local",
        )

    async def get(self, storage_id: str) -> bytes:
        filepath = self._resolve(storage_id)
        if not filepath.exists():
            raise FileNotFoundError(f"文件不存在: {storage_id}")
        return filepath.read_bytes()

    async def get_url(self, storage_id: str, expires_seconds: int = 3600) -> str:
        # 本地模式直接返回后端 API 地址
        return f"/documents/file/{storage_id}"

    async def delete(self, storage_id: str) -> bool:
        filepath = self._resolve(storage_id)
        if filepath.exists():
            filepath.unlink()
            return True
        return False

    async def exists(self, storage_id: str) -> bool:
        return self._resolve(storage_id).exists()

    def _resolve(self, storage_id: str) -> Path:
        # 防止路径穿越
        safe_name = Path(storage_id).name
        return self.base_dir / safe_name
```

### 3.3 MinIO 实现

```python
class MinioStorage(StorageBackend):
    """MinIO / S3 兼容存储后端"""

    def __init__(self, endpoint: str, access_key: str,
                 secret_key: str, bucket: str, secure: bool = False):
        from minio import Minio  # pip install minio
        self.client = Minio(endpoint, access_key, secret_key, secure=secure)
        self.bucket = bucket
        if not self.client.bucket_exists(bucket):
            self.client.make_bucket(bucket)

    async def save(self, content: bytes, filename: str) -> StoredFile:
        import uuid
        from io import BytesIO
        suffix = Path(filename).suffix
        storage_id = f"{uuid.uuid4().hex[:12]}{suffix}"
        self.client.put_object(
            self.bucket, storage_id,
            BytesIO(content), len(content),
            content_type=_guess_mime(filename),
        )
        return StoredFile(
            storage_id=storage_id,
            original_name=filename,
            size_bytes=len(content),
            mime_type=_guess_mime(filename),
            backend="minio",
        )

    async def get_url(self, storage_id: str, expires_seconds: int = 3600) -> str:
        return self.client.presigned_get_object(
            self.bucket, storage_id,
            expires=timedelta(seconds=expires_seconds),
        )
    # ... get / delete / exists 类似实现
```

### 3.5 单例工厂

```python
# backend/services/storage.py

_storage_instance: Optional[StorageBackend] = None

def get_storage() -> StorageBackend:
    global _storage_instance
    if _storage_instance is None:
        _storage_instance = _create_storage(config.storage)
    return _storage_instance

def _create_storage(cfg) -> StorageBackend:
    if cfg.backend == "local":
        return LocalFileStorage(cfg.local.base_dir)
    elif cfg.backend == "minio":
        return MinioStorage(
            cfg.minio.endpoint,
            cfg.minio.access_key,
            cfg.minio.secret_key,
            cfg.minio.bucket,
            cfg.minio.secure,
        )
    elif cfg.backend == "oss":
        return OssStorage(...)
    raise ValueError(f"Unknown storage backend: {cfg.backend}")
```

## 4. 文件清理策略

无论选择哪种存储后端，都需要清理策略。

### 4.1 清理时机决策树

```
导入后是否还需要原始文件？
├── 需要（PDF 预览 / TOC 提取 / 重新索引）
│   ├── 保留 N 天 → 定时任务清理
│   └── 永久保留 → 依赖对象存储生命周期
└── 不需要
    └── 导入成功后立即删除
```

### Phase 1：与当前方案兼容的最小改进（0 改动，立即生效）

## 6. 总结

| 维度 | 当前 | 推荐（Phase 2+） |
|------|------|------------------|
| 存储位置 | `project/uploaded_docs/` | 可配置（本地 / MinIO / OSS） |
| 扩展性 | 单机 | 无状态，可水平扩展 |
| 清理 | 无 | 定时任务 + 对象生命周期 |
| 预览 | 后端 FileResponse | 本地同前，OSS/MinIO 签名 URL |
| 代码改动 | — | ~150 行新增 + 3 文件改造 |

核心原则：**通过 StorageBackend 抽象，将存储从"硬编码的本地目录"变为"可配置的可插拔后端"，在不改变现有功能的前提下，为未来扩展留出空间。**
