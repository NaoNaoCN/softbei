# 交互与按钮重构方案

## 一、问题诊断

当前交互的 7 个系统性缺陷：

| 问题 | 表现 | 频次 |
|------|------|------|
| 反馈方式落后 | `alert()` 弹成功、`confirm()` 弹确认，阻塞且不可定制 | 全站 40+ 处 |
| 按钮无状态 | 点击后没有 loading/success/error 状态变化，用户不知道操作是否在进行 | 全站 |
| 无撤销机制 | 删除、修改操作不可逆，误触即永久丢失 | 全站 |
| 无批量操作 | 资源只能逐条删除，每题单独提交 API | library / evaluate |
| 无中断能力 | 资源生成、导入一旦开始无法取消，轮询持续到超时 | generate / library |
| 输入无即时反馈 | 搜索框需点"刷新"才生效，无 debounce，无实时结果 | library / pathway |
| 窗口函数污染 | `window.handleXxx` 与 `addEventListener` 混用，全局函数散落 | 全站 |

---

## 二、设计目标

1. **每个按钮有三种可见状态** — 空闲 / 执行中 / 完成（成功或失败），用户始终知道发生了什么
2. **所有反馈走 Toast 通道** — 不再有 `alert()` 和裸 `confirm()`
3. **危险操作可撤销** — 删除后 5 秒内可恢复
4. **批量操作** — 多选后统一处理，不逐条确认
5. **可中断** — 长操作有取消按钮，轮询有清理机制
6. **即时响应** — 输入即搜索，切换即筛选，不再需要手动点"刷新"

## 三、按钮状态机

### 3.1 标准按钮 5 态

每个按钮都是一个微型状态机：

```
          ┌──────────┐
          │  idle    │  默认：可点击
          └────┬─────┘
               │ 点击
          ┌────▼─────┐
          │ loading  │  执行中：disabled + spinner + "生成中..."
          └────┬─────┘
               │
       ┌───────┴───────┐
       │               │
  ┌────▼─────┐  ┌──────▼──────┐
  │ success  │  │   error     │
  │ 短暂展示 │  │ 显示错误信息 │
  │ 自动恢复 │  │ 可重试      │
  └────┬─────┘  └──────┬──────┘
       │               │
       └───────┬───────┘
               │ 1.5~3s 后
          ┌────▼─────┐
          │  idle    │  自动恢复
          └──────────┘
```

### 3.2 按钮状态 CSS 约定

```
idle:    渐变背景 + 彩色投影（当前 .btn-primary 样式）
loading: 背景变浅 + spinner 替换图标 + 文字变"处理中..."
success: 背景短暂变绿 + 图标变 check + 文字变"已完成"（1.5s）
error:   背景短暂变红 + 图标变 alert + 文字变错误信息（3s，可手动关闭）
disabled: 灰色背景 + 无投影 + cursor: not-allowed
```

### 3.3 实现策略 — 统一函数

所有操作按钮走同一个包装函数，自动管理状态：

```
smartButton(buttonEl, asyncFn, options)
  → 自动设置 loading 态
  → 自动处理成功/失败态
  → 自动恢复
  → options.onSuccess / options.onError 回调
```

全站按钮通过 `data-action` 属性声明行为，事件统一委托，不再散落 `onclick`：

```html
<!-- 当前 -->
<button onclick="handleDelete('abc123')">删除</button>

<!-- 改进后 -->
<button data-action="delete" data-id="abc123">删除</button>
```

## 四、Toast 通知系统

### 4.1 替代所有 alert() 和 confirm()

**当前：** `alert('保存成功！')` — 阻塞 UI，必须手动点确定，在不同平台样式不一致。

**改进后：** 非阻塞 Toast，从右上角滑入，3s 自动消失，4 种类型各有颜色和图标：

| 类型 | 颜色 | 图标 | 场景 |
|------|------|------|------|
| success | 绿 | `check-circle` | 保存成功、删除成功、生成完成 |
| error | 红 | `x-circle` | 操作失败、网络错误 |
| warning | 橙 | `alert-triangle` | 确认删除、网络超时 |
| info | 蓝 | `info` | 导入进行中、刷新完成 |

### 4.2 Toast 布局

```
┌─────────────────────────────────┐
│  [图标] 资源已保存到资源库       │  ← 从右上角滑入
│         查看资源                  │  ← 可选操作按钮
│                       [×]       │  ← 手动关闭
│  ██████████████████░░░  3s      │  ← 进度条（自动消失倒计时）
└─────────────────────────────────┘
```

### 4.3 可操作的 Toast

某些通知带有操作按钮：

| 场景 | Toast 内容 | 操作按钮 |
|------|-----------|---------|
| 资源生成完成 | "学习文档已生成" | [预览] |
| 删除成功 | "资源已删除" | [撤销] |
| 测验提交 | "答题结果已保存" | [查看解析] |
| 导入完成 | "文档导入完成" | [打开资源] |
| 保存成功 | "画像已更新" | 无（纯通知） |

## 五、撤销系统

### 5.1 软删除 + 定时撤销

**当前：** `confirm('确定删除？')` → 永久删除 → 无法恢复。

**改进后：** 删除操作先"软标记"，5 秒倒计时，期间可撤销：

```
用户点击删除
  ↓
Toast: "[trash] 已删除 — [撤销]  (5s)"
  ↓
5 秒后自动调 API 真删
  ↓
如果在 5 秒内点了"撤销" → 取消删除，Toast 变 "已恢复"
```

### 5.2 适用场景

| 操作 | 撤销窗口 | 撤销方式 |
|------|---------|---------|
| 删除资源 | 5s | Toast 按钮 |
| 删除学习路径 | 5s | Toast 按钮 |
| 删除会话 | 5s | Toast 按钮 |
| 编辑画像保存 | 3s | Toast 按钮（回滚到旧值） |
| 批量删除 | 8s | Toast 按钮（批量恢复） |

## 六、确认对话框

### 6.1 替代 confirm()

**当前：** `if (!confirm('确定删除吗？')) return;` — 原生弹窗，样式不可控。

**改进后：** 自定义模态对话框，三种模式：

**模式 1：危险确认（删除类）**

```
┌──────────────────────────────┐
│                              │
│    [红色图标]                 │
│    确定要删除此资源？         │
│    此操作不可撤销（5 秒内可恢复）│
│                              │
│    [取消]      [确认删除]     │  ← 红底按钮
└──────────────────────────────┘
```

**模式 2：普通确认（保存/提交类）**

```
┌──────────────────────────────┐
│                              │
│    [蓝色图标]                 │
│    确定要提交所有答案？       │
│    提交后无法修改             │
│                              │
│    [返回检查]    [确认提交]   │  ← 渐变主按钮
└──────────────────────────────┘
```

**模式 3：输入确认（高危操作）**

```
┌──────────────────────────────┐
│                              │
│    此操作将删除所有测验记录   │
│    请输入"删除"确认：         │
│    [__________]               │
│                              │
│    [取消]      [确认]         │  ← 未输入时 disabled
└──────────────────────────────┘
```

### 6.2 使用约定

简单删除用 Toast 撤销（不需要弹窗），批量操作和不可撤销操作才弹确认对话框：

| 操作 | 反馈方式 |
|------|---------|
| 删除单条资源 | Toast + 撤销按钮 |
| 删除单条路径 | Toast + 撤销按钮 |
| 批量删除 | 确认对话框 |
| 提交测验 | 确认对话框 |
| 退出登录 | 无确认（点击即退，可立即重新登录） |

## 八、可中断操作

### 8.1 生成/导入 取消按钮

**当前：** 资源生成和文档导入一旦开始无法取消，用户只能苦等或刷新页面。

**改进后：** 所有长操作旁边有取消按钮：

```
┌──────────────────────────────────┐
│ 正在生成资源...        [取消]    │
│ ████████░░░░░░  65%             │
│ 正在生成：思维导图               │
└──────────────────────────────────┘
```

点击取消后：
1. 停止轮询
2. Toast 提示"已取消生成，已完成的部分已保存"
3. 按钮恢复 idle 态

### 8.2 轮询生命周期管理

**当前：** `setTimeout` 递归，无清理机制，页面跳转后仍在后台运行。

**改进后：** 使用 `AbortController` + 页面可见性控制：

```
const controller = new AbortController();

// 开始轮询
pollStatus(taskId, controller.signal);

// 取消：
// 1. 用户点"取消" → controller.abort()
// 2. 页面隐藏 → 暂停，恢复后继续
// 3. 页面卸载 → controller.abort()
// 4. 超时 → controller.abort() + Toast 提示

// 页面隐藏/恢复
document.addEventListener('visibilitychange', () => {
  if (document.hidden) pausePolling();
  else resumePolling();
});
```

## 九、即时输入反馈

### 9.1 搜索：输入即搜

**当前：** 资源库搜索框 → 输入 → 点"刷新" → 等待 — 三步操作。

**改进后：** 输入 300ms 后自动发起搜索（debounce），无需手动点按钮。

```
用户输入 "二叉树"
  → 300ms 无新输入
  → 自动发起 API 请求
  → 结果列表更新
  → 无结果时显示空状态"未找到包含'二叉树'的资源"
```

搜索框右侧加一个 `x` 清除按钮（输入内容后出现），点击清空并恢复全量列表。

### 9.2 筛选：切换即生效

**当前：** 资源库类型下拉 → 选"文档" → 点"刷新" → 等待。

**改进后：** 下拉选择后立即筛选，无刷新按钮。

### 9.3 知识图谱搜索改进

**当前：** 只做前端精确匹配，没有模糊搜索，没有搜索建议。

**改进后：** 输入时下拉显示匹配建议，选中后平滑聚焦到该节点，无匹配时提示。

## 十四、操作事件统一委托

### 14.1 从 onclick 到 data-action

**当前问题：** 事件绑定散落在三处 — HTML `onclick` 属性、`window.handleXxx`、`addEventListener`。

**改进后：** 所有操作通过 `data-action` 声明，JS 层统一委托处理：

```html
<!-- 资源卡片操作 -->
<div class="resource-card" data-id="res123">
  <button data-action="preview" data-id="res123">预览</button>
  <button data-action="delete" data-id="res123">删除</button>
  <button data-action="regenerate" data-id="res123" data-kp="二叉树">重新生成</button>
</div>
```

```javascript
// 统一委托
document.addEventListener('click', async (e) => {
  const btn = e.target.closest('[data-action]');
  if (!btn) return;

  const action = btn.dataset.action;
  const handlers = {
    preview: handlePreview,
    delete: handleDeleteWithUndo,
    regenerate: handleRegenerate,
    // ...
  };

  if (handlers[action]) {
    await smartButton(btn, () => handlers[action](btn.dataset));
  }
});
```

### 14.2 好处

- 一处注册，全站生效
- 动态生成的 DOM 自动获得事件
- 容易追踪和调试
- 不再需要 `window.handleXxx`

### 16.2 文件职责

| 文件 | 职责 | 暴露 |
|------|------|------|
| `toast.js` | Toast 创建/销毁/队列管理 | `showToast(msg, type, actions)` |
| `button.js` | smartButton 包装 + data-action 统一委托 | `smartButton(el, fn, opts)` |
| `dialog.js` | 三种确认对话框（危险/普通/输入） | `showDialog({type, title, desc})` → Promise |
| `command.js` | 命令面板的索引/搜索/渲染/导航 | `initCommandPalette()` |
| `shortcut.js` | 全局 + 页面级快捷键注册 | `registerShortcut(key, fn, scope)` |

### 16.3 依赖关系

```
toast.js   ← 独立，无依赖

shortcut.js ← 独立，无依赖
```

所有页面 `import` 所需模块，不需要的全部引入（每个页面只引入自己需要的）。

## 十七、效果预期

改造完成后，用户感知的变化：

| 场景 | 当前体验 | 改进后体验 |
|------|---------|-----------|
| 删除资源 | 弹窗"确定删除？"→点确定→资源消失（无法恢复） | 点删除→Toast"已删除[撤销]"→5s 后自动消失 |
| 生成资源 | 点"开始生成"→按钮无变化→等待→突然完成 | 按钮变"生成中..."带 spinner→进度条→完成时 Toast 通知+可预览 |
| 搜索资源 | 打字→点"刷新"→等待→出结果 | 打字→300ms 后自动出结果 |
| 网络错误 | 弹窗"网络异常，请稍后重试"→必须手动关闭 | Toast 红色提示→3s 自动消失 |
| 批量删除 | 逐条点删除→逐条确认→逐条等待 | 多选→点批量删除→确认对话框→一次性处理 |
| 生成到一半想取消 | 无法取消，只能刷新页面 | 点"取消"→已完成的保留→Toast 提示 |
| 快速导航 | 侧边栏逐一点击 | Ctrl+K 搜索→回车→跳转 |
| 测验提交 | 每题依次调 API→无进度提示 | 提交按钮显示进度"提交中 3/10"→完成 Toast |
