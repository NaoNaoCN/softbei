# 前端与后端冲突检查报告

> 检查日期：2026-06-03
> 检查范围：`frontend/` 全部 HTML/JS/CSS vs `backend/` 路由、Schema、ORM

---

## 一、严重冲突（直接影响功能）

### 1.1 `ResourceMetaOut.content_path` 与 ORM `content` 字段名不匹配

| 项目 | 字段名 |
|------|--------|
| ORM `ResourceMeta` (models.py:226) | `content: Mapped[str \| None]` |
| Schema `ResourceMetaOut` (schemas.py:291) | `content_path: Optional[str]` |
| 前端 library.html 取值 | `r.content_path` |

**问题**：Schema 声明了 `content_path`，但 ORM 列名为 `content`。Pydantic `from_attributes=True` 按字段名从 ORM 对象取值，`content_path` 在 ORM 上不存在，因此 API 响应中 `content_path` **始终为 `null`**。

前端 library.html 中 doc/summary 类型资源的预览依赖 `r.content_path` 渲染 Markdown 内容（library.html:850, 887），当前所有此类资源预览将显示 "(暂无内容)"。

**修复**：将 `ResourceMetaOut.content_path` 改为 `content`，或添加 `field_validator` / `model_validator` 做字段映射。

> 违反 CLAUDE.md 约定："Schema field names must exactly match ORM field names."

### 1.2 `LearningRecordOut` 缺少 `kp_name` 字段

| 前端取值 | Schema 定义 |
|----------|------------|
| pathway.html:1300 `r.kp_name` | `LearningRecordOut` 仅有 `kp_id`，无 `kp_name` |

**问题**：学习路径页和评估页通过 `getLearningRecords()` 获取记录后，使用 `r.kp_name` 展示知识点名称。但 `LearningRecordOut` 只有 `kp_id`（ID 字符串），没有 `kp_name`（人类可读名称）。前端将显示空名称。

**修复**：在 `list_records` 端点中 JOIN `KGNode` 表，将 `kp_name` 加入返回结构。

### 1.3 `getChatMessages` 返回结构与 Schema 不一致

| 后端实际返回 (main.py:490-499) | Schema `ChatMessageOut` |
|------|------|
| `role`, `content`, `resource_type`, `extra`, `created_at` | 仅 `role`, `content`, `created_at` |

后端手动构造 dict 绕过了 `ChatMessageOut` schema，添加了 `extra` 和 `resource_type` 字段。前端 chat.html:598 依赖 `m.extra.video_refs` 渲染视频卡片。

**问题**：虽然当前手动构造的 dict 包含 `extra`，但无类型安全保障。若未来改为使用 `ChatMessageOut` 序列化，`extra` 字段会丢失，前端 `m.extra.video_refs` 将抛出 TypeError。

**修复**：将 `extra` 和 `resource_type` 加入 `ChatMessageOut` schema 定义。

## 二、中等问题（潜在运行时错误）

### 2.1 错误字段命名不一致

| 端点 | 错误字段名 |
|------|----------|
| `GenerateTaskOut` | `error_msg` |
| `BatchTaskItem` | `error_message` |
| `KGBuildTaskOut` | `error_msg` |
| 文档导入状态 | `error` |

前端 generate.html 单任务轮询用 `status.error_msg` (line 651)，批量任务用 `t.error_message` (line 736)。前端 library.html 导入状态用 `s.error` (line 754)，图谱构建用 `s.error_message \|\| s.error_msg` (line 685)。

**问题**：三套命名体系，前端代码需要多处兼容。若新增端点遗漏任一变体，错误信息显示"未知错误"。

**修复**：统一为 `error_message`（全拼，与 ORM 一致）。

### 2.2 `recorded_at` vs `created_at` 混用

| 模块 | ORM 字段 | Schema 字段 | 前端取值 |
|------|---------|------------|---------|
| `LearningRecord` | `recorded_at` | `recorded_at` ✓ | profile.html:707 `recorded_at` ✓ |
| `LearningRecord` | `recorded_at` | `recorded_at` ✓ | pathway.html `created_at` ✗ |

**问题**：pathway.html 学习记录列表访问 `r.created_at`，实际字段名是 `recorded_at`。时间戳将显示 `undefined`。

**修复**：pathway.html 中 `created_at` → `recorded_at`。

### 2.3 聊天消息 `extra` 字段无空值守卫

chat.html:598：
```javascript
const videoRefs = m.extra.video_refs || [];
```

**问题**：若后端某条消息的 `extra` 为 `null`/`undefined`（如用户消息或文本回复），直接访问 `.video_refs` 将抛出 `TypeError: Cannot read properties of null`。

**修复**：改为 `(m.extra && m.extra.video_refs) || []`。

### 2.4 测验多选答案解析脆弱

evaluate.html:522：
```javascript
const correctOpts = JSON.parse(answerStr);  // 期望 '["A","B"]'
```

**问题**：后端 `QuizItemOut.answer: Any` 类型未约束。若后端存储多选答案为逗号分隔字符串 `"A,B"` 而非 JSON 数组 `'["A","B"]'`，`JSON.parse` 失败后 catch 返回 `[]`，导致正确答案为空集，所有多选答案都判定为错误。

**修复**：统一多选答案格式为 JSON 数组，或前端增加逗号分隔字符串的降级解析。

### 2.5 答题详情模态框数据注入风险

evaluate.html:605：
```javascript
onclick="showAttemptDetail(${JSON.stringify(a).replace(/"/g, '&quot;')})"
```

**问题**：将完整 attempt 对象序列化后嵌入 HTML 属性。若 `stem`/`explanation` 等字段含换行符、反斜杠或 HTML 标签，可能导致 JS 语法错误或 XSS。同时大数据量会增加 DOM 体积。

**修复**：改为 `data-*` 属性或 JS 事件绑定方式传递数据。

## 三、安全问题

### 3.1 `updateSessionTitle` 无权限校验

| 方面 | 详情 |
|------|------|
| 前端调用 | `PATCH /chat/sessions/{id}/title?user_id=xxx` + body `{title}` |
| 后端 `TitleIn` | `title: str`, `user_id: Optional[int] = None` |
| 权限检查 (main.py:550) | `if body.user_id:` 才做校验 |

**问题**：前端不在 body 中发送 `user_id`，`body.user_id` 为 `None`，因此 `if body.user_id:` 为 `False`，权限检查**被跳过**。任意用户可修改任意会话的标题。

**修复**：将 `user_id` 改为 JWT 依赖 `Depends(get_current_user_id)`，或改为必填字段。

### 3.2 认证模式不统一

31 个端点中，仅 14 个使用 JWT `Depends(get_current_user_id)`，其余 17 个使用裸 `user_id: int` 查询参数。

| 认证方式 | 端点数量 | 示例 |
|---------|---------|------|
| JWT (安全) | 14 | `/kg/graph`, `/resources/{id}` (DELETE), `/quiz/submit` |
| 查询参数 (无验证) | 17 | `/profile`, `/generate`, `/chat/sessions`, `/records` |

**问题**：查询参数端点仅依赖前端传入的 `user_id`，未验证 JWT token 中的用户身份是否匹配。虽然 `apiFetch` 同时发送 JWT token 和 `user_id`，但后端不校验两者的对应关系。

**修复**：统一使用 `Depends(get_current_user_id)` 获取用户身份。

## 四、前端内部问题

### 4.1 Lucide 图标版本未锁定

所有页面使用：
```html
<script src="https://unpkg.com/lucide@latest"></script>
```

**问题**：`@latest` 随新大版本自动更新，可能引入 breaking icon 重命名或删除，导致页面图标全部消失。

**修复**：锁定版本，如 `lucide@0.460.0`。

### 4.2 页面 CSS 属性硬编码

多个页面 style 块中硬编码颜色值，与 `styles.css` 变量不一致：

| 页面 | 硬编码颜色 | 应使用 |
|------|----------|--------|
| evaluate.html:44 | `background: #F7F8FC` | `var(--color-bg)` |
| evaluate.html:47 | `background: #fff` | `var(--color-card)` |
| library.html:19 | `color: #1E1E2E` | `var(--color-text)` |
| generate.html | 多处 `#4F6EF7` | `var(--color-primary)` |

**影响**：未来切换主题时需逐个文件修改。

### 4.3 API 错误处理不完整

`apiFetch` 在 401 时清除认证并跳转登录页，但在网络错误或其他 HTTP 错误时仅抛出 Error。多数页面调用 API 时用 `try/catch` 捕获但不展示用户友好提示，用户可能看到空白页面而不知原因。

## 六、修复优先级建议

| 优先级 | 问题 | 影响 |
|--------|------|------|
| **P0** | `content_path` → `content` 字段名不匹配 | 所有 doc/summary 资源预览无内容 |
| **P0** | `LearningRecordOut` 缺少 `kp_name` | 学习路径页知识点名称空白 |
| **P1** | `updateSessionTitle` 无权限校验 | 任意用户可修改他人会话标题 |
| **P1** | 聊天消息 `extra` 无空值守卫 | 非视频消息可能触发 JS 报错 |
| **P1** | `ChatMessageOut` schema 缺少字段 | 类型安全缺失 |
| **P2** | 错误字段命名不一致 (`error_msg`/`error_message`/`error`) | 部分错误信息显示"未知错误" |
| **P2** | `recorded_at` vs `created_at` 混用 | 学习记录时间显示异常 |
| **P2** | 多选答案 JSON.parse 兼容性 | 多选答案可能误判 |
| **P3** | 认证模式不统一 | 安全风险（需大规模改后端） |
| **P3** | Lucide `@latest` 版本锁定 | 未来可能图标消失 |
| **P3** | 页面硬编码颜色值 | 主题切换困难 |
