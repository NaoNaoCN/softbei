# 前端架构设计文档

## 1. 概述

个性化学习助手前端采用**原生 HTML/CSS/JS 多页面架构**，通过 FastAPI StaticFiles 挂载于 `/app` 路径。前端由 8 个独立 HTML 页面组成，共享统一的 API 层、样式系统和侧边栏组件，通过 JWT 令牌实现客户端鉴权。

### 技术选型

| 层次 | 技术 | 说明 |
|------|------|------|
| 页面架构 | 原生多页面 (MPA) | 无 SPA 框架，页面间通过 `window.location.href` 导航 |
| 样式 | 原生 CSS + CSS 自定义属性 | 共享 `styles.css` + 页面内联 `<style>` |
| 脚本 | ES Module (`<script type="module">`) | 每个页面独立加载所需模块 |
| API 通信 | Fetch API | 统一封装于 `api.js`，自动携带 JWT |
| 鉴权 | JWT (Bearer Token) | 存储于 `localStorage`，401 自动跳转登录页 |
| 图标 | Lucide | CDN 加载，`data-lucide` 属性声明式使用 |
| 图表 | ECharts 5 | 仅知识图谱页，力导向图 |
| Markdown | marked 4.3 + highlight.js 11.9 | 聊天页、资源库预览 |
| 数学公式 | KaTeX 0.16.9 | 聊天页、资源库预览 |

### 3.2 页面加载流程

每个受保护页面（除 `auth.html` 外）遵循统一的初始化流程：

```
1. HTML 解析 → 加载 CDN 依赖 (lucide, echarts 等)
2. <link> 加载 shared/styles.css
3. <style> 加载页面特定样式
4. <script type="module"> 执行：
   a. import API 函数 + initSidebar
   b. 鉴权守卫：if (!isLoggedIn()) → redirect auth.html
   c. initSidebar('pageName') → 渲染侧边栏
   d. 获取 userId = getUserId()
   e. 调用业务 API 加载数据
   f. 构建 DOM / 绑定事件
   g. lucide.createIcons() 初始化图标
```

### 3.3 状态管理

- **无跨页面状态共享**：页面间通过完整页面跳转导航，数据在每次加载时从 API 重新获取
- **localStorage** 仅存储鉴权信息：`user_id`、`access_token`、`session_id`
- **页面级状态**：使用模块级变量（如 `activeSessionId`、`currentPage`）或 DOM data 属性
- **URL 参数传递**：`generate.html?kp_id=...&type=doc` 用于跨页面传递知识点上下文

## 4. 页面架构

### 4.1 auth.html — 登录/注册

**定位**：独立鉴权页面，不包含侧边栏和共享样式。

**页面结构**：
```
.auth-container
├── .auth-logo (标题 + 副标题)
├── #alert-box (消息提示)
├── .tabs
│   ├── .tab.active (登录)
│   └── .tab (注册)
├── #login-form
│   ├── 用户名输入框
│   ├── 密码输入框
│   └── 登录按钮
└── #register-form (默认隐藏)
    ├── 用户名输入框
    ├── 密码输入框
    ├── 确认密码输入框
    └── 注册按钮
```

**交互流程**：
- 已登录用户 → 自动跳转 `index.html`
- 登录成功 → `setAuth()` 写入 localStorage → 跳转 `index.html`
- 注册成功 → 显示成功提示 → 切换到登录 tab → 预填用户名
- 客户端校验：用户名 3-20 字符、密码 ≥6 字符、两次密码一致

### 4.2 index.html — 首页仪表盘

**定位**：用户登录后的着陆页，展示学习概览和快捷入口。

**页面结构**：
```
.layout
├── #sidebar-container (侧边栏，带用户信息和退出按钮)
└── .main
    ├── .page-title / .page-subtitle
    ├── .stats-grid (4 列统计卡片)
    │   ├── 学习文档数 | 思维导图数 | 测验题数 | 学习路径数
    ├── .feature-grid (2×2 快捷入口)
    │   ├── 生成资源 → generate.html
    │   ├── 我的资源 → library.html
    │   ├── 学习评估 → evaluate.html
    │   └── 学习路径 → pathway.html
    └── .card (画像摘要)
        ├── 加载中 / 空状态 / 画像内容
        └── 跳转编辑 → profile.html
```

**数据加载**：`loadStats()`、`loadProfile()`、`loadPathways()` 三个异步函数并行执行，各自独立渲染对应 DOM 区域。

### 4.3 chat.html — 智能对话

**定位**：核心交互页面，实现 AI 对话、资源推荐和批量生成。

**页面结构**：
```
.layout
├── #sidebar-container (侧边栏，无底部信息区)
└── .chat-container
    ├── .session-panel (左侧会话列表)
    │   ├── .session-header (新建会话按钮)
    │   └── .session-list (会话列表，支持双击重命名、删除)
    └── .chat-main (右侧对话区)
        ├── .chat-header (会话标题 + 引导横幅)
        ├── .messages-area (消息列表)
        │   ├── .message.user (用户消息气泡)
        │   └── .message.assistant (AI 回复，含 Markdown/LaTeX 渲染)
        ├── #rec-panel (资源推荐面板，动态插入)
        │   ├── 推荐条目 + 加入路径按钮
        │   └── 批量生成进度卡片 (2s 轮询)
        └── .input-area (输入框 + 发送按钮)
```

**核心交互**：
- 首条消息自动创建会话（后端延迟命名，前端 3s 后重新加载）
- AI 回复内容经过 Markdown → 代码高亮 → LaTeX 公式渲染管线
- 推荐面板根据 `metadata.recommendations` 动态展示
- 批量生成通过 `metadata.batch_id` 触发进度轮询

**渲染管线**（chat.html & library.html 共用）：
```
原始文本
  → LaTeX 占位符保护 ($$...$$  → __LATEX_BLOCK_n__)
  → marked.parse() Markdown 渲染
  → highlight.js 代码块语法高亮
  → LaTeX 占位符还原
  → renderMathInElement() KaTeX 公式渲染
  → 注入 DOM
```

### 4.4 profile.html — 学习画像

**定位**：查看和编辑用户学习画像，为系统个性化提供数据基础。

**页面结构**：
```
.layout
├── #sidebar-container
└── .main
    ├── .page-title / .page-subtitle
    ├── .tabs
    │   ├── .tab.active (查看画像)
    │   └── .tab (编辑画像)
    ├── #view-panel (查看模式)
    │   ├── .stats-grid (4 列统计：已掌握/薄弱/每日时长/版本)
    │   └── .card (画像详情：标签云展示)
    └── #edit-panel (编辑模式，默认隐藏)
        ├── .form-grid (2 列表单)
        │   ├── 专业、每日学习时长、认知风格
        │   └── 学习目标 (textarea)
        ├── 已掌握知识点 (textarea，逗号分隔)
        ├── 薄弱知识点 (textarea)
        ├── 易错知识点 (textarea)
        └── .form-actions (保存 + 取消)
```

**数据流**：
- 查看：`getProfile(userId)` → 填充 DOM
- 编辑：表单 → `updateProfile(userId, data)` → 刷新查看视图
- 知识点标签按类别着色：已掌握(绿)、薄弱(橙)、易错(灰)

### 4.5 generate.html — 资源生成

**定位**：选择知识点和资源类型，触发 AI 生成个性化学习资源。

**页面结构**：
```
.layout
├── #sidebar-container
└── .main
    ├── .page-title / .page-subtitle
    ├── .mode-tabs
    │   ├── 对话式 (跳转 chat.html)
    │   └── 直接生成 (当前页)
    └── .content-grid (左表单 + 右结果)
        ├── .form-card (左侧粘性表单)
        │   ├── #kp-cascade (级联知识点选择器)
        │   │   └── 课程 → 章 → 知识点 → 子知识点 → 概念
        │   ├── 资源类型多选 (文档/思维导图/测验/代码/总结)
        │   ├── 测验题型配置 (单选/多选/填空数量)
        │   ├── 智能推荐按钮
        │   ├── 高级选项 (创意度滑块)
        │   └── 生成按钮
        └── .result-card (右侧结果区)
            ├── 空状态 / 进度条 / 成功结果
            └── 批量生成：Tab 切换查看各类型结果
```

**级联选择器**：从知识图谱 API 获取完整树结构，根据 `IS_PART_OF` 和 `CONTAINS` 边关系动态构建多级 `<select>` 下拉菜单。

**生成模式**：
- **单个生成**：选一种资源类型 → `startGeneration()` → 轮询 `getTaskStatus()` (2s 间隔)
- **批量生成**：选多种类型 → `startBatchGeneration()` → 轮询 `getBatchStatus()` (2s 间隔)
- **智能推荐**：`smartPlanResources()` 获取推荐方案后自动选中

### 4.6 pathway.html — 学习路径

**定位**：知识图谱可视化、学习路径管理和学习记录查看（最复杂的页面）。

**页面结构**：
```
.layout
├── #sidebar-container
└── .main
    ├── .page-title / .page-subtitle
    ├── .tabs
    │   ├── 知识图谱 | 学习路径 | 学习记录
    ├── #tab-kg (知识图谱)
    │   ├── .kg-filter (文档选择 / 根节点 / 深度 / 类型过滤 / 搜索 / 已学状态 / 路径叠加 / 背景切换 / 全屏)
    │   ├── .kg-graph-area (#kg-chart ECharts 力导向图容器)
    │   ├── .kg-detail-panel (右侧滑入详情面板)
    │   │   ├── 节点信息 + 关联关系 + 关联资源
    │   │   └── 操作按钮 (生成资源 / 加入路径)
    │   └── .node-grid (节点列表浏览)
    ├── #tab-pathways (学习路径)
    │   ├── 新建路径输入框
    │   └── .pathway-grid (路径卡片列表)
    │       └── .pathway-card
    │           ├── 进度条 + 步骤列表 (点击切换完成状态)
    │           └── 删除按钮
    └── #tab-records (学习记录)
        ├── .records-stats (统计卡片)
        └── 记录列表
```

**知识图谱可视化**（ECharts 力导向图）：
- 5 种节点类型：课程(90px) / 章(55px) / 知识点(30px) / 子知识点(20px) / 概念(10px)，不同颜色和符号大小
- 力导向布局参数：`repulsion: 200, gravity: 0.1, edgeLength: [120, 280]`
- 搜索定位：动画移动视角至目标节点，高亮 (橙色边框+发光)，非匹配节点透明度降至 0.3
- 已学状态叠加：已学节点饱和度增强+边框+发光+放大，未学节点透明度降至 0.15
- 路径叠加：已完成(绿边框) / 当前(橙边框+放大) / 计划中(蓝边框)，非路径节点变暗
- 缩放自适应：小节点类型在低缩放级别自动隐藏
- 全屏模式：`body.kg-fullscreen` 隐藏侧边栏和其他页面元素
- 点击节点：右侧滑入详情面板，展示关联关系和资源，提供快捷操作按钮

### 4.7 library.html — 资源库

**定位**：资源浏览管理、文档导入、知识图谱构建、内容预览。

**页面结构**：
```
.layout
├── #sidebar-container
└── .main
    ├── .page-title / .page-subtitle
    ├── .stats-bar (5 列统计：文档/思维导图/测验/代码/总结数量)
    ├── .import-section (文档导入区，可折叠)
    │   ├── 文件选择器 (PDF/DOCX/MD/TXT)
    │   ├── 标题输入框
    │   ├── 导入进度显示
    │   └── 上传按钮
    ├── .filter-bar (类型筛选 + 搜索 + 刷新)
    ├── .resource-list (资源卡片列表)
    │   └── .resource-item
    │       ├── 类型图标 + 标题 + 日期
    │       └── 操作按钮 (构建KG / 预览 / 测验 / 删除)
    ├── .pagination (分页控件)
    └── #preview-modal (全屏预览弹窗)
        ├── .modal-header (标题 + 关闭)
        └── .modal-body (按类型渲染)
            ├── Markdown/总结 → marked + KaTeX 渲染
            ├── 代码 → highlight.js 语法高亮
            ├── 思维导图 → 嵌套 <ul> CSS 树形图
            ├── 测验 → 题目/选项/答案/解析列表
            └── PDF → <iframe> 嵌入 (降级为下载链接)
```

**文档导入流程**：
```
选择文件 → importDocumentAsync(userId, file, title)
  → 轮询 getImportStatus(taskId) (1.5s 间隔, 最多 300 次)
  → 完成/失败 → 刷新文档列表和统计
```

**KG 构建流程**：
```
点击构建KG → buildKg(docId, userId)
  → 轮询 getKgBuildStatusByDoc(docId) (1.5s 间隔)
  → 完成 → 显示构建成功提示
```

**思维导图渲染**：纯 CSS 实现，递归构建 `<ul>/<li>` 嵌套结构，通过 `::before`/`::after` 伪元素绘制树形连接线。根节点蓝色背景，二级节点浅灰背景，三级以上无背景。

### 4.8 evaluate.html — 学习评估

**定位**：在线答题、历史查看和薄弱知识点分析。

**页面结构**：
```
.layout
├── #sidebar-container
└── .main
    ├── .page-title / .page-subtitle
    ├── .tabs
    │   ├── 开始测验 | 答题历史 | 薄弱分析

    │           ├── .quiz-question (题干 + 题型标签)
    │           ├── .quiz-options
    │           │   └── .quiz-option (单选互斥 / 多选切换 / 填空输入)
    │           └── .submit-bar (提交按钮)
    ├── #tab-history (历史)
    │   ├── 答题记录表格
    │   └── #attempt-modal (答题详情弹窗)
    └── #tab-weak (薄弱分析)
        └── .weak-item (正确率 < 60% 的知识点)
            ├── 正确率进度条
            └── 去学习按钮 → generate.html?kp=...&type=doc
```

**答题交互**：
- 单选题：点击选项→互斥选中
- 多选题：点击选项→切换选中/取消
- 填空题：文本输入框
- 提交：逐题调用 `submitQuizAnswer()` → 服务端判分 → 回显对错样式
- 答对自动调用 `postLearningRecord(action=complete)`
- 得分 ≥60% 显示通过，<60% 显示未通过

**薄弱分析**：按知识点分组聚合答题记录，计算正确率，筛选 <60% 的知识点展示。

### 5.3 api.js — 统一 API 层

## 6. 鉴权流程

### 6.1 令牌生命周期

```
登录页 → POST /auth/login
         ↓ (成功)
         localStorage: user_id, access_token
         ↓
受保护页面 → apiFetch() 自动附加 Authorization: Bearer <token>
         ↓ (401)
         clearAuth() → 跳转 auth.html
```

### 6.2 鉴权守卫

每个受保护页面在 `<script type="module">` 顶部执行：
```javascript
import { isLoggedIn } from './assets/api.js';
if (!isLoggedIn()) {
    window.location.href = 'auth.html';
}
```

这是纯客户端保护，后端 API 层面通过 JWT 验证中间件进行实际鉴权。

### 6.3 特殊情况

- `importDocumentAsync` 是唯一直接使用 `fetch()` 而非 `apiFetch()` 的函数，因为上传文件需要 `FormData` 且不能设置 `Content-Type` 请求头。它手动读取并附加 Authorization 头。

## 7. 数据流模式

### 7.1 API → DOM 渲染模式

```
1. import API 函数
2. 异步调用 API (e.g., const data = await getResources(userId, filters))
3. 空值检查 → 渲染空状态
4. 数据映射 → HTML 字符串 (data.map(item => `<div>...</div>`).join(''))
5. element.innerHTML = html
6. lucide.createIcons() 初始化新图标
7. (如有数学公式) renderMathInElement(element)
```

### 7.2 轮询模式

用于异步任务状态跟踪（生成、导入、KG 构建）：
```
const poll = async () => {
    const status = await getTaskStatus(taskId);
    更新 UI (进度条/状态文本)
    if (status === 'done' || status === 'failed') → 停止轮询
    else → setTimeout(poll, 1500-3000)
};
```

### 7.3 URL 参数跨页面通信

| 来源 | 目标 | 参数 |
|------|------|------|
| pathway 详情面板 | generate.html | `?kp_id=...&kp_name=...` |
| evaluate 薄弱分析 | generate.html | `?kp=...&type=doc` |
| chat 推荐面板 | generate.html | `?kp_id=...` |

### 7.4 事件绑定

- 模块作用域函数通过 `window.fnName = fnName` 暴露给内联 `onclick` 属性

## 10. 设计决策与权衡

### 10.1 MPA vs SPA

**选择 MPA 的原因**：
- 项目规模适中，8 个页面各司其职，无需 SPA 路由
- 零构建工具依赖，开发部署简单
- 页面间天然隔离，避免状态污染

**代价**：
- 页面跳转有白屏闪烁
- 共享状态只能通过 localStorage 或 URL 参数传递
- 无法实现页面切换动画

### 10.2 原生 JS vs 框架

**选择原生 JS 的原因**：
- 无需编译打包流程
- 团队成员可直接修改，无框架学习成本
- 页面交互以表单提交和数据展示为主，不涉及复杂 UI 状态同步

**代价**：
- DOM 操作代码量大（大量 `innerHTML` 拼接）
- 无组件化能力，HTML 结构重复
- 状态管理分散在模块变量中

### 10.3 共享样式策略

当前采用 `styles.css`（共享基础样式）+ 页面内联 `<style>`（页面特定样式）的混合策略。页内联样式会覆盖共享样式中的同名规则。部分共享规则（如 sidebar、page-title）在页面中仍有冗余定义——这是为了确保页面独立可工作，但增加了维护成本。后续可逐步清理页面中的重复规则。

### 10.4 鉴权方案

JWT 存储在 localStorage 存在 XSS 风险。对于本项目（高校内部教学系统），当前方案在安全性和简洁性之间取得了可接受的平衡。若需增强安全性，可考虑：
- HttpOnly Cookie 存储令牌（需后端配合）
- 令牌过期后自动刷新
- CSP (Content Security Policy) 限制脚本来源
