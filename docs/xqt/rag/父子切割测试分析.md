## 1. 问题定义

父子切割的核心假设：**用父块（更大上下文）替代子块返回给 LLM，能提升生成质量，同时不损害检索精度**。

需要回答三个问题：
1. 检索阶段：回填父块后，返回给 LLM 的上下文质量是否提升？
2. 生成阶段：LLM 基于父块上下文生成的答案是否更好？
3. 是否有副作用（延迟增加、冗余信息过多、费用变化）？

**所有评估完全自动化，不依赖人工标注。**

## 2. 量化指标体系

### 2.1 指标总览

```
                    ┌──────────────────────────────┐
                    │      RAG 质量评估三层指标       │
                    └──────────────────────────────┘
                                    │
            ┌───────────────────────┼───────────────────────┐
            ▼                       ▼                       ▼
    ┌───────────────┐     ┌───────────────┐     ┌───────────────┐
    │ 检索质量       │     │ 上下文质量      │     │ 生成质量       │
    │ (L1: Input)   │     │ (L2: Bridge)  │     │ (L3: Output)  │
    │ 完全自动化      │     │ 完全自动化      │     │ 完全自动化      │
    │ Judge 打分     │     │ LLM 自比对     │     │ 现有 Judge     │
    └───────────────┘     └───────────────┘     └───────────────┘
```

### 2.2 L1 — 检索质量指标

测量"检索到的子块与查询的相关性"，父子切割前后应**持平**（子块嵌入粒度不变）。

| 指标 | 含义 | 自动化方式 | 来源 |
|------|------|-----------|------|
| **Precision@5** | 前 5 个结果中相关的比例 | `judge.judge_chunk_relevance_batch()` 自动打分 | `metrics.precision_at_k` |
| **MRR** | 第一个相关结果的平均排名倒数 | 同上 | `metrics.mrr` |
| **NDCG@5** | 考虑排序位置的相关性得分 | 同上 | `metrics.ndcg_at_k` |
| **Hit Rate@5** | 至少命中 1 个相关结果的比例 | 同上 | `metrics.hit_rate` |

**裁判方式**：`RAGJudge.judge_chunk_relevance_batch()` 使用 LLM（temperature=0.0）对每个 chunk 打分 0/1/2。无需人工标注 relevance labels。所有计算函数已在 `backend/evaluation/metrics.py` 中实现。

**Recall 的自动化困难与处理**：Recall 需要知道"总相关 chunk 数"，这在无人工标注时无法精确获得。替代方案——不计算 Recall，改用 **Hit Rate**（更直观：有没有找到至少一个相关结果）和 **NDCG**（同时考虑相关性和排序位置，不依赖总数）。

### 2.3 L2 — 上下文质量指标

这是父子切割最直接的评估维度。核心问题：**父块上下文是否比子块上下文包含更多有用信息？**

#### 2.3.1 上下文信息增益 (Context Information Gain, CIG) — 核心指标

**思想**：不依赖人工"标准答案"，而是将**父块所覆盖的完整章节文本**作为参考标准。因为父块 = 完整章节，它天然包含该节的所有信息。评估时，用 LLM 对比"检索到的上下文"和"完整章节文本"之间的信息覆盖度。

```
对于每个查询：
  1. 定位查询对应的"参考章节"（父块所覆盖的完整文本，程序中可获取）
  2. LLM 从参考章节中提取该查询涉及的所有关键信息点（自动生成，无需人工）
  3. LLM 判断检索到的上下文中覆盖了多少个信息点

  CIG = (检索上下文覆盖的信息点数) / (参考章节中的信息点总数)
```

**为什么无人工标注也能成立**：
- 参考标准来自**文档本身**（父块对应的完整章节文本），不是人工编写的外部答案
- 关键信息点由 LLM 自动从参考章节中提取
- A/B 两组的 CIG 使用**同一组信息点**作为分母，对比公平

**示例**：

```
查询: "Sigmoid 函数的优缺点"  (LLM 从章节标题自动生成)

参考章节文本 (完整的 3.2.1 节, ~2000 字符):
  ...Sigmoid 函数的定义为 σ(x) = 1/(1+e^(-x))，输出范围 (0,1)...
  ...优点: 平滑可导，输出可解释为概率...
  ...缺点: 非零中心导致 zig-zag 收敛，梯度消失，计算成本高...
  ...与 Tanh 对比: Tanh 零中心...

LLM 自动提取的关键信息点:
  1. 公式: σ(x) = 1/(1+e^(-x))
  2. 输出范围 (0,1), 可解释为概率
  3. 优点: 平滑可导
  4. 优点: 适合二分类输出层
  5. 缺点: 输出非零中心, 导致 zig-zag 收敛
  6. 缺点: x→±∞ 时梯度趋近 0 (梯度消失)
  7. 与 Tanh 的对比

基线检索上下文 (5 × 500 字符子块) 覆盖: 1, 2, 3       → CIG = 3/7 = 0.43
父子切割检索上下文 (5 个父块) 覆盖:       1-6          → CIG = 6/7 = 0.86  ✅ +100%
```

**CIG 的有效性保证**：
- 父子切割的父块 = 完整章节 → 父块本身几乎总是 CIG ≈ 1.0（自己覆盖自己）
- CIG 衡量的不是"答案多好"，而是**"检索过程丢失了多少信息"**
- 基线系统的 CIG < 1.0 是信息丢失；父子切割的 CIG 应更接近 1.0

#### 2.3.2 上下文冗余度 (Context Redundancy Ratio, CRR)

定义：返回给 LLM 的上下文中，与查询无关的字符占比。

```
CRR = (LLM 判定为 irrelevant 的字符数) / (总字符数)
```

**自动化方式**：LLM 对上下文中的每个句子标注 `relevant | tangential | irrelevant`，计算 irrelevant 占比。不依赖人工判断。

父块更大可能引入更多冗余 → CRR 可能上升。去重机制缓解此问题。目标：CIG 显著提升而 CRR 不超过 0.60。

#### 2.3.3 跨块信息整合率 (Cross-Chunk Integration Rate, CCIR)

定义：上下文中包含完整"前提→推导→结论"推理链的比例。

**自动化方式**：LLM 判断（temperature=0.0）。对每个查询的检索上下文，直接问 LLM：

> "此上下文是否包含完整的推理链条（前提/假设 → 推导/分析 → 结论/总结）？返回 JSON: {has_chain: true/false, reasoning: '...'}"

子块上下文往往只含推理片段，父块上下文可呈现完整论证。CCIR 提升是父子切割的独有优势。

#### 2.3.4 兄弟块覆盖增益 (Sibling Coverage Gain, SCG)

定义：同一父块下的兄弟子块中，被检索到的子块有多少也被 Judge 判定为相关。

```
SCG = (检索到的兄弟子块中 Judge 判定为相关的数量) / (检索到的兄弟子块总数)
```

**完全程序化**：无需人工标注。对每个查询，检索 top-10 子块 → 按 `parent_chunk_id` 分组 → 对每个有 ≥2 个兄弟被检索到的父块，用 Judge 批量打分 → 计算兄弟相关率。

SCG 高 → 父块边界划分合理（同一父块的内容确实都相关）。SCG 低 → 父块切分边界需要调整。

### 2.4 L3 — 生成质量指标

直接复用现有 `RAGJudge`，完全自动化，无需任何改动。

| 指标 | 来源 | 含义 |
|------|------|------|
| **Faithfulness** | `judge.judge_faithfulness()` | 生成内容是否忠实于检索上下文 |
| **Hallucination Rate** | `metrics.hallucination_rate()` | 生成内容中无依据的陈述占比 |
| **Completeness** | `judge.judge_completeness()` | 答案是否覆盖了知识点的核心方面 |

**预期效果**：Completeness +10-15%（父块覆盖更多信息点）、Hallucination -5-10%（更完整上下文 → 更少脑补）、Faithfulness +5-10%。

### 2.5 系统效率指标

全部通过代码测量，无需人工。

| 指标 | 测量方式 |
|------|---------|
| **检索延迟 P50/P95** | `time.perf_counter()` 包裹 `retrieve()` |
| **父块回填延迟** | `time.perf_counter()` 包裹 `_resolve_parent_chunks()` |
| **上下文总长度** | `len(context)` |
| **Embedding API 调用次数** | `index_chunks()` 中 `_embed_batch` 的调用计数 |
| **索引存储总量** | `SELECT count(*), sum(length(text)) FROM document_chunk` |

## 3. 测试数据集：全自动生成

### 3.1 核心原则

**不编写、不标注、不审核任何测试数据。** 所有测试输入从文档本身自动生成。

### 3.2 查询自动生成流程

```
Step 1: 选择测试文档
  └─ 直接使用 knowledge_base/ 下的已有文档（或手动放入 3-5 个 PDF 到指定目录）
  └─ 文档选择只此一步需要人工，且不需额外工作——用现有知识库即可

Step 2: 自动提取查询候选
  └─ 从文档中提取所有章节标题（# / ## / ###）
  └─ 对每个标题运行 split_text() 取首段作为上下文

Step 3: LLM 批量生成查询
  └─ 一次 API 调用：输入 30 个 (标题, 首段) 对
  └─ LLM 为每个标题生成 1-2 个自然语言查询
  └─ LLM 同时标注每个查询的类型 (factual / concept / reasoning) 和难度 (easy / medium / hard)
  └─ 输出结构化 JSON

Step 4: 自动筛选
  └─ 排除重复或高度相似的查询（基于文本相似度 > 0.85）
  └─ 确保 3 种类型 × 3 种难度各至少 3 条
  └─ 最终保留 30-50 条
```

### 3.3 查询生成 Prompt

```
你是一个测试查询生成器。给定文档章节的标题和首段内容，为每个章节生成可用于
RAG 检索评估的自然语言查询。

对每个章节，生成 1-2 个查询，并标注：
- type: "factual"（事实型，答案在单一段落中）/
        "concept"（概念型，答案分布在一节中的多个段落）/
        "reasoning"（推理型，答案需要跨段落综合理解）
- difficulty: "easy" / "medium" / "hard"

返回 JSON 数组。每个元素格式：
{"section_title": "...", "query": "...", "type": "...", "difficulty": "..."}

输入章节列表:
[ {章节标题和首段内容} ]
```

### 3.4 CIG 参考标准生成

对于每个自动生成的查询，需要定位其"参考章节"来计算 CIG。

```
Step 1: 检索定位
  └─ 用自动生成的 query 做一次检索（baseline 系统）
  └─ 取 top-3 检索结果的 section 字段

Step 2: 获取完整章节文本
  └─ 在 document_chunk 表中查找同一 section 的所有 chunk（包括未被检索到的）
  └─ 按 chunk_index 排序后拼接 = "参考章节文本"

Step 3: LLM 提取关键信息点
  └─ 对每个 (query, 参考章节文本) 对
  └─ LLM 从参考章节文本中提取该 query 涉及的所有关键信息点
  └─ 输出: {"key_points": ["信息点1", "信息点2", ...]}

Step 4: 缓存参考标准
  └─ 写入 tests/data/parent_child_eval/reference_standards.json
  └─ 后续 A/B 测试直接读取，无需重新生成
```

**参考标准是一次性 LLM 生成 + 文件缓存**。不需要人工检查或修正——即使 LLM 生成的信息点略有偏差，A/B 两组使用同一套参考标准，对比仍然公平。

### 3.5 自动化程度总结

| 组件 | 原方案 | 新方案 |
|------|--------|--------|
| 测试查询 | 人工编写 30-50 条 | LLM 从文档标题自动生成 |
| 查询分类 (类型/难度) | 人工标注 | LLM 生成查询时同步标注 |
| 标准答案 (gold answer) | 人工编写 + 审核 | **不需要** — CIG 对比参考章节文本 |
| 关键信息点 (key_points) | 人工拆分 atomic facts | LLM 从参考章节文本中自动提取 |
| CIC/CIG 计算 | 人工 key_points vs 检索上下文 | LLM 自动判断（信息点已自动生成） |
| Relevance labels | 人工标注 | `judge.judge_chunk_relevance_batch()` |
| CCIR 判断 | 人工判断完整逻辑链 | LLM 判断 |
| CRR 判断 | LLM（无需人工） | 同左 |
| SCG 计算 | 程序化（无需人工） | 同左 |
| L3 生成质量 | `judge.evaluate_full()` | 同左 |

## 4. A/B 测试框架设计

### 4.1 总体架构

```
┌───────────────────────────────────────────────────────────────┐
│              全自动化 A/B 测试流程（零人工标注）                  │
│                                                               │
│  Step 1: 准备阶段（一次性，全自动化）                             │
│    ├─ 从 knowledge_base/ 选取 3-5 个 PDF                       │
│    ├─ LLM 自动生成 30-50 个测试查询 + 类型/难度标注              │
│    ├─ 对每个查询定位参考章节 → LLM 提取关键信息点                 │
│    └─ 缓存到 tests/data/parent_child_eval/                     │
│                                                               │
│  Step 2: 构建两套索引（一次性）                                  │
│    ├─ A 组（baseline）: 当前 500 字符固定切分                    │
│    └─ B 组（candidate）: 父子切割                               │
│                                                               │
│  Step 3: 执行批量检索 + 评估（可重复运行）                        │
│    └─ 对每个查询: A/B 各检索 → L1 Judge 打分 → L2 CIG/CRR/CCIR │
│       → L3 生成答案 + evaluate_full                            │
│                                                               │
│  Step 4: 统计检验 + 报告                                        │
│    └─ Wilcoxon signed-rank test → Markdown 报告                │
└───────────────────────────────────────────────────────────────┘
```

### 4.2 测试脚本骨架

编写 `tests/eval_parent_child_chunking.py`：

```python
"""
父子切割 A/B 对比评估脚本（零人工标注，全自动化）
用法:
  python -m tests.eval_parent_child_chunking --mode generate  # Step 1: 生成测试数据
  python -m tests.eval_parent_child_chunking --mode ab_test   # Step 2-3: A/B 测试
  python -m tests.eval_parent_child_chunking --mode report    # Step 4: 生成报告
"""

import asyncio
import json
import time
import hashlib
from pathlib import Path
from dataclasses import dataclass, field
from typing import Optional

from backend.evaluation.metrics import (
    precision_at_k, mrr, ndcg_at_k, hit_rate
)
from backend.evaluation.judge import RAGJudge, get_judge


# ============================================================
# 数据结构
# ============================================================

@dataclass
class AutoGeneratedQuery:
    """全自动生成的测试查询（无人工标注）"""
    query_id: str
    query_text: str
    query_type: str        # LLM 自动标注: factual / concept / reasoning
    difficulty: str        # LLM 自动标注: easy / medium / hard
    source_section: str    # 来源章节标题
    # 以下由 LLM 自动生成（非人工标注）
    reference_key_points: list[str] = field(default_factory=list)
    # 从参考章节文本中自动提取的关键信息点


@dataclass
class ABTestResult:
    """单查询的 A/B 对比结果"""
    query_id: str

    # A 组（baseline）
    a_relevance_labels: list[int]
    a_context_text: str
    a_cig: float
    a_crr: float
    a_has_chain: bool
    a_latency_ms: float

    # B 组（parent-child）
    b_relevance_labels: list[int]
    b_context_text: str
    b_cig: float
    b_crr: float
    b_has_chain: bool
    b_latency_ms: float

    # L3 生成质量（可选，耗 LLM tokens）
    a_faithfulness: Optional[float] = None
    b_faithfulness: Optional[float] = None
    a_completeness: Optional[float] = None
    b_completeness: Optional[float] = None


# ============================================================
# Step 1: 自动生成测试数据
# ============================================================

class QueryAutoGenerator:
    """从文档自动生成测试查询和参考标准。零人工参与。"""

    def __init__(self, judge: RAGJudge):
        self.judge = judge

    async def generate_from_documents(
        self,
        doc_paths: list[str],
        target_count: int = 40,
    ) -> list[AutoGeneratedQuery]:
        """
        从文档列表中全自动生成测试查询。

        1. 加载文档 → 提取章节标题和首段
        2. LLM 批量生成查询 + 类型/难度标注
        3. 去重 + 按类型/难度分层采样
        4. 对每个查询，LLM 从对应章节提取关键信息点
        """
        # Step 1: 提取章节信息
        sections = await self._extract_sections(doc_paths)

        # Step 2: LLM 批量生成查询
        raw_queries = await self._llm_generate_queries(sections)

        # Step 3: 去重 + 分层采样
        queries = self._deduplicate_and_sample(raw_queries, target_count)

        # Step 4: 对每个查询生成参考关键信息点
        for q in queries:
            q.reference_key_points = await self._extract_key_points(
                query=q.query_text,
                section_title=q.source_section,
            )
            # 用 query_text + source_section 的 hash 作为稳定 ID
            q.query_id = hashlib.md5(
                f"{q.query_text}{q.source_section}".encode()
            ).hexdigest()[:12]

        return queries

    async def _extract_sections(self, doc_paths: list[str]) -> list[dict]:
        """提取每个文档的章节标题和首段文本。"""
        from backend.rag.loader import _split_markdown_by_headers, convert_to_markdown

        all_sections = []
        for path in doc_paths:
            md_text = convert_to_markdown(path)
            raw_sections = _split_markdown_by_headers(md_text)
            for title, text in raw_sections:
                # 取前 300 字符作为 LLM 生成查询的上下文
                preview = text[:300]
                all_sections.append({
                    "source_file": path,
                    "section_title": title,
                    "section_preview": preview,
                    "full_text": text,       # 保留完整文本用于后续关键信息点提取
                })
        return all_sections

    async def _llm_generate_queries(
        self, sections: list[dict]
    ) -> list[dict]:
        """调用 LLM 从章节标题+首段批量生成查询。"""
        # 构造批量 prompt（每批 20 个章节，避免 prompt 过长）
        all_queries = []
        batch_size = 20

        for i in range(0, len(sections), batch_size):
            batch = sections[i:i + batch_size]
            items = []
            for j, sec in enumerate(batch):
                items.append(
                    f"{i+j+1}. 标题: {sec['section_title']}\n"
                    f"   首段: {sec['section_preview'][:200]}"
                )

            prompt = f"""你是一个测试查询生成器。给定文档章节的标题和首段内容，
为每个章节生成用于 RAG 检索评估的自然语言查询。

对每个章节生成 1-2 个查询，并标注类型和难度：
- type: "factual"（事实型）/ "concept"（概念型）/ "reasoning"（推理型）
- difficulty: "easy" / "medium" / "hard"

返回 JSON 数组（只返回 JSON，不要解释）：
[{{"index": 编号, "section_title": "原标题", "query": "生成的查询",
   "type": "concept", "difficulty": "medium"}}, ...]

输入章节:
{chr(10).join(items)}"""

            from backend.services.llm import chat_completion
            response = await chat_completion(
                messages=[{"role": "user", "content": prompt}],
                temperature=0.3,  # 稍高温度增加查询多样性
                max_tokens=2000,
            )
            try:
                batch_queries = json.loads(response)
                all_queries.extend(batch_queries)
            except json.JSONDecodeError:
                continue

        return all_queries

    def _deduplicate_and_sample(
        self, raw_queries: list[dict], target: int
    ) -> list[AutoGeneratedQuery]:
        """去重 + 按类型/难度分层采样，确保覆盖所有类别。"""
        # 简单去重：完全相同的 query_text 合并
        seen = set()
        unique = []
        for q in raw_queries:
            text = q.get("query", "").strip()
            if text and text not in seen:
                seen.add(text)
                unique.append(q)

        # 分层采样：每种 (type, difficulty) 至少 3 条
        strata: dict[tuple, list] = {}
        for q in unique:
            key = (q.get("type", "concept"), q.get("difficulty", "medium"))
            strata.setdefault(key, []).append(q)

        sampled = []
        for key, items in strata.items():
            sampled.extend(items[:max(3, target // len(strata))])

        # 截断到 target
        return [
            AutoGeneratedQuery(
                query_id="",  # 稍后填充
                query_text=q["query"],
                query_type=q.get("type", "concept"),
                difficulty=q.get("difficulty", "medium"),
                source_section=q.get("section_title", ""),
            )
            for q in sampled[:target]
        ]

    async def _extract_key_points(
        self, query: str, section_title: str
    ) -> list[str]:
        """
        从完整章节文本中，LLM 自动提取与查询相关的关键信息点。

        使用现有的文档数据：找到该章节的所有 chunk → 拼接为完整章节文本。
        """
        # 从向量库查询该章节的完整文本
        from backend.db.vector import get_collection
        col = get_collection()

        # 查找该 section 下的所有 chunk
        raw = await col.get(
            where={"section": section_title},
            limit=50,
        )
        full_text = "\n\n".join(raw.get("documents", []))

        if not full_text:
            return []

        prompt = f"""从以下文档章节中，提取与查询相关的所有"关键信息点"（atomic facts）。
每个信息点应是一个简短、独立的陈述句。

查询: {query}

章节内容:
{full_text[:4000]}

返回 JSON 格式（只返回 JSON，不要解释）:
{{"key_points": ["信息点1", "信息点2", ...]}}"""

        try:
            from backend.services.llm import chat_completion
            response = await chat_completion(
                messages=[{"role": "user", "content": prompt}],
                temperature=0.0,
                max_tokens=500,
            )
            result = json.loads(response)
            return result.get("key_points", [])
        except Exception:
            return []

class ParentChildABEvaluator:
    """父子切割 A/B 对比评估器（全自动化）"""

    def __init__(self, queries: list[AutoGeneratedQuery], judge: RAGJudge):
        self.queries = queries
        self.judge = judge
        self.results: list[ABTestResult] = []

    async def run_ab_test(self) -> dict:
        """执行完整 A/B 测试"""

        for query in self.queries:
            # --- A 组: baseline 检索 ---
            t0 = time.perf_counter()
            a_chunks = await self._retrieve_baseline(query.query_text)
            a_latency = (time.perf_counter() - t0) * 1000

            a_labels = await self.judge.judge_chunk_relevance_batch(
                query=query.query_text,
                chunks=[c.text for c in a_chunks],
            )
            a_context = "\n\n".join(c.text for c in a_chunks)

            # --- B 组: 父子切割检索 ---
            t0 = time.perf_counter()
            b_chunks = await self._retrieve_parent_child(query.query_text)
            b_latency = (time.perf_counter() - t0) * 1000

            b_labels = await self.judge.judge_chunk_relevance_batch(
                query=query.query_text,
                chunks=[c.text for c in b_chunks],
            )
            b_context = "\n\n".join(c.text for c in b_chunks)

            # --- L2 上下文质量 ---
            a_cig = await self._compute_cig(query, a_context)
            b_cig = await self._compute_cig(query, b_context)

            a_crr = await self._compute_crr(query.query_text, a_context)
            b_crr = await self._compute_crr(query.query_text, b_context)

            a_chain = await self._compute_has_chain(query.query_text, a_context)
            b_chain = await self._compute_has_chain(query.query_text, b_context)

            self.results.append(ABTestResult(
                query_id=query.query_id,
                a_relevance_labels=a_labels,
                a_context_text=a_context,
                a_cig=a_cig, a_crr=a_crr, a_has_chain=a_chain,
                a_latency_ms=a_latency,
                b_relevance_labels=b_labels,
                b_context_text=b_context,
                b_cig=b_cig, b_crr=b_crr, b_has_chain=b_chain,
                b_latency_ms=b_latency,
            ))

        return self.generate_report()

    async def _retrieve_baseline(self, query: str):
        """使用当前系统检索（baseline）。"""
        from backend.rag.retriever import retrieve
        return await retrieve(query, n_results=5)

    async def _retrieve_parent_child(self, query: str):
        """使用父子切割检索（candidate）。"""
        # 调用增强版 retrieve，内部含 _resolve_parent_chunks()
        from backend.rag.retriever import retrieve  # 假定已升级
        return await retrieve(query, n_results=5)

    async def _compute_cig(
        self, query: AutoGeneratedQuery, context: str
    ) -> float:
        """
        计算上下文信息增益 (Context Information Gain)。

        用 LLM 判断 reference_key_points（已自动生成）中有多少
        在检索上下文中被覆盖。
        """
        if not query.reference_key_points:
            return 0.0

        points_json = json.dumps(
            [{"id": i, "point": p}
             for i, p in enumerate(query.reference_key_points)],
            ensure_ascii=False,
        )

        prompt = f"""判断以下每个"关键信息点"是否在"检索上下文"中有明确提及
或可从中直接推断。

关键信息点:
{points_json}

检索上下文:
{context[:5000]}

返回 JSON 列表（只返回 JSON）:
[{{"id": 0, "covered": true, "evidence": "原文引用"}}, ...]"""

        try:
            from backend.services.llm import chat_completion
            response = await chat_completion(
                messages=[{"role": "user", "content": prompt}],
                temperature=0.0,
                max_tokens=500,
            )
            results = json.loads(response)
            covered = sum(1 for r in results if r.get("covered"))
            return covered / len(query.reference_key_points)
        except Exception:
            return self._fallback_cig(query.reference_key_points, context)

    def _fallback_cig(
        self, key_points: list[str], context: str
    ) -> float:
        """关键词匹配的 CIG 降级方案（零 API 调用）。"""
        import re
        covered = 0
        for point in key_points:
            keywords = set(re.findall(r'[\u4e00-\u9fff]{2,}', point))
            keywords |= set(
                w.lower() for w in re.findall(r'[a-zA-Z]{3,}', point)
            )
            if not keywords:
                continue
            ratio = sum(
                1 for kw in keywords if kw.lower() in context.lower()
            ) / len(keywords)
            if ratio > 0.5:
                covered += 1
        return covered / len(key_points) if key_points else 1.0

    async def _compute_crr(self, query: str, context: str) -> float:
        """
        计算上下文冗余度。LLM 逐句标注 relevant/tangential/irrelevant，
        返回 irrelevant 字符占比。
        """
        import re

        sentences = re.split(r'(?<=[。！？.!?\n])\s*', context)
        sentences = [s.strip() for s in sentences if s.strip()]
        if not sentences:
            return 0.0

        labels = []
        batch_size = 20

        for i in range(0, len(sentences), batch_size):
            batch = sentences[i:i + batch_size]
            items = json.dumps(
                [{"id": j, "text": s[:200]} for j, s in enumerate(batch)],
                ensure_ascii=False,
            )

            prompt = f"""标注每个句子与查询的相关程度: "relevant" / "tangential" / "irrelevant"。

查询: {query}

句子: {items}

返回 JSON: [{{"id": 0, "label": "relevant"}}, ...]（只返回 JSON）"""

            try:
                from backend.services.llm import chat_completion
                response = await chat_completion(
                    messages=[{"role": "user", "content": prompt}],
                    temperature=0.0,
                    max_tokens=300,
                )
                batch_labels = [
                    r.get("label", "relevant")
                    for r in json.loads(response)
                ]
                labels.extend(batch_labels)
            except Exception:
                labels.extend(["relevant"] * len(batch))

        irrelevant_chars = sum(
            len(sentences[i]) for i, label in enumerate(labels)
            if label == "irrelevant"
        )
        return irrelevant_chars / len(context) if context else 0.0

    async def _compute_has_chain(
        self, query: str, context: str
    ) -> bool:
        """LLM 判断上下文是否包含完整推理链。"""
        prompt = f"""判断以下检索上下文是否包含完整的"推理/论证链条"
（前提/假设→推导/分析→结论/总结），而不仅是孤立的事实片段。

查询: {query}

检索上下文:
{context[:4000]}

返回 JSON: {{"has_chain": true/false, "reasoning": "一句话解释"}}（只返回 JSON）"""

        try:
            from backend.services.llm import chat_completion
            response = await chat_completion(
                messages=[{"role": "user", "content": prompt}],
                temperature=0.0,
                max_tokens=100,
            )
            return json.loads(response).get("has_chain", False)
        except Exception:
            return False

    # ----------------------------------------------------------
    # 报告生成
    # ----------------------------------------------------------

    def generate_report(self) -> dict:
        """生成汇总报告（直接输出 JSON 的 dict 格式）。"""
        if not self.results:
            return {}

        a_labels_all = [r.a_relevance_labels for r in self.results]
        b_labels_all = [r.b_relevance_labels for r in self.results]

        # L1 检索质量
        retrieval_metrics = {
            "precision_at_5": {
                "baseline": self._safe_metric(
                    precision_at_k, a_labels_all, 5
                ),
                "parent_child": self._safe_metric(
                    precision_at_k, b_labels_all, 5
                ),
            },
            "mrr": {
                "baseline": self._safe_metric(mrr, a_labels_all),
                "parent_child": self._safe_metric(mrr, b_labels_all),
            },
            "ndcg_at_5": {
                "baseline": self._safe_metric(
                    lambda labels: sum(ndcg_at_k(l, 5) for l in labels) / max(len(labels), 1),
                    a_labels_all,
                ),
                "parent_child": self._safe_metric(
                    lambda labels: sum(ndcg_at_k(l, 5) for l in labels) / max(len(labels), 1),
                    b_labels_all,
                ),
            },
            "hit_rate_at_5": {
                "baseline": self._safe_metric(hit_rate, a_labels_all, 5),
                "parent_child": self._safe_metric(hit_rate, b_labels_all, 5),
            },
        }

        # L2 上下文质量
        context_metrics = {
            "cig_mean": {
                "baseline": self._mean([r.a_cig for r in self.results]),
                "parent_child": self._mean([r.b_cig for r in self.results]),
            },
            "crr_mean": {
                "baseline": self._mean([r.a_crr for r in self.results]),
                "parent_child": self._mean([r.b_crr for r in self.results]),
            },
            "ccir": {
                "baseline": sum(1 for r in self.results if r.a_has_chain) / len(self.results),
                "parent_child": sum(1 for r in self.results if r.b_has_chain) / len(self.results),
            },
            "context_length_mean_chars": {
                "baseline": self._mean([len(r.a_context_text) for r in self.results]),
                "parent_child": self._mean([len(r.b_context_text) for r in self.results]),
            },
        }

        # 按查询类型分层的 CIG
        cig_by_type = {"factual": {"a": [], "b": []},
                       "concept": {"a": [], "b": []},
                       "reasoning": {"a": [], "b": []}}
        for r, q in zip(self.results, self.queries):
            t = q.query_type
            if t in cig_by_type:
                cig_by_type[t]["a"].append(r.a_cig)
                cig_by_type[t]["b"].append(r.b_cig)

        stratified = {}
        for t, data in cig_by_type.items():
            if data["a"] and data["b"]:
                stratified[t] = {
                    "n_queries": len(data["a"]),
                    "cig_baseline": self._mean(data["a"]),
                    "cig_parent_child": self._mean(data["b"]),
                    "cig_gain_pct": (
                        (self._mean(data["b"]) - self._mean(data["a"]))
                        / max(self._mean(data["a"]), 0.01) * 100
                    ),
                }

        # 系统效率
        latencies_a = sorted([r.a_latency_ms for r in self.results])
        latencies_b = sorted([r.b_latency_ms for r in self.results])
        n = len(latencies_a)

        return {
            "n_queries": len(self.results),
            "n_factual": sum(1 for q in self.queries if q.query_type == "factual"),
            "n_concept": sum(1 for q in self.queries if q.query_type == "concept"),
            "n_reasoning": sum(1 for q in self.queries if q.query_type == "reasoning"),
            "retrieval": retrieval_metrics,
            "context_quality": context_metrics,
            "stratified_by_type": stratified,
            "latency": {
                "p50_ms": {
                    "baseline": latencies_a[n // 2] if n > 0 else 0,
                    "parent_child": latencies_b[n // 2] if n > 0 else 0,
                },
                "p95_ms": {
                    "baseline": latencies_a[int(n * 0.95)] if n > 0 else 0,
                    "parent_child": latencies_b[int(n * 0.95)] if n > 0 else 0,
                },
            },
        }

    @staticmethod
    def _safe_metric(func, *args, **kwargs):
        try:
            return func(*args, **kwargs)
        except Exception:
            return 0.0

    @staticmethod
    def _mean(values: list[float]) -> float:
        return sum(values) / len(values) if values else 0.0
```

### 4.3 统计显著性检验

```python
def significance_test(
    results: list[ABTestResult],
    metric_name: str,
) -> dict:
    """
    Wilcoxon signed-rank 配对检验。
    H0: 两组无差异; H1: B 组优于 A 组。

    无需人工判断——p_value 自动计算。
    """
    from scipy.stats import wilcoxon

    if metric_name == "cig":
        a_vals = [r.a_cig for r in results]
        b_vals = [r.b_cig for r in results]
    elif metric_name == "crr":
        a_vals = [r.a_crr for r in results]
        b_vals = [r.b_crr for r in results]
    else:
        raise ValueError(f"Unknown metric: {metric_name}")

    # 筛掉 A/B 相同的 pair（wilcoxon 要求差值非零）
    diffs = [(b - a) for a, b in zip(a_vals, b_vals) if abs(b - a) > 0.001]
    if len(diffs) < 5:
        return {"significant": False, "reason": "有效差值不足 5 对"}

    stat, p_value = wilcoxon(
        [d for d in diffs if d >= 0],
        [abs(d) for d in diffs if d < 0],
    )
    # 或直接: stat, p_value = wilcoxon(b_vals, a_vals, alternative='greater')

    effect = (sum(b_vals) - sum(a_vals)) / len(a_vals)

    return {
        "statistic": float(stat),
        "p_value": float(p_value),
        "significant": p_value < 0.05,
        "effect_size": round(effect, 4),
        "effect_size_pct": round(effect / max(self._mean(a_vals), 0.01) * 100, 1),
    }
```

def auto_decision(report: dict) -> dict:
    """
    基于 A/B 测试结果自动决策。
    返回 {"verdict": "enable" | "disable" | "tune", "reason": "..."}
    """
    cig_gain = (
        report["context_quality"]["cig_mean"]["parent_child"]
        - report["context_quality"]["cig_mean"]["baseline"]
    ) / max(report["context_quality"]["cig_mean"]["baseline"], 0.01)

    retrieval_precision_change = abs(
        report["retrieval"]["precision_at_5"]["parent_child"]
        - report["retrieval"]["precision_at_5"]["baseline"]
    )

    latency_increase = (
        report["latency"]["p95_ms"]["parent_child"]
        - report["latency"]["p95_ms"]["baseline"]
    )

    crr = report["context_quality"]["crr_mean"]["parent_child"]

    # 决策逻辑
    checks = {
        "cig_significant_gain": cig_gain > 0.30,
        "retrieval_not_degraded": retrieval_precision_change < 0.05,
        "latency_acceptable": latency_increase < 10,
        "redundancy_acceptable": crr < 0.60,
    }

    if all(checks.values()):
        return {
            "verdict": "enable",
            "reason": "所有指标达标，建议默认开启父子切割",
        }
    elif checks["cig_significant_gain"] and (
        checks["retrieval_not_degraded"] or checks["latency_acceptable"]
    ):
        return {
            "verdict": "enable",
            "reason": f"CIG 提升 {cig_gain:.0%}，建议开启；关注未达标指标",
        }
    elif checks["cig_significant_gain"]:
        return {
            "verdict": "tune",
            "reason": "CIG 提升但检索质量或延迟退化，建议调优参数后重测",
        }
    else:
        return {
            "verdict": "disable",
            "reason": f"CIG 提升仅 {cig_gain:.0%}，不满足最低要求，建议重新设计父块策略",
        }

## 9. 成本估算

所有评估依赖 LLM API 调用，以下估算基于 qwen3.5-plus 的定价：

| LLM 调用 | 次数 | 每次 token 估算 | 总 token 估算 |
|----------|------|---------------|------------|
| 查询生成 (Step 1) | 2-3 次批量调用 | ~2000 tokens | ~5K |
| 关键信息点提取 | 40 次 | ~800 tokens | ~32K |
| Chunk relevance 打分 | 80 次 (每查询 × 2组) | ~600 tokens | ~48K |
| CIG 计算 | 80 次 | ~800 tokens | ~64K |
| CRR 计算 | 80 次 | ~400 tokens | ~32K |
| CCIR 判断 | 80 次 | ~300 tokens | ~24K |
| L3 生成质量 (可选) | 80 次 | ~2000 tokens | ~160K |
| **合计** | | | **~365K tokens** |

按 qwen3.5-plus 约 0.002 元/1K tokens → **总费用约 0.73 元**。L3 生成质量是最贵的部分（约占一半），可首次测试时去掉 L3，仅验证 L1+L2，确认 CIG 显著提升后再加入 L3 做完整评估。
