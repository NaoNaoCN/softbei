# 知识图谱渲染优化方案

## 问题诊断

当前 ECharts 力导向图在节点数量较多（50+）时，出现以下问题：

| 问题 | 症状 | 根因 |
|------|------|------|
| 节点重叠 | 相近节点互相遮挡，无法点击 | 力导向布局参数固定，未随节点数自适应 |
| 标签碰撞 | 文字互相覆盖，无法辨认 | `label.show: true` 始终开启，ECharts 无内置标签避让 |
| 视觉噪声 | 小节点（Concept/SubPoint）淹没大节点 | 缩放阈值过低，大量小节点在小缩放比下仍可见 |
| 布局拥挤 | 中心区域节点密集成团 | `repulsion` 固定 500，对 100+ 节点不足 |
| 全图加载 | 每次渲染全量数据 | 无增量加载或视口裁剪 |

---

## 优化方案

### 方案一：标签按缩放层级显示（低成本，高收益）

**当前状态：** 所有节点标签始终 `show: true`，仅 `zoomThresholds` 控制节点可见性但标签跟随节点。

**改进：** 为标签增设独立的缩放阈值，比节点阈值更高一档——节点可以显示，但标签只在放大到足够程度时才出现。

| 节点类型 | 节点阈值 (现有) | 标签阈值 (新增) |
|----------|:----------:|:----------:|
| Course | 0.0 | 0.1 |
| Chapter | 0.1 | 0.5 |
| KnowledgePoint | 0.3 | 0.8 |
| SubPoint | 0.5 | 1.5 |
| Concept | 1.0 | 2.0 |

实现方式：在 `updateVisibilityByZoom()` 中增加 label 控制：

```js
const labelThresholds = {
    'Course': 0.1, 'Chapter': 0.5, 'KnowledgePoint': 0.8,
    'SubPoint': 1.5, 'Concept': 2.0,
};
// 在节点更新时：
const lt = labelThresholds[n.node_type] || 0.8;
const showLabel = zoom >= lt;
return { ...n, label: { ...n.label, show: showLabel } };
```

### 方案二：力导向参数按节点数自适应（低成本，中收益）

**当前状态：** `repulsion: 500`, `gravity: 0.05`, `edgeLength: [80, 380]` 固定不变。

**改进：** 在 `renderGraph()` 中根据节点总数动态调整：

```js
const nodeCount = chartNodes.length;
const repulsion = nodeCount < 30 ? 500 : nodeCount < 80 ? 800 : 1200;
const gravity = nodeCount < 30 ? 0.05 : nodeCount < 80 ? 0.03 : 0.02;
const edgeLengthLow = nodeCount < 30 ? 80 : nodeCount < 80 ? 60 : 40;
const edgeLengthHigh = nodeCount < 30 ? 380 : nodeCount < 80 ? 300 : 250;
const friction = nodeCount < 30 ? 0.6 : 0.4;
```

逻辑：节点越多，斥力越大、引力越小、边长越短——让图自然"散开"的同时不占用过多画布。

### 方案三：提高默认深度 & 缩放阈值收紧（低成本，中收益）

**当前状态：** 默认深度为 2，缩放阈值偏低（SubPoint 在 zoom 0.5 就可见）。

**改进：**

1. 默认深度保持 2，但将深度 3+ 标记为"需要时加载"
2. 收紧缩放阈值，让小节点在更高缩放比下才出现：

```js
const zoomThresholds = {
    'Course': 0.0,
    'Chapter': 0.2,         // 原 0.1
    'KnowledgePoint': 0.5,  // 原 0.3
    'SubPoint': 1.0,        // 原 0.5
    'Concept': 2.0,         // 原 1.0
};
```

效果：默认视图只显示 Course → Chapter → KnowledgePoint 三层，SubPoint 和 Concept 需要用户放大后才能看到，大幅降低初始渲染的节点数。

### 方案四：Label 位置策略优化（中成本，高收益）

**当前状态：** 所有标签 `position: 'bottom'`，当节点密集时底部标签互相堆叠。

**改进：** 利用 ECharts 的 `label.position` 根据节点类型差异化：

```js
// 在构建 chartNodes 时按类型设置标签偏好
function getLabelConfig(nodeType, index) {
    const positions = ['bottom', 'right', 'top', 'left', 'inside'];
    return {
        show: true,
        fontSize: nodeType === 'Course' ? 13 : nodeType === 'Chapter' ? 11 : 10,
        position: nodeType === 'Course' ? 'right' :
                  nodeType === 'Chapter' ? 'bottom' :
                  'bottom',
        distance: nodeType === 'Course' ? 12 : nodeType === 'Chapter' ? 8 : 5,
        overflow: 'truncate',
        ellipsis: '...',
        width: nodeType === 'Course' ? 120 : 80,
    };
}
```

### 方案五：最小节点过滤（低成本，中收益）

**当前状态：** 深度 2 仍可能拉入大量 Concept/SubPoint。

**改进：** 在 `applyFilters()` 中，对非搜索场景增加"小节点折叠"选项——当某类型节点数超过阈值时，默认不显示最小的一类：

```js
// 如果总节点 > 60 且 Concept 节点 > 15，默认折叠 Concept
const typeCounts = {};
filteredNodes.forEach(n => { typeCounts[n.type] = (typeCounts[n.type] || 0) + 1; });
if (filteredNodes.length > 60 && (typeCounts['Concept'] || 0) > 15) {
    // 自动取消勾选 Concept，并提示用户
    document.querySelector('#kg-type-filters input[value="Concept"]').checked = false;
    filteredNodes = filteredNodes.filter(n => n.type !== 'Concept');
    // toast 提示
}
```

### 方案六：增量渲染 + 初始居中（中成本，高收益）

**当前状态：** `setOption` 一次性渲染全部节点，力导向计算在主线程阻塞。

**改进：**

1. **分批渲染：** 先渲染 Course + Chapter，200ms 后再补 KnowledgePoint，再 200ms 后补其余：

```js
// 先渲染核心节点
const coreTypes = ['Course', 'Chapter'];
const coreNodes = chartNodes.filter(n => coreTypes.includes(n.node_type));
const coreIds = new Set(coreNodes.map(n => n.id));
const coreEdges = chartEdges.filter(e => coreIds.has(e.source) && coreIds.has(e.target));

chartInstance.setOption({ series: [{ data: coreNodes, links: coreEdges }] });

// 延迟补全
setTimeout(() => {
    chartInstance.setOption({ series: [{ data: chartNodes, links: chartEdges }] });
}, 300);
```

2. **初始聚焦：** 渲染完成后自动缩放到能看到所有 Course 节点的范围：

```js
// 找出所有 Course 节点，适当居中
const courseNodes = chartNodes.filter(n => n.node_type === 'Course');
// 不自动居中以避免干扰用户操作，但可以在初始加载时设置合适的默认 zoom
```

### 方案七：Tooltip 替代小节点标签（低成本，体验优化）

**当前状态：** SubPoint 和 Concept 标签也在 10-11px 下持续显示。

**改进：** 对 SubPoint 和 Concept 类型节点，默认 `label.show: false`，依赖 `tooltip` + `emphasis` 来展示名称。用户 hover 时 tooltip 自然显示节点名，无需标签常驻。

```js
const labelHiddenTypes = new Set(['SubPoint', 'Concept']);
// 在 chartNodes 构建时：
if (labelHiddenTypes.has(nType)) {
    node.label = { show: false };
    node.tooltip = { show: true, formatter: n.name };
}
```

## 实施优先级

| 优先级 | 方案 | 改动量 | 效果 |
|--------|------|--------|------|
| P0 | 方案一：标签按缩放层级显示 | ~15 行 | 立竿见影减少标签碰撞 |
| P0 | 方案三：收紧缩放阈值 | ~5 行 | 初始节点数减半 |
| P1 | 方案二：力导向参数自适应 | ~10 行 | 大图更舒展，小图更紧凑 |
| P1 | 方案七：小节点关闭标签 | ~8 行 | 消灭 Concept 标签噪声 |
| P2 | 方案五：小节点智能折叠 | ~15 行 | 超大图自动降噪 |
| P2 | 方案四：Label 位置差异化 | ~25 行 | 标签分散到不同方位 |
| P3 | 方案六：增量渲染 | ~30 行 | 感知性能提升，首屏更快 |

P0 方案改动量最小、效果最直接，建议优先实施。

---

## 不推荐的方案

1. **Canvas 自绘替代 ECharts：** 工作量大（需自行实现力导向布局、事件系统、缩放平移），性价比极低。
2. **WebGL 渲染器：** ECharts GL 对 graph 类型支持有限，且引入额外依赖，当前节点规模（通常 50-200）完全不需要。
3. **后端预计算布局：** 每次查询结果不同，预计算覆盖不全；前端力导向 200 节点内性能可接受。
