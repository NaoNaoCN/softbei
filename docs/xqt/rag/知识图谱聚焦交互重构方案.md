# 知识图谱聚焦交互重构方案

## 背景

当前知识图谱一次性加载并渲染所有节点，节点数量大时（50-200+），即便已实施缩放阈值和标签控制等优化，初始视图仍然拥挤。学生面对密密麻麻的节点和连线，很难快速定位到自己关心的知识区域。

## 核心思路

将交互模式从"一次加载全图 + 筛选过滤"重构为"**聚焦下钻 + 面包屑导航**"：

- **初始视图**：仅展示 Course 层节点，干净清晰
- **点击展开**：以被点击节点为根，向下展开至多 3 层类型层级
- **面包屑导航**：顶部显示当前聚焦路径，支持逐级返回
- **保留全图模式**：通过切换开关保留现有"展示全部"行为

### 类型层级定义

```
Course → Chapter → KnowledgePoint → SubPoint → Concept
  0          1             2            3          4
```

"展开 3 层"从点击节点的类型开始计数。例如点击 Chapter（索引 1），展示 Chapter + KnowledgePoint + SubPoint（索引 1, 2, 3）。

## 方案评估

### 优势

| 维度 | 说明 |
|------|------|
| **视觉清晰度** | 初始仅 3-8 个 Course 节点，零杂乱 |
| **认知负荷** | 学生逐层探索，符合"从粗到细"的学习认知规律 |
| **性能** | 每次 API 仅返回子树节点，数据量从 200 降至 20-50 |
| **实现成本** | 零后端改动，纯前端交互重构 |
| **力导向效果** | 节点数 < 50 时力导向布局舒展自然，无需自适应参数 |

### 劣势与缓解

| 劣势 | 缓解措施 |
|------|----------|
| 失去全局视野 | 保留"全图模式"一键切换 |
| 跨课程/跨章节的交叉关系（REQUIRES/RELATED_TO）不可见 | 选中节点时，详情面板仍展示其所有关联关系 |
| 面包屑导航增加操作步数 | 支持点击图中任意可见节点直接跳转，无需逐级返回 |

### 风险

| 风险 | 影响 | 缓解 |
|------|------|------|
| 后端 BFS 仅走 IS_PART_OF/CONTAINS 边，交叉边不会引入额外节点 | 子图可能不包含 REQUIRES 关联的跨分支节点 | 详情面板补充展示交叉关系；全图模式可查看完整关联 |
| 部分知识点层级深度不足 3 层（如 SubPoint 下面只有 Concept，仅 2 层） | 展示层数可能不足 3 | 属正常情况，有多少展示多少 |

## 技术方案

### 接口复用（零后端改动）

现有 `GET /kg/graph` 的两个参数即可覆盖需求：

| 场景 | API 调用 | 说明 |
|------|----------|------|
| 初始视图 | `?depth=1` | 仅返回 Course 类型节点 |
| 点击 Course | `?root_id=<id>&depth=3` | BFS 从该 Course 出发，类型限定 Course/Chapter/KP |
| 点击 Chapter | `?root_id=<id>&depth=4` | BFS 从该 Chapter 出发，限定 Chapter/KP/SP |
| 点击 KP | `?root_id=<id>&depth=5` | BFS 从该 KP 出发，限定 KP/SP/Concept |
| 全图模式 | `?depth=5` | 现有行为，展示所有层级 |

**depth 计算公式：**

```js
const TYPE_ORDER = ['Course', 'Chapter', 'KnowledgePoint', 'SubPoint', 'Concept'];

function computeDepth(nodeType) {
    const idx = TYPE_ORDER.indexOf(nodeType);
    return Math.min(idx + 3, 5);  // 从当前层级向下最多 3 层，不超过 5
}
```

### 新增前端状态

```js
let focusState = {
    mode: 'focus',           // 'focus' | 'overview'
    rootNodeId: null,        // 当前聚焦的根节点 ID
    rootNodeType: null,      // 当前根节点类型
    stack: [],               // 面包屑导航栈：[{id, name, type}, ...]
};
```

### 核心函数变更

| 函数 | 当前行为 | 新行为 |
|------|----------|--------|
| `loadKgGraph()` | 按筛选条件加载全图 | 初始加载 depth=1；若 focusState 中有 rootNodeId，则按聚焦参数加载 |
| `handleNodeClick()` | 打开详情面板 | 聚焦模式：对 Course/Chapter/KP 类型节点触发下钻；对 SubPoint/Concept 仍打开详情 |
| `focusOnNode(id, type)` | 不存在 | 将节点设为根，计算 depth，调用 API，推入 stack，重新渲染 |
| `goBack()` | 不存在 | 弹出 stack 顶部，以上一层节点为根重新加载；栈为空时回到初始视图 |
| `switchToOverview()` | 不存在 | 切换到全图模式，depth=5，清空 stack |

### 新增 UI 元素

```
┌──────────────────────────────────────────────────────┐
│  🏠 全部课程  >  程序设计基础  >  第3章  >  [当前]    │  ← 面包屑
│  [全图模式]  [← 返回上级]                              │  ← 操作按钮
└──────────────────────────────────────────────────────┘
```

面包屑位于 `kg-filter` 区域上方或替换第一行 filter row，仅在聚焦模式下显示。

## 实施计划

### 阶段一：核心聚焦逻辑（~50 行 JS）

在 `pathway.html` 中新增：
- `focusState` 状态对象
- `focusOnNode(nodeId, nodeType)` 函数
- `goBack()` 函数
- 修改 `handleNodeClick(params)` 逻辑：聚焦模式下可展开的节点类型触发 `focusOnNode` 而非 `showDetailPanel`
- 修改 `loadKgGraph()` 的 depth 参数计算

### 阶段二：面包屑 UI（~30 行 HTML + CSS）

- 面包屑导航栏 HTML 片段
- CSS 样式（面包屑链接、分隔符、当前项高亮）
- 与 `focusState.stack` 绑定

### 阶段三：全图模式切换（~15 行 JS）

- "全图模式"按钮，点击后 depth=5 重新加载，清空 stack
- 在全图模式下点击节点仍打开详情面板（保留原行为）
- 在全图模式下提供"返回聚焦模式"按钮

### 阶段四：节点可展开性提示（~10 行 JS + CSS）

- 在 Course/Chapter/KP 类型节点的 tooltip 中提示"点击展开下层"
- 可展开节点使用微妙的视觉提示（如光标变为 pointer + 虚线边框）

### 总计改动量

| 文件 | 改动行数 | 说明 |
|------|----------|------|
| `frontend/pathway.html` | ~120 行 | JS 逻辑 + HTML 结构 + CSS 样式 |
| 无其他文件 | 0 | 不需要后端或 API 改动 |

## 验证清单

1. 打开学习规划页面，初始仅显示 Course 节点（1-8 个）
2. 点击一个 Course 节点，图表展开为 Course + Chapter + KnowledgePoint 三层
3. 面包屑显示当前聚焦路径
4. 点击面包屑中某一级，返回对应层级视图
5. 点击 Chapter 节点，视图变为 Chapter + KP + SubPoint
6. 点击 KnowledgePoint 节点，视图变为 KP + SP + Concept
7. 点击 SubPoint 或 Concept 节点，打开详情面板（不继续下钻）
8. 切换到全图模式，恢复现有行为（所有层级可见）
9. 全图模式下切回聚焦模式，回到初始 Course 视图
