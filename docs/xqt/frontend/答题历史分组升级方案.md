# 答题历史分组升级方案

## 问题

当前答题历史是**单条平铺表格**——每道题一行，知识点、答案、结果、时间四列。一次 10 题的测验就产生 10 行，多次测验后表格拉得很长，视觉碎片化，看不出"哪次测验考了多少分"。

## 目标

将平铺的单题列表 → **按测验会话分组**，一次测验对应一个可展开的卡片，默认显示汇总（日期、题数、正确率），点击展开查看单题详情。

## 数据基础

`GET /quiz/attempts` 返回每道题的提交记录，关键字段：

| 字段 | 说明 |
|------|------|
| `created_at` | 提交时间戳（同一会话的题几乎同时提交，差 <2s） |
| `is_correct` | 是否答对 |
| `kp_name` / `stem` | 知识点 / 题干 |
| `question_type` / `difficulty` | 题型 / 分值 |

当前 API **不返回** `resource_id` 或资源标题，因此分组依据为**提交时间聚类**（间隔 ≤60s 视为同一会话）。

## 分组算法

纯前端聚类，不依赖后端改动：

```js
function groupAttempts(attempts) {
    const sessions = [];
    let current = null;
    
    // 按时间降序排列（已在 API 层排好）
    for (const a of attempts) {
        const t = new Date(a.created_at).getTime();
        if (!current || (current.time - t) > 60000) {
            // 新会话：距上一题 >60 秒
            current = {
                time: t,
                dateLabel: formatDate(a.created_at),
                items: [],
            };
            sessions.push(current);
        }
        current.items.push(a);
        current.time = t; // 更新为该会话最早的时间
    }
    
    return sessions;
}
```

阈值 60 秒：正常测验所有题几乎同时提交（差 <2s），跨会话至少间隔几十秒（用户需切换页面再回来），60s 足够安全。

## 实施范围

- **仅修改** `frontend/evaluate.html` 中 `loadHistory()` 函数和新增 CSS
- 不涉及后端 API 改动
- 现有模态窗 `showAttemptDetail()` 复用，不修改
- kp_id 筛选功能保留——筛选后只显示包含该 kp 的会话

## 优势

| 对比 | 现状（平铺） | 升级后（分组） |
|------|------------|-------------|
| 一次 10 题测验 | 10 行 | 1 张卡片 |
| 5 次测验历史 | 50 行散落 | 5 张卡片有序 |
| 找某次测验 | 靠记忆时间翻找 | 按日期卡片一眼定位 |
| 整体正确率感知 | 无 | 每个卡片直接显示 X/Y |
| 单题详情 | 点击行 | 展开卡片后点击行 |
