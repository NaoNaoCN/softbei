# 学习记录（Learning Records）页面优化方案

## 1. 现状分析

### 1.1 当前实现

`pathway.html` 的"学习记录"Tab 当前仅做了最简单的平铺渲染：

```js
// 取 50 条记录，无分组、无筛选、无翻页
const records = await getLearningRecords(userId, { limit: 50 }) || [];

// 平铺成卡片列表
list.innerHTML = records.map(r => `
    <div class="record-item">
        <div class="record-info">
            <div class="record-icon">${r.action === 'complete' ? '✅' : '▶️'}</div>
            <div>
                <div class="record-action">${r.action === 'complete' ? '完成学习' : '开始学习'}</div>
                <div class="record-target">${r.kp_name || r.kp_id || ''}</div>
            </div>
        </div>
        <div class="record-time">${r.recorded_at ? new Date(r.recorded_at).toLocaleString() : ''}</div>
    </div>
`).join('');
```

顶部 3 个统计卡：总条数、完成数、开始数。

### 1.2 核心问题

| 问题 | 说明 |
|------|------|
| **无日期分组** | 三个月前的记录和今天的记录混在一堆，无法感知学习节奏 |
| **无时间线** | 缺少纵向时间轴，看不出哪天学了多少、什么时间学得最密集 |
| **无筛选/搜索** | 不能按知识点、动作类型、日期范围过滤 |
| **无分页/懒加载** | 硬编码 `limit: 50`，超过 50 条的旧记录永远看不到 |
| **浪费字段** | `duration_seconds`（学习时长）、`resource_id`（关联资源）完全未使用 |
| **动作类型不完整** | 后端有 4 种 action（`view` / `complete` / `quiz` / `stay`），前端只展示 2 种 |
| **CSS 未更新** | 仍沿用旧设计的 `#6B7280` / `#E5E7EB` 灰色系，未迁移到 styles-v4 暖沙色系统 |
| **无上下文** | 单条记录缺乏与资源、知识点的联动，不能从记录跳转到对应资源 |

### 1.3 可用数据（后端已就绪）

`LearningRecordOut` 返回的完整字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | int | 记录主键 |
| `user_id` | int | 用户 ID |
| `resource_id` | int? | 关联的资源 ID，可跳转到资源库 |
| `kp_id` | str? | 知识点 ID，可跳转到知识图谱 |
| `kp_name` | str? | 知识点名称（JOIN 查出的） |
| `action` | str | `view` / `complete` / `quiz` / `stay` |
| `duration_seconds` | int? | 学习时长（秒），用于展示专注时长 |
| `recorded_at` | datetime | 记录时间，用于时间轴排序和分组 |

## 2. 优化方案

### 2.1 方案对比

| 维度 | 方案 A：增量优化 | 方案 B：时间轴重构（推荐） |
|------|-----------------|--------------------------|
| 改动量 | 小（30 行 JS + 30 行 CSS） | 中（~150 行 JS + ~100 行 CSS） |
| 视觉效果 | 略好于现在 | 质的飞跃 |
| 交互体验 | 仍以列表为主 | 时间轴 + 分组 + 筛选 |
| 可扩展性 | 差 | 好 |
| 推荐场景 | 快速修补 | 作为正式功能 |

### 2.2 推荐方案 B：时间轴重构

**设计理念**：将学习记录从一个"数据堆"转变为一个"学习日记"——学生能直观看到自己的学习旅程，哪天学了什么、学了多久、哪些知识点反复在啃。

### 3.2 组件拆解

#### 3.2.1 统计概览（4 卡）

| 卡片 | 数据来源 | 计算方式 |
|------|---------|---------|
| 本周学习天数 | `recorded_at` | 本周去重日期数 |
| 累计学习时长 | `duration_seconds` | `sum / 3600`，显示为 `X.X h` |
| 知识点覆盖 | `kp_id` | 去重 `kp_id` 个数 |
| 测验正确率 | 需调用 `QuizAttempt` 数据 | `correct / total * 100`（本周） |

> 注：测验正确率需要用 `getQuizAttempts` 或新增聚合接口。若接口成本大，可降级为"本周记录数"。

#### 3.2.2 筛选栏

- **知识点下拉**：从已有记录中提取 `kp_name` 列表（去重），`<select>` + 搜索
- **动作类型**：radio/chip 组：全部 / 完成 / 测验 / 浏览 / 挂机
- **时间范围**：本周 / 本月 / 近三月 / 全部
- **关键词搜索**：`<input>` 实时过滤 `kp_name`

所有筛选器在前端对已加载数据做 `filter()`，不需要额外 API 调用。

#### 3.2.3 月度热力（CSS Grid 复用）

直接复用 `index.html` 的热力格子模式，展示当月每天的学习时长分布。行为保持一致：月份左右翻页 + 颜色深浅表示时长 + 悬停 tooltip。

#### 3.2.4 时间轴（核心组件）

**分组逻辑**：

```
dataGroups = [
  { label: '今天', records: [...] },
  { label: '昨天', records: [...] },
  { label: '本周', records: [...] },
  { label: '上周', records: [...] },
  { label: '本月', records: [...], collapsed: true },
  { label: '更早', records: [...], collapsed: true },
]
```

- "今天"和"昨天"默认展开
- "本周"默认展开
- "本月"和"更早"默认折叠，点击展开（`details` / `summary` 或手动 toggle）
- 每组内按时间倒序排列

**单条记录卡片**：

```
● ─ ─  时间  ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─  时长  ─ ─ │
  ●  14:30  完成学习 · 数据结构-二叉树         32 min      │
  │                                                         │
  │  (左侧竖线连接同一组内的记录)                             │
```

- 左侧：时间轴竖线（`border-left`）+ 彩色圆点
- 圆点颜色按动作类型区分：
  - `complete` → `--accent` (#C77B3C)
  - `quiz` → `--success` (#6E9466)
  - `view` → `--text-4` (#B5A590)
  - `stay` → `--text-4` 更浅
- 中间：知识点名称（可点击跳转到知识图谱对应节点详情）+ 动作标签
- 右侧：学习时长（`duration_seconds` → `X min`），无时长则显示 `—`

**交互**：

- 点击知识点名称 → 切换到图谱浏览 Tab 并定位该节点（或通过 URL 参数跳转）
- 点击资源 → 跳转到资源库对应资源详情
- 分组折叠/展开（可全部展开/全部折叠）

### 3.5 JS 架构

```
loadRecords()
├── fetchData(page)           → API 调用 + 累积数据
├── computeStats(allRecords)  → 统计概览 4 卡
├── applyFilters(allRecords)  → 筛选 + 搜索
│   └── renderTimeline(filteredRecords)
│       ├── groupByDate()     → 日期分组
│       ├── renderGroup(g)    → 渲染一组
│       └── renderItem(r)     → 渲染单条
└── renderHeatmap(allRecords) → CSS 热力（可选）
```

### 3.6 向后兼容与降低风险

- `loadRecords()` 函数名称不变，外部调用（`switchTab` → `loadRecords`）无需改动
- 统计卡片 HTML 结构不变，仅增加第 4 个卡片
- 旧 CSS 类名 `.record-item` / `.record-info` / `.record-time` 弃用，新类名不冲突
- 分页默认 30 条，首次加载与旧版体验接近
- 热力格子为纯 CSS 实现，不依赖 ECharts

## 4. 实施计划

### Step 1：CSS 重构（20 min）
- 替换 `.records-stats` / `.record-item` 等旧样式为 styles-v4 适配的新样式
- 新增 `.tl-group` / `.tl-item` / `.tl-dot` 等时间轴样式
- 新增筛选栏样式

### Step 2：统计概览升级（15 min）
- 4 卡改为：本周学习天数 / 累计时长 / 知识点覆盖 / 本周记录数（或测验正确率）
- 计算逻辑在 `computeStats()` 中实现

### Step 3：时间轴渲染（30 min）
- 实现 `groupByDate()` 日期分组函数
- 实现 `renderTimeline()` 替换当前 `records.map().join()` 平铺
- 分组折叠/展开交互

### Step 4：筛选栏（15 min）
- HTML 添加筛选栏（知识点下拉、动作类型 chips、时间范围、搜索框）
- `applyFilters()` 逻辑

### Step 5：月度热力（15 min）
- 复用 index.html 的热力格子 JS + CSS
- 以 `recorded_at` 聚合每日学习时长

### Step 6：分页加载（10 min）
- `limit: 30` + `skip` 参数
- 底部"加载更多"按钮
