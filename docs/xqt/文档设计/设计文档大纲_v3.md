### 写作风格与排版规范（v3.2 新增 · 落实 YC 批注 #0/#4/#5/#6/#7/#8）

> 本节对应 `docs/xqt/文档设计/项目设计文档_评审批注_2026.06.27.md` 中评委指出的 6 条写作风格类批注。所有正式设计文档撰写人 / AI 辅助工具必须遵守。

#### 1. 每节「四段式 + 图表点缀」结构（落实批注 #0、#4、#6、#7）

每节内容按以下顺序组织，**文字是主体，图表是点缀**：

```
1) 场景 / 痛点  — 1 段（教育场景中真实存在的问题，引用评委关心的真实场景）
2) 设计思路   — 1 段（我们为什么这样设计，受什么启发 / 与现有工作的差异）
3) 技术方案 / 关键决策 — 1-2 段（怎么落地的、为什么选 A 不选 B、关键取舍）
4) 价值与效果  — 1 段（带来了什么、量化或定性指标、对用户/评委的可见价值）
5) 表格 / 列表 / 图（点缀，不再是主体）
```

**反例（评委批评的"开发文档"风格）**：节标题 + 短句列表 + 表格

**正例**（评委期望的"对外介绍"风格）：节标题 + 4 段叙述 + 1 张表/图

#### 2. 关键术语首次出现时给一句话定义

不要假定评委熟悉所有术语。**首次出现**时必须给一句话定义：

- MoSCoW 优先级矩阵 → 一种将需求分为 Must / Should / Could / Won't 四档的优先级排序方法
- RRF → Reciprocal Rank Fusion，倒数排名融合，用于合并多路检索结果
- HNSW → Hierarchical Navigable Small World，pgvector 使用的近似最近邻索引
- A3 赛题 → 中国软件杯的"个性化资源生成与学习多智能体"赛题

#### 3. 表格前后各加一段叙述（落实批注 #2）

- 表前：1 段说明"本表要回答的问题 / 选取的对比维度"
- 表后：1-2 句话**结论性解读**（"由表可见，X 类需求占比 …%；本系统在 Y 维度上具有相对优势"）

#### 4. 图表必须有「图 X-Y 标题」（落实批注 #5）

- 编号规则：**图 X-Y**（X 为章号、Y 为章内序号），与答辩 PPT 的 FIGURE 03 / FIGURE 10 编号口径保持一致
- 标题格式：「**图 3-1  四层解耦总体架构**」
- 图下补 1-2 句话：**该图要回答的问题**（不要让评委自己悟）

#### 5. 不使用 emoji（落实批注 #8）

- **禁用**：`✅ ❌ 👍 💡 ✓ ✗ ⭐ 🚀` 等所有 emoji 与勾叉符号
- **替换为中文**：「是 / 否 / 满足 / 未满足 / 通过 / 不通过」
- 例外：系统提示词（`configs/prompts.yaml`）中 LLM 使用的 token（如 `[n]` 引用编号）在文档中按其原始形式记录，但**叙述中不出现 emoji**

#### 6. 1.5 文档组织结构改为「3 段文字 + 1 张简图」（落实批注 #4）

- 段一：六板块叙事主线（是什么 → 为什么 → 怎么做 → 怎么样 → 凭什么 → 总结）
- 段二：按读者身份推荐阅读路径（评委 / 教师 / 开发者 / 学生）

# 第三部分  作品设计与实现（约 55-65 页，文档主体）

## 3.1 总体设计

### 3.1.1 设计目标与原则
- 目标：单课程垂直工具 → 可扩展的学习生态底座
- 原则：层间单向依赖 / 每层只解决一个问题 / 配置外置 / 可观测

### 3.1.2 四层解耦总体架构
> 答辩 PPT 口径：**展示层 / 智能体路由总线 / 智能体功能层 / 基础能力层**，层间单向依赖、每层只解决一个问题。

- **架构总览图**（四层，从上到下）
- **设计动机**
  - 展示层：只管 UI 与交互，不感知 Agent
  - 智能体路由总线：只管调度与状态，不感知具体业务
  - 智能体功能层：只管按资源类型生产内容
  - 基础能力层：只管为上层提供可复用的引擎能力（LLM / Embedding / RAG / KG / 视频检索 / 工具集）

### 3.1.3 技术栈选型
> 答辩 PPT 核心数字：**20+ 数据表 · 12 智能体 · 7 资源类型 · 4 LLM Provider 适配器**

- 后端：FastAPI（async，高并发）+ Uvicorn + Pydantic v2
- Agent 编排：**LangGraph**（智能体路由总线 / 条件路由）
- 数据层：PostgreSQL + **pgvector**（HNSW in-DB 检索）+ SQLAlchemy 2.0 async + Alembic
- 主力大模型：**通义千问 Qwen3.6-Plus**（`qwen3.6-plus-2026-04-02`，DashScope，支持 `enable_thinking` 高质量/低延迟两档）
- 多模型适配：**讯飞星火 Spark**（`generalv3.5`）备选 + DeepSeek / OpenAI，统一 OpenAI 兼容接口
- Embedding：DashScope `text-embedding-v4`（1024 维）
- 前端：原生 HTML / CSS / JS，**Aurora UI 主题**，轻量无框架依赖

### 3.3.5 五层递进防幻觉架构

> 防幻觉是教育场景的架构核心约束，不是选配功能。本系统采用从检索前到生成后全覆盖的五层递进防护，对应代码仓库 `docs/xqt/rag/防幻觉机制.md`。
> **答辩 PPT 命名**（与代码一致）：第一层 检索前 → 第二层 检索中 → 第三层 生成中 → 第四层 生成后 → 第五层 全流程。

#### 3.3.5.1 防幻觉问题分析
- 三类幻觉风险及危害
  - 事实捏造：编造不存在的公式、定理、算法步骤
  - 概念混淆：将概念 A 的定义套到概念 B 上
  - 来源不明：声称"根据教材……"但教材根本没有该内容
- LLM 作为「语言模型」而非「知识模型」的根本矛盾
- 教育场景对准确性的底线要求
- 五层递进总架构图（基于项目防幻觉机制流程图重绘）

#### 3.3.5.2 第一层 · 检索前（EX-ANTE）— Query Rewrite 查询改写
> 作用时机：向量检索之前
> 关键文件：`backend/agents/utils.py` `_rewrite_query()` `_expand_queries()`
- 策略 A：对话去上下文化（指代消解，最近 6 轮窗口）
- 策略 B：学生画像感知改写（偏向薄弱知识点 / 学习目标）
- 策略 C：多角度查询扩展（概念定义、原理推导、应用示例、常见误区、跨概念关联）+ RRF 融合
- 容错设计：每次改写失败都有 `_build_fallback_query()` 回退，不阻断检索流程

#### 3.3.5.3 第二层 · 检索中（RETRIEVAL）— 混合检索 + 父块回填
> 作用时机：LLM 生成之前
> 关键文件：`backend/rag/retriever.py`
- 混合检索：DashScope text-embedding-v4 语义路 + jieba 关键词路（PostgreSQL `ts_rank`）
- pgvector HNSW **in-DB 检索**（`hnsw.ef_search` 可调）
- RRF 融合排序
- 相似度阈值过滤（默认 `score_threshold=0.5`）
- 关键词重叠 re-rank（语义相似但术语不匹配的 chunk 降级）
- 父-子块回填（parent-child chunking，子块 500 字精准检索 + 父块 2000 字完整上下文）
- 多样感知排序（section round-robin，避免 Top-k 同源）
- Citation 编号安全提示
- 用户级数据隔离

#### 3.3.5.4 第三层 · 生成中（IN-PROCESS）— NEVER / IMPORTANT 分级禁令
> 作用时机：LLM 生成过程中
> 关键文件：`configs/prompts.yaml`
- NEVER 绝对禁止条款（编造事实、凭记忆补充、跳过空引用声明）
- IMPORTANT 必须做到条款（引用追溯、覆盖声明、画像适配）
- Pre-generation Check 内心自查清单（不输出，仅约束生成路径）
- `[n]` 引用标注规范 + 「补充」（系统提示词中 LLM 使用的自我知识前缀，文档叙述中以「补充」二字表示，不使用 emoji）
- `role:"system"` + 低温度（0.1-0.4）确保高遵循度

#### 3.3.5.5 第四层 · 生成后（POST-HOC）— SafetyAgent 独立审核
> 作用时机：LLM 生成完成之后
> 关键文件：`backend/agents/safety_agent.py`
- 4 项审核清单
  - 事实核查：声明是否能在 `retrieved_docs` 中找到依据
  - 引用验证：每个 `[n]` 是否对应真实片段
  - 误导检测：是否存在"似是而非"的表述
  - 学习场景适配：是否符合用户画像与目标层次
- "只审不修"原则（保留原始 `draft_content`，问题写入 metadata）
- fail-open 策略（审核失败保守通过，避免阻塞主流程）
- temperature=0.1 确定性输出
- 独立 LLM 角色与提示词（与生成 Agent 解耦，避免"自己审自己"）

#### 3.3.5.6 第五层 · 全流程（CODE-LEVEL）— 硬约束 + LLM-as-Judge
> 作用时机：贯穿全流程
> 关键文件：`recommend_agent.py` `backend/evaluation/*` `health_check.py`
- 硬约束校验
  - `recommend_agent`：DB 强制过滤不存在的 `kp_id`，从源头拒绝幻觉知识点
  - `safe_json_loads`：5 策略递进式 JSON 解析（直解 → 修复引号 → 修复转义 → 提取代码块 → 正则兜底）
- 持续质量监控
  - `judge.py`：4 维度 LLM-as-Judge（Faithfulness / Completeness / Citation Accuracy / Hallucination）
  - `golden_dataset.py`：15 条人工标注查询的端到端回归测试，防退化
  - `health_check.py`：无 LLM 代理指标监控（向量库连通、索引统计），<5ms
  - 多 LLM 交叉验证（cross_validation）

#### 3.3.5.7 防幻觉效果度量
- 各层贡献度分解（消融实验：逐层关闭后幻觉率/引用准确率变化）
- 关键指标
  - 幻觉率（Hallucination Rate）

- 黄金集回归对比（优化前 vs 优化后）

# 第五部分  作品创新性说明（约 6-8 页）

> 答辩 PPT 三大核心创新：① 教材驱动的 RAG 知识库引擎 · ② 智能体路由总线与模块化协同 · ③ 五层知识图谱自动构建

## 5.1 创新点一（PPT）：教材驱动的 RAG 知识库引擎（**5 层防幻觉闸门**）
- 5.1.1 问题陈述：通用 LLM 在垂直课程上幻觉严重
- 5.1.2 技术方案：以教材为知识权威来源，5 层防幻觉保障生成内容可信
- 5.1.3 检索流水线（4 步）
  1. 智能文档解析：PDF / DOCX / MD → 结构化 Markdown（pymupdf4llm 保留标题/表格/层级）
  2. 父子切割策略：子块 500 字精准检索 · 父块 2000 字完整上下文
  3. 混合检索 + RRF 融合：pgvector HNSW 向量路 · jieba + ts_rank 关键词路 · round-robin 去重
  4. Query Rewrite：指代消解 · 画像感知改写 · 多查询扩展
- 5.1.4 五层防幻觉闸门（**第一层 ~ 第五层**，与 §3.3.5 一一对应）
  - 第一层 检索前：Query Rewrite
  - 第二层 检索中：混合检索 + 父块回填
  - 第三层 生成中：NEVER / IMPORTANT 分级禁令
  - 第四层 生成后：SafetyAgent 独立审核
  - 第五层 全流程：硬约束 + LLM-as-Judge
- 5.1.5 四层评估体系（L1 健康 / L2 检索 / L3 生成 / L4 黄金）
- 5.1.6 实测效果（黄金集 P@5、引用准确率 90%+）

## 5.2 创新点四（**文档独有 · PPT 不讲**）：垂直领域模型基座引擎
> 落实批注 #9：基座引擎 PPT 不展开，但作为文档独有第 4 创新点保留，体现文档深度。**答辩时仅在被追问"还有别的吗"时提及，不主动展开 5 分钟。**

- 5.2.1 问题陈述：多模型多工具散落业务代码，新 Agent 接入成本高、配置耦合、难以横向对比
- 5.2.2 设计思路：将 LLM / Embedding / RAG / 工具调用 打包为统一基座，对上层 Agent 完全透明
- 5.2.3 技术方案
  - **配置管理子系统**（YAML + 环境变量双层 + 模块级单例 + 多 Provider 抽象）
  - **LLM 接入子系统**（4 个 Provider 适配器：spark / deepseek / qwen / openai + 统一 OpenAI 兼容接口 + 指数退避重试 + SSE 流式）
  - **Embedding 子系统**（DashScope `text-embedding-v4` · 1024 维 · 批量化并发）
  - **RAG 子系统**（loader / indexer / retriever 三段式 + 黄金集回归）
  - **工具与外部能力**（B 站视频检索 / 教学动画沙箱 / 知识图谱查询）
- 5.2.4 核心亮点
  - **配置外置**：`configs/config.yaml` + `configs/prompts.yaml` 双文件，零代码切换 Provider
  - **提示词外置**：所有 Agent 提示词外部化，版本可追溯、A/B 可对比
  - **异常自动降级**：provider 级降级 + 深度思考双档（`enable_thinking`）
  - **与上层解耦**：Agent 不感知底层 Provider，新增 LLM 只需新增 1 个 adapter
- 5.2.5 价值量化
  - 新增一个 LLM Provider：**1 天**（旧范式需 3-5 天散落在业务代码）
  - 新增一个 Agent：**0.5 天**（基于基座接口 + 提示词模板）
  - 提示词 A/B 测试：**小时级**（提示词外部化 + 黄金集回归）
- 5.2.6 与 3 个 PPT 创新点的关系
  - 创新点一（RAG 引擎）的实现离不开本基座（Embedding / Retriever 都属基座）
  - 创新点二（Agent 总线）的状态机调度也借助本基座（统一 LLM 入口 / 异常降级）
  - 创新点三（KG 自动构建）依赖本基座的 LLM 节点提取与边推理能力
  - **结论**：本基座是三大 PPT 创新点的"使能层"，是文档深度的最佳体现
- 5.2.7 与 §3.2 基础能力层的对应：本节是 §3.2 的"创新性视角重述"，不重复技术细节

## 5.3 创新点二（PPT）：智能体路由总线与模块化协同（**12 Agent · 3 模块 · 4 设计亮点**）
- 5.3.1 问题陈述：多智能体分散调用、状态难管理
- 5.3.2 技术方案：基于 LangGraph 构建自有调度中枢，按职责分模块组织 Agent
- 5.3.3 **4 项设计亮点**
  - 共享状态机制：统一数据模型在节点间传递，避免序列化反序列化
  - 条件路由：精确分发到单一生成 Agent，不并行扇出
  - DB Session 注入：`configurable` 异步访问，避免全局变量
  - 画像驱动个性化：每次推理加载最新画像快照
- 5.3.4 **3 模块组织**
  - 入口与画像模块（profile / planner / clarify）
  - 内容生成模块（doc / mindmap / quiz / code / summary / anim）
  - 出口与反馈模块（kg / safety / recommend）
- 5.3.5 价值：新增 Agent 标准化接入流程、状态可观测性、与五层防幻觉架构天然解耦（SafetyAgent 独立审核避免"自己审自己"）

## 5.4 创新点三（PPT）：五层知识图谱自动构建（**零人工标注 · 增量更新**）
- 5.4.1 问题陈述：课程知识体系人工维护成本高、跨课程知识难以关联
- 5.4.2 技术方案：从教材 PDF 到结构化知识网络 — 全自动、零人工标注
- 5.4.3 5 层节点结构（与答辩 PPT 一致）
  - Course → Chapter → KnowledgePoint → SubPoint → Concept
- 5.4.4 3 类关系边
  - prerequisite / contains / related_to
- 5.4.5 5 步构建流水线
  1. TOC 骨架提取：PDF 目录自动识别 → Chapter / KnowledgePoint
  2. LLM 节点提取：章节文本提取 SubPoint / Concept 细粒度节点
  3. 动态类型映射：已覆盖层级不重复 · LLM 只补充更深节点
  4. 边关系推理：prerequisite / contains / related_to 批量推理
  5. 增量更新：新文档仅处理增量 · 不破坏已有图谱
- 5.4.6 应用场景
  - 学习路径规划：拓扑排序最优学习顺序
  - 推荐引擎：沿关联边推荐"下一步应学"
  - 学习计划表：以知识图谱为内容基准构建学习计划表
- 5.4.7 价值：复用现有 PDF 教材即可一键成图、跨课程横向扩展
