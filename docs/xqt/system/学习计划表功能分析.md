# 学习计划表功能详细分析

## 概述

学习计划表是学习规划页面的第三个子页面（Tab），功能是将学生的学习路径和知识薄弱点转化为一个有明确日期、时间安排的每日学习计划，支持自动排程、资源关联、邮件发送。

**入口：** 学习规划页面 → "学习计划" Tab（或 URL `?tab=study-plan`）

## 2. 生成流程（5 步管道）

```
用户点击"开始生成"
  │
  ▼
┌─────────────────────────────────────────────────────┐
│ Step 1: collector  — 收集候选知识点                   │
│                                                      │
│  来源：                                              │
│  - 用户的学习路径（LearningPath → LearningPathItem）  │
│  - 用户画像中的知识薄弱点（StudentProfile.weak_kps）  │
│                                                      │
│  去重逻辑：先收集学习路径中的 KP，再补入画像薄弱点     │
│  中未在路径中出现的 KP                                │
│                                                      │
│  输出：CandidateItem[] （kp_id, kp_name, source）    │
└──────────────┬──────────────────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────────────────┐
│ Step 2: sequencer — LLM 排序（核心智能环节）          │
│                                                      │
│  调用 LLM，使用 prompt: agents.study_plan.sequence   │
│  输入：候选 KP 列表 + 用户画像摘要                    │
│                                                      │
│  LLM 任务：                                          │
│  - 按前置依赖关系排序                                │
│  - 薄弱点排在前面，给更充裕的时间                     │
│  - 已掌握知识点排在后面                              │
│  - 为每个 KP 估计学习分钟数（20-180 分钟）            │
│  - 输出 JSON 数组，无反引号包裹                       │
│                                                      │
│  防幻觉：验证所有 kp_id 都在候选列表内                │
│  降级策略：LLM 失败时回退到确定性的排序（薄弱点优先）  │
│                                                      │
│  输出：SequencedItem[] (kp_id, estimated_minutes,    │
│         priority, tip)                               │
└──────────────┬──────────────────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────────────────┐
│ Step 3: scheduler — 日历装箱（确定性算法，非LLM）     │
│                                                      │
│  贪心装箱算法：                                      │
│  1. 按 sequenced 顺序遍历 KP                          │
│  2. 累计当天已安排的 estimated_minutes                │
│  3. 超过 daily_time_minutes 预算 → 滚动到下一天       │
│  4. 单个 KP 不拆分到多天                              │
│  5. 若用户指定了 days，重算每日预算 = ceil(total/days)│
│  6. 若配置了 start_hour，计算每天的 start_time/end_time│
│                                                      │
│  输出：ScheduledItem[] (kp_id, scheduled_date,        │
│         start_time, end_time, order_index)            │
└──────────────┬──────────────────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────────────────┐
│ Step 4: resource_linker — 资源匹配                   │
│                                                      │
│  批量查询 ResourceMeta 表：                           │
│  - 每个 KP 有哪些已生成的资源（doc/mindmap/quiz 等）  │
│  - 哪些目标资源类型尚未生成                           │
│                                                      │
│  输出：resource_ids[]（已匹配）,                      │
│        missing_resource_types[]（待生成）             │
└──────────────┬──────────────────────────────────────┘
               │
               ▼
┌─────────────────────────────────────────────────────┐
│ Step 5: persist — 写入数据库                         │
│                                                      │
│  单事务写入：                                        │
│  - INSERT INTO study_plan （计划主记录）               │
│  - INSERT INTO study_plan_item × N （每天每KP一条）   │
│                                                      │
│  输出：StudyPlanOut（完整计划 + 所有子项）            │
└─────────────────────────────────────────────────────┘
```

### 2.1 配置参数

`configs/config.yaml → study_plan`：

| 参数 | 值 | 说明 |
|------|-----|------|
| `default_daily_minutes` | 60 | 用户画像无每日时长时的回退值 |
| `default_start_hour` | "19:00" | 每日默认开始时间 |
| `min_kp_minutes` | 20 | 单个 KP 最少学习分钟 |
| `max_kp_minutes` | 180 | 单个 KP 最多学习分钟 |
| `default_kp_minutes` | 45 | LLM 未估计时的默认值 |
| `target_resource_types` | ["doc", "mindmap", "quiz"] | 目标资源类型 |
| `sequence.temperature` | 0.3 | LLM 排序温度 |

## 3. 邮件发送机制

### 3.1 触发方式

**纯手动触发。** 用户在计划卡片上点击"发送到邮箱"按钮 → 调用 `POST /study-plan/email` → 后台异步发送 → 前端提示"发送成功"。

系统**没有**定时任务或 cron 自动发送学习计划邮件。

### 3.2 发送流程

```
前端点击"发送到邮箱"
  │
  ▼
POST /study-plan/email?plan_id=xxx&user_id=xxx   (main.py:489)
  │
  ├─ 验证用户存在且 email 字段不为空
  ├─ 查询 StudyPlan + StudyPlanItem
  ├─ 构建 plan_data 字典（按日期分组，中文星期标签）
  │
  └─ asyncio.create_task(email_sender.send_study_plan(...))
       │  ← 立即返回给前端（不等待发送完成）
       │
       ▼
  EmailSender.send_study_plan()                     (sender.py:114)
       │
       ├─ 渲染 Jinja2 模板: study_plan.html
       ├─ 主题: "[学习系统] 您的学习计划表 · {计划标题}"
       ├─ 收件人: user.email
       │
       └─ EmailSender.send()                        (sender.py:46)
            │
            ├─ SMTP 已配置 → aiosmtplib.send() 异步发送
            │
            └─ SMTP 未配置 → _save_to_file()
                 └─ 保存 HTML 到 debug_emails/ 目录
```

### 3.3 SMTP 配置

`configs/config.yaml → email`（全部通过环境变量注入，无硬编码值）：

```yaml
email:
  smtp_host: "${SMTP_HOST}"
  smtp_port: "${SMTP_PORT}"           # 通常 465 (SSL) 或 587 (STARTTLS)
  smtp_username: "${SMTP_USERNAME}"
  smtp_password: "${SMTP_PASSWORD}"
  smtp_from: "${SMTP_FROM}"
  smtp_use_tls: "${SMTP_USE_TLS}"
  max_retries: "${SMTP_MAX_RETRIES}"  # 默认 3
```

**当前状态：** 环境变量中是否有值决定了实际行为：
- **有配置** → SMTP 真实发送
- **无配置** → 降级为写入 `debug_emails/study_plan_*.html` 本地文件

### 3.4 发送内容

邮件使用 `backend/templates/email/study_plan.html` 模板，内容包括：

| 区域 | 内容 |
|------|------|
| 头部 | 渐变色（琥珀色系）banner，"学习计划表"标题 + 计划名称 |
| 摘要行 | 开始日期、结束日期、每日学习预算、学习目标 |
| 每日分组 | 按日期分组，每天显示：(1) 日期+周几+任务数 (2) 时间段/序号 (3) 知识点名称+完成状态 (4) 备注 (5) 预估时长 (6) 资源数量+缺失类型 |
| CTA 按钮 | "查看完整计划" → `http://localhost:8000/app/schedule.html` |
| 页脚 | "个性化资源生成与学习多智能体系统" |

### 3.5 重试策略

Tenacity `@retry` 装饰器：最多 `max_retries` 次（默认 3），指数退避 2s-30s，仅在 `(SMTPException, ConnectionError, TimeoutError)` 上重试。

## 5. 计划项的操作

### 5.1 标记完成

点击计划项的 checkbox → `PUT /study-plans/{plan_id}/items/{item_id}` → 更新 `is_completed = true` → 同时写入 `learning_record`（action="complete"）→ 前端重新渲染进度条。

### 5.2 生成缺失资源

点击计划项上的"生成资源"按钮 → `POST /study-plans/{plan_id}/items/{item_id}/generate-resource` → 创建批量生成任务 → 后台异步调用 Agent 生成资源 → 生成完成后自动回填 `resource_ids` 和清空 `missing_resource_types`。

### 5.3 删除计划

点击"删除计划" → 确认弹窗 → `DELETE /study-plans/{plan_id}` → 级联删除所有 item。

## 7. 关键技术决策总结

| 决策 | 内容 | 原因 |
|------|------|------|
| 排序方式 | LLM 排序 + 确定性降级 | LLM 可理解学习依赖关系，降级保证可用性 |
| 排程算法 | 贪心装箱（非 LLM） | 确定性、可预期、可调试 |
| 资源生成 | 按需懒加载，后台异步 | 避免创建计划时等待时间过长 |
| 邮件触发 | 手动按钮，无自动调度 | 用户主动控制，避免无 SMTP 时报错 |
| SMTP 降级 | 降级为本地文件 | 开发/测试环境无需 SMTP 服务 |
| 知识点快照 | kp_name 始终存储 | KG 节点可能被修改，快照保证计划内容稳定 |
| 薄弱点处理 | kp_id 可为空 | 画像薄弱点可能尚未录入 KG |
