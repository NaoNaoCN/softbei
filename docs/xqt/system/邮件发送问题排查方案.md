# 邮件发送问题排查方案

## 现象

- 后端日志显示 `[Email] 发送成功`
- QQ 邮箱收件箱**未收到**邮件
- `debug_emails/` 目录**为空**（说明走了真实的 SMTP 路径，不是降级模式）

## 关键代码路径

```
POST /study-plan/email
  → email_sender.send_study_plan(user.email, username, plan_data)   (sender.py:114)
    → self.send(to, subject, html)                                   (sender.py:46)
      → aiosmtplib.send(msg, hostname=..., port=..., ...)            (sender.py:58)
      → logger.success("[Email] 发送成功")                            (sender.py:68)
```

`enabled` 判断逻辑（`sender.py:34`）：
```python
self._enabled = bool(cfg.smtp_host and cfg.smtp_password)
```

只要 `SMTP_HOST` 和 `SMTP_PASSWORD` 均非空，就启用 SMTP 模式。

## 1. 问题诊断

### 1.1 "发送成功"的真实含义

`logger.success("[Email] 发送成功")` 只表示 `aiosmtplib.send()` **没有抛出异常**，即 SMTP 服务器**接受了**邮件。但这不等于收件方一定会收到：

```
[应用] --SMTP--> [SMTP服务器] --转发---> [收件方邮件服务器] --> [收件箱]
                      ✅                    ？                ？
                 (aiosmtplib 不报错)     (不在控制范围)
```

邮件可能在 SMTP 服务器转发后被：
- 归入**垃圾邮件箱**（最常见）
- 被收件方服务器**静默丢弃**
- 触发反垃圾策略被**延迟投递**（可能几小时到几天）

### 1.2 需要排查的变量

| 排查维度 | 检查方式 |
|----------|----------|
| SMTP 服务商类型 | `.env` 中 `SMTP_HOST` 的值 |
| `SMTP_FROM` 是否与认证用户一致 | `.env` 中对比 `SMTP_USERNAME` 和 `SMTP_FROM` |
| `SMTP_PASSWORD` 是否为授权码 | QQ 邮箱需授权码而非登录密码 |
| QQ 邮箱垃圾箱 | 登录 QQ 邮箱网页版检查垃圾邮件箱 |
| 发件箱是否有记录 | 登录发送方邮箱查看发件箱 |

### 测试二：QQ 邮箱垃圾箱检查

**操作步骤：**
1. 登录 `2902125312@qq.com` 网页版（mail.qq.com）
2. 点击左侧"垃圾箱"
3. 搜索"学习系统"或"学习计划表"
4. 若找到，点击"这不是垃圾邮件"将其移回收件箱

### 测试三：检查发件箱

如果使用的是 QQ 邮箱作为发件方：
1. 登录发件 QQ 邮箱网页版
2. 检查"已发送"文件夹
3. 如果有发送记录，说明 SMTP 层面确实成功
4. 如果没有，说明 SMTP 转发没有被记录（部分 SMTP 服务商不记录 API 发送的邮件）

### 测试四：修改收件人为发件人自己

**目标：** 如果发件人自己能收到，说明是收件方过滤问题。

```python
# 临时修改 main.py:547 行附近

    user.email,         # 正常收件人
    username, plan_data

# 改为：
_asyncio.create_task(email_sender.send_study_plan(

    username, plan_data

```

重启服务，再次点击"发送到邮箱"：
- 发件人自己收到了 → 收件方 QQ 邮箱过滤了
- 发件人自己也没收到 → SMTP 配置本身有问题

### 测试五：发送纯文本空白邮件

**目标：** 排除 HTML 内容被反垃圾过滤的可能。

在 `main.py:500` 附近添加测试端点：

```python
@app.post("/test-email")
async def test_email(db: AsyncSession = Depends(get_session)):
    from backend.email.sender import email_sender
    # 获取一个测试用户
    user = (await db.execute(sa.select(User).limit(1))).scalar_one_or_none()
    if not user or not user.email:
        return {"error": "no user with email"}
    ok = await email_sender.send(user.email, "[测试] 纯文本邮件", "<p>这是一封测试邮件</p>")
    return {"ok": ok, "to": user.email, "from": email_sender._from}
```

重启服务，用浏览器访问 `http://localhost:8000/test-email`，检查收件情况。

### 测试六：QQ 邮箱授权码验证

如果使用 QQ 邮箱 SMTP（`smtp.qq.com`）：

1. 登录 QQ 邮箱网页版 → 设置 → 账户
2. 找到"POP3/IMAP/SMTP 服务"
3. 检查是否已开启"SMTP 服务"
4. 生成的**授权码**（16 位字符）才是 `SMTP_PASSWORD` 的值
5. **QQ 邮箱登录密码不能用于 SMTP 认证**

**验证命令**（在终端执行）：
```bash
python -c "
import asyncio, aiosmtplib
from email.mime.text import MIMEText
from email.mime.multipart import MIMEMultipart

async def test():
    msg = MIMEMultipart('alternative')
    msg['From'] = 'your_email@qq.com'
    msg['To'] = '2902125312@qq.com'
    msg['Subject'] = '手动SMTP测试'
    msg.attach(MIMEText('<p>测试</p>', 'html', 'utf-8'))
    try:
        await aiosmtplib.send(msg, hostname='smtp.qq.com', port=587,
            username='your_email@qq.com', password='你的授权码',
            use_tls=True, timeout=30)
        print('发送成功')
    except Exception as e:
        print(f'发送失败: {e}')

asyncio.run(test())
"
```

### 测试七：增加发送结果诊断日志

**目标：** 在发送流程中增加更多诊断点。

修改 `backend/email/sender.py` 的 `send()` 方法（`sender.py:57-68`），增加更详细的日志：

```python
try:
    logger.info("[Email] 开始发送: to={}, from={}, host={}, port={}, tls={}",
        to, self._from, self._host, self._port, self._use_tls)
    response = await aiosmtplib.send(
        msg,
        hostname=self._host,
        port=self._port,
        username=self._username,
        password=self._password,
        use_tls=self._use_tls,
        timeout=self._timeout,
        local_hostname="localhost",
    )
    logger.success("[Email] 发送成功: to={}, subject={}, smtp_response={}", to, subject, response)
    return True
except Exception as e:
    logger.exception("[Email] 发送失败: to={}, subject={}, error={}", to, subject, e)
    raise
```

`aiosmtplib.send()` 返回的 `response` 是一个 dict，包含 `(code, message)` 元组，记录了 SMTP 服务器的每条响应。这会告诉我们 SMTP 服务器实际返回了什么。

## 3. 常见根因排名

按可能性从高到低：

| 排名 | 原因 | 证据 | 修复 |
|------|------|------|------|
| 1 | **邮件被 QQ 归入垃圾箱** | 日志显示发送成功 | 用户检查垃圾箱，添加到白名单 |
| 2 | **SMTP_PASSWORD 是登录密码而非授权码** | QQ 邮箱需要授权码 | 在 QQ 邮箱设置中生成授权码 |
| 3 | **SMTP_FROM 与 SMTP_USERNAME 不一致** | QQ 邮箱要求 from 必须与认证用户一致 | 确保 `.env` 中两者一致 |
| 4 | **邮件内容触发反垃圾规则** | 包含 `localhost` 链接 | 修改模板中的链接为正式域名或移除 |
| 5 | **SMTP 服务商限制了程序发送** | 部分免费 SMTP 限额很低 | 检查服务商的 API 限额 |

## 4. 建议执行顺序

```
测试一（检查配置） ──→ SMTP配置项正确？
  │                      │
  │ ✅                   │ ❌ → 修正 .env
  ↓                      ↓
测试二（检查垃圾箱）      测试六（验证授权码）
  │                      │
  │ ✅ 在垃圾箱找到      │ ❌ 不在垃圾箱
  ↓                      ↓
操作"不是垃圾邮件"      测试七（增加诊断日志）
                        → 查看 SMTP response
                        → 测试五（发件人自收测试）
```

## 5. 长期改进建议

1. **SMTP 返回码记录**：将 `aiosmtplib.send()` 的返回值记入日志，方便前端排查
2. **邮件模板中避免 `localhost` 链接**：使用可配置的前端地址
3. **Debug 模式与真实模式分离更清晰**：前端应能感知当前是否为 debug 模式，避免用户误以为邮件已发出
4. **增加发送状态回调**：目前 `asyncio.create_task` 异步发送后不等待结果，前端无法知道发送是否真的成功——建议增加一个发送状态查询接口
