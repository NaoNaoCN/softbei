## 1. 系统概述

### 1.1 项目背景

本项目面向高等教育场景，针对传统"一刀切"教学模式无法兼顾学生个体差异的痛点，构建一套基于大模型的个性化资源生成与学习多智能体系统。以"人工智能导论"课程为切入点，通过 11 个 Agent（10 个在 LangGraph 状态图中协同编排 + 1 个独立澄清 Agent）自动为学生生成个性化学习资源。

### 1.2 核心功能模块

| 模块 | 功能描述 |
|------|----------|
| 对话式画像构建 | 多轮对话自动抽取并维护学生八维学习画像 |
| 多智能体资源生成 | 并行生成 doc/mindmap/quiz/code/summary 五种资源 + kg 异步构建 |
| 知识图谱自动构建 | 从课程文档自动提取五层节点结构 |
| 个性化学习路径规划 | 基于知识图谱拓扑排序推荐学习顺序 |
| 学习效果评估 | 答题记录、薄弱点识别、动态推送 |
| RAG 智能检索 | 语义检索课程文档，带引用溯源 |

### 1.3 技术栈

| 层次 | 技术选型 |
|------|----------|
| 前端 | HTML/CSS/JS + ECharts |
| 后端 | FastAPI + SQLAlchemy 2.0 (async) |
| Agent 编排 | LangGraph StateGraph (10-Agent) + 独立 ClarifyAgent |
| LLM | Qwen / 讯飞星火 / DeepSeek / OpenAI（多 Provider） |
| RAG | BGE-M3 + ChromaDB |
| 数据库 | SQLite (dev) / MySQL (prod) |

## 3. 核心数据模型

### 3.1 AgentState

所有 Agent 通过 `AgentState` (Pydantic BaseModel) 共享状态，在 LangGraph 各节点间传递：

```python
class AgentState(BaseModel):
    user_id: str                          # 用户 ID
    session_id: str                       # 会话 ID
    user_message: str                     # 用户当前消息
    profile: Optional[StudentProfileIn]    # 学生画像
    kp_id: Optional[str]                   # 目标知识点 ID
    resource_type: Optional[ResourceType]  # 生成资源类型
    retrieved_docs: list[str]             # RAG 检索结果
    draft_content: Optional[str]          # Agent 生成结果
    final_content: Optional[str]          # 最终输出
    safety_passed: bool = True            # 安全校验标志
    error: Optional[str] = None            # 错误信息
    metadata: dict[str, Any]               # 元数据（推荐资源等）
    kg_doc_id: Optional[str] = None       # KG 构建目标文档 ID
    is_onboarding: bool = False           # 画像初始化阶段
    profile_complete: bool = False        # 画像完整性
    clarify_message: Optional[str] = None  # 追问内容
    num_questions: int = 4               # 测验题目数量
    question_type_counts: dict[str, int] # 题目类型计数
```

## 4. 多智能体设计

### 4.1 Agent 职责表

| Agent | 节点/文件 | 职责 |
|-------|----------|------|
| ProfileAgent | `profile_agent.py` | 从对话中提取/更新学生画像，判断画像完整性，决定路由 |
| PlannerAgent | `planner_agent.py` | 解析用户意图，决定 resource_type 和 kp_id，支持多资源智能推荐 |
| DocAgent | `doc_agent.py` | RAG + LLM 生成 Markdown 知识讲解文档（带 `[n]` 引用溯源） |
| MindmapAgent | `mindmap_agent.py` | RAG + LLM 生成 ECharts tree JSON 思维导图（≤4层，≤6子节点） |
| QuizAgent | `quiz_agent.py` | RAG + LLM 生成多题型（单选/多选/填空）测验，含 save_quiz_items 持久化 |
| CodeAgent | `code_agent.py` | RAG + LLM 生成 Python 代码实操案例（含参考答案） |
| SummaryAgent | `summary_agent.py` | RAG + LLM 生成 300-500 字要点式复习总结（含 LaTeX 公式） |
| KGAgent | `kg_agent.py` | 调用 kg_builder 异步构建知识图谱，绕过安全审查直接进入推荐 |
| SafetyAgent | `safety_agent.py` | 对比 retrieved_docs 审核 draft_content，防止幻觉（保留原文） |
| RecommendAgent | `recommend_agent.py` | 结合画像和知识图谱推荐 3-5 个下一步学习知识点 |
| ClarifyAgent | `clarify_agent.py` | **独立 Agent（不在状态图中）**：处理追问/澄清对话，结合历史与画像生成简短回复 |

### 4.2 协作亮点

**并行生成**：5 个生成 Agent（doc/mindmap/quiz/code/summary）通过 `asyncio.gather` 批量调度，同时运行。

**画像驱动的条件路由**：PlannerAgent 根据学生的认知风格（visual/text/practice）决定资源类型的侧重比例。

**防幻觉机制**：SafetyAgent 对比 RAG 检索结果与生成内容的一致性，标记 `safety_passed` 状态。

**AgentState 共享状态**：所有 Agent 通过 Pydantic BaseModel 共享状态，无需额外通信协议。

### 4.3 八维学习画像体系

| 维度 | 字段名 | 说明 | 更新机制 |
|------|--------|------|----------|
| 专业 | major | 学生所在专业 | 对话提取一次后稳定 |
| 学习目标 | learning_goal | LLM 概括历史提问得到 | 增量追加提问，后台异步重新概括 |
| 认知风格 | cognitive_style | 视觉型/阅读型/动手型 | 对话提取 |
| 每日学习时间 | daily_time_minutes | 分钟数 | 对话提取 |
| 已掌握知识点 | knowledge_mastered | 列表 | 对话增量追加，去重保序 |
| 薄弱知识点 | knowledge_weak | 列表 | 对话增量追加 |
| 易错点 | error_prone | 列表 | 对话增量追加 |
| 当前进度 | current_progress | 自由文本 | 对话提取 |

## 5. LangGraph 状态机

### 5.1 拓扑结构

```
profile_agent
  ├─ (画像不足) → END  ← 追问，本轮结束
  └─ (画像足够) → planner_agent
                ├─ doc_agent ──────────┐
                ├─ mindmap_agent ──────┤
                ├─ quiz_agent ─────────→ safety_agent → recommend_agent → END
                ├─ code_agent ─────────┤
                ├─ summary_agent ──────┘
                └─ kg_agent ──────────→ recommend_agent → END   (绕过 safety)
```

**特殊路由**：
- KG 类型跳过 safety_agent，直接进入 recommend_agent
- Planner 根据 resource_type 扇出到对应生成 Agent
- 资源类型为 kg 且无明确 kp_id 时，Planner 直接路由到 recommend_agent

### 5.2 条件路由函数

```python
def route_after_profile(state: AgentState) -> str:
    """profile_agent 路由：画像不足则追问，否则进入 planner"""
    if state.profile_complete:
        return "planner_agent"
    return END

def route_by_resource_type(state: AgentState) -> str:
    """planner_agent 路由：按 resource_type 扇出"""
    resource_type = state.resource_type
    if resource_type == ResourceType.kg:
        return "kg_agent"
    if resource_type in [ResourceType.doc, ResourceType.mindmap,
                         ResourceType.quiz, ResourceType.code, ResourceType.summary]:
        return f"{resource_type.value}_agent"
    return "recommend_agent"
```

### 5.3 节点定义

| 节点 | 入口条件 | 出口 |
|------|----------|------|
| profile_agent | 入口节点 | route_after_profile → planner_agent 或 END |
| planner_agent | profile_complete=True | route_by_resource_type → 对应生成 Agent 或 recommend_agent |
| doc/mindmap/quiz/code/summary_agent | 由 planner 扇出 | → safety_agent |
| kg_agent | 由 planner 扇出 | → recommend_agent（绕过 safety） |
| safety_agent | 来自 5 个生成 Agent | → recommend_agent |
| recommend_agent | 来自 safety_agent 或 kg_agent | → END |

## 6. RAG 流水线

### 6.1 文档加载 (`backend/rag/loader.py`)

**支持格式**：
- PDF（`PyPDFLoader`）
- DOCX/DOC（`UnstructuredWordDocumentLoader`）
- Markdown（`TextLoader`）
- TXT（`TextLoader`）

**TextChunk 数据结构**：
```python
@dataclass
class TextChunk:
    chunk_id: str
    text: str
    doc_id: str
    source_path: str
    page: Optional[int] = None
    section: Optional[str] = None
```

**核心函数**：
- `load_file(path, doc_id=None)` → `list[TextChunk]`
- `load_directory(dir_path)` → 递归加载
- `split_text(text, chunk_size, overlap)` → 带 overlap 的字符级分块
- `extract_toc(pdf_path)` → 提取 PDF 大纲为 `[{title, page, level}, ...]`

### 6.2 向量索引构建 (`backend/rag/indexer.py`)

- `index_chunks(chunks, batch_size=32)` → 批量嵌入并写入 ChromaDB
- `index_file(file_path)` → 一键加载+索引
- `index_directory(dir_path)` → 递归全量索引
- 并发控制：`asyncio.Semaphore(8)`

### 6.3 语义检索 (`backend/rag/retriever.py`)

- `retrieve(query, n_results=5, score_threshold=0.5)` → 返回 `list[RetrievedChunk]`
- `retrieve_by_kp(kp_name, n_results=8)` → 知识点检索（自动添加"知识点："前缀）
- `format_context(chunks, max_tokens=3000)` → 格式化为带编号引用块：
  ```
  [1] （来源：chapter_01.pdf, 第2页）
  梯度下降是一种...
  ```

**防幻觉引用格式**：
```python
def format_context(chunks: list[RetrievedChunk], max_tokens=3000) -> str:
    """格式化为带编号的引用块，用于生成时溯源"""
    result = []
    total_tokens = 0
    for i, chunk in enumerate(chunks, 1):
        source = chunk.source_path.split("/")[-1]
        page_info = f", 第{chunk.page}页" if chunk.page else ""
        header = f"[{i}] （来源：{source}{page_info}）"
        result.append(f"{header}\n{chunk.text}")
    return "\n\n".join(result)
```

## 8. 核心服务层

### 8.1 画像服务 (`backend/services/profile.py`)

**核心函数**：
- `get_profile(user_id, db)` → 获取学生画像
- `create_or_update_profile(user_id, data, db)` → 创建/更新 + 写 ProfileHistory 快照
- `merge_chat_updates(user_id, updates, db, user_message)` → **增量合并**字段，追加提问到 `goal_questions`，触发异步 LLM 目标概括
- `refresh_learning_goal(user_id, questions)` → 后台任务：调用 LLM 概括 `goal_questions` → 回写 `learning_goal`

**增量更新机制**：
```python
async def merge_chat_updates(user_id: str, updates: dict, db, user_message: str):
    """列表型字段采用追加而非覆盖，自动去重保序"""
    profile = await get_profile(user_id, db)
    for field in ["knowledge_mastered", "knowledge_weak", "error_prone"]:
        if field in updates and updates[field]:
            old_list = getattr(profile, field, []) or []
            new_items = updates[field]
            # 追加并去重（保持顺序）
            merged = list(dict.fromkeys(old_list + new_items))
            setattr(profile, field, merged)
    # 追加用户提问到 goal_questions
    profile.goal_questions.append(user_message)
    await db.flush()
    # 异步触发 learning_goal 重新概括
    _schedule_refresh_learning_goal(user_id)
```

### 8.2 资源生成服务 (`backend/services/generation.py`)

**主流程**：`run_generation(task_id, user_id, session_id, request)`
1. 初始化 `AgentState`
2. 调用 `get_graph().ainvoke()` 执行 LangGraph 状态机
3. 成功：持久化 content 到 `ResourceMeta`；Quiz 类型同时写入 `QuizItem` 表
4. 失败：更新 `GenerationTask.error_message`
5. 自动创建学习路径（如用户尚无路径）

**批量生成**：`run_batch_generation(batch_id, user_id, session_id, task_configs)` 通过 `asyncio.gather` 并行执行多个生成任务。

### 8.3 知识图谱构建服务 (`backend/services/kg_builder.py`)

**入口函数**：`build_kg(doc_id, db, on_progress, user_id)`

**构建流程**：
```
ChromaDB 文本块 → TOC 目录解析 → 按章节聚合 → LLM 节点提取
 → LLM 关系推断 → 节点/边写入 DB
```

**五层节点结构**：`Course → Chapter → KnowledgePoint → SubPoint → Concept`

**两种路径**：
1. **TOC 路径**（PDF 有≥3 个大纲项）：构建 Course/Chapter 骨架 → 按章节聚合文本 → LLM 补充细粒度节点
2. **Fallback 路径**（无目录）：按页聚合文本（约 12000 chars/batch）→ 全量 LLM 提取

**并发控制**：
```python
_LLM_SEMAPHORE = asyncio.Semaphore(10)  # 控制并发请求数
```

**关系推断规则**：
- 只保留 `REQUIRES`/`RELATED_TO` 跨章节关系
- `IS_PART_OF` 由骨架自动创建
- 节点分批 + 重叠 10 个捕获边界关系

### 8.4 学习路径服务 (`backend/services/pathway.py`)

**数据结构**：
```
LearningPath
  └─ LearningPathItem[] (kp_id, order_index, is_completed)
        └─ KGNode (知识点)
```

**接口**：
- `POST /pathways` — 创建路径
- `POST /pathways/{id}/items` — 添加知识点项
- `PUT /pathways/{path_id}/items/{item_id}` — 标记完成状态，同时写入 `LearningRecord`

**自动创建**：资源生成完成后，如用户无路径，自动创建以当前知识点为起点的路径。

```python
async def create_chat_table(session_id: str, db, username: str = ""):
    """动态创建会话消息表"""
    safe_name = re.sub(r"[^a-zA-Z0-9_]", "_", username.lower())
    short_id = session_id.replace("-", "")[:8]
    table_name = f"chat_msg_{safe_name}_{short_id}"

        session_id TEXT NOT NULL,
        role TEXT NOT NULL,
        content TEXT NOT NULL,
        resource_type TEXT,
        created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
    )
    """
    await db.execute(text(sql))
```

## 10. Auth 鉴权系统

### 10.1 密码安全

```python
# backend/auth/hash_utils.py
def hash_password(password: str) -> str:
    """bcrypt 哈希"""
    return bcrypt.hashpw(password.encode(), bcrypt.gensalt()).decode()

def verify_password(password: str, hashed: str) -> bool:
    """bcrypt 校验"""
    return bcrypt.checkpw(password.encode(), hashed.encode())
```

### 10.2 JWT 鉴权

**Token 结构**：
```python
{
    "sub": user_id,      # 用户 ID
    "exp": expire        # 过期时间
}
```

**依赖注入**（`backend/auth/deps.py`）：
```python
async def get_current_user_id(cred, user_id) -> str:
    """优先从 HTTPBearer JWT 解析，回退到 query param user_id"""
    if cred:
        token = cred.credentials
        payload = jwt.decode(token, config.jwt.secret, algorithms=[config.jwt.algorithm])
        return payload["sub"]
    return user_id
```

**配置**（`configs/config.yaml`）：
```yaml
jwt:
  secret: "${JWT_SECRET}"
  algorithm: "HS256"
  expire_hours: 24
```
