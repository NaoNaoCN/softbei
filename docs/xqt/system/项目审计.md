## 二、中危：Schema 字段名违反命名约定

### 问题描述

CLAUDE.md 明确规定 **"Schema field names must exactly match ORM field names"**，但以下 Schema 使用了不同的字段名。虽然目前通过手动构造绕过了问题，但这是维护隐患——如果将来改用 `from_attributes` 直接映射 ORM 对象，将导致运行时 `ValidationError`。

### 具体清单

| Schema | Schema 字段 | ORM 字段 | 文件:行 |
|--------|------------|----------|---------|
| `LearningPathOut` | `name` | `title` | schemas.py:199 |
| `LearningPathCreate` | `name` | `title` | schemas.py:208 |
| `LearningPathUpdate` | `name` | `title` | schemas.py:213 |
| `KGNodeOut` | `type` | `node_type` | schemas.py:150 |
| `ResourceMetaOut` | `content_path` | `content` | schemas.py:291 |
| `GenerateTaskOut` | `task_id` | `id` | schemas.py:234 |
| `GenerateTaskOut` | `error_msg` | `error_message` | schemas.py:237 |
| `KGBuildTaskOut` | `task_id` | `id` | schemas.py:244 |
| `KGBuildTaskOut` | `error_msg` | `error_message` | schemas.py:251 |
| `BatchTaskItem` | `task_id` | `id` | schemas.py:269 |
| `BatchGenerateOut` | `batch_id` | `id` | schemas.py:279 |

### 当前容错机制

这些 schema 在 `main.py` 和 `services/*.py` 中均通过**手动构造关键字参数**来赋值，例如：
```python
# backend/services/resource.py:46
ResourceMetaOut(content_path=resource.content, ...)
```
因此当前不会触发运行时错误，但不符合同一命名约定。

## 三、中危：Schema 声明了 ORM 不存在的字段

以下 Schema 声明了 ORM 模型中不存在的字段，完全依赖手动赋值：

| Schema | 字段 | schemas.py:行 | 说明 |
|--------|------|---------------|------|
| `KGNodeOut` | `difficulty` | 152 | `KGNode` 无此列 |
| `KGNodeOut` | `is_core` | 153 | `KGNode` 无此列 |
| `KGNodeOut` | `extra` | 154 | `KGNode` 无此列，运行时从 `description` 构造 |
| `QuizItemOut` | `difficulty` | 311 | `QuizItem` 无此列 |
| `QuizAttemptOut` | `kp_name, stem, options, answer, explanation, question_type, difficulty` | 334-342 | 这些是 `QuizItem` 的字段，需 JOIN 后才能填充 |

这些不会导致运行时错误（手动构造中赋值），但 `from_attributes=True` 对它们是无效配置。

## 四、中危：ORM 时间戳不规范

CLAUDE.md 要求统一使用 `created_at` / `updated_at`，但以下模型偏离了约定：

| 模型 | 问题 |
|------|------|
| `StudentProfile` | 有 `updated_at`，无 `created_at` |
| `LearningRecord` | 使用 `recorded_at` 替代 `created_at` |
| `QuizAttempt` | Python 属性名 `created_at` 映射到 DB 列 `submitted_at` |
| `ChatSession` | 使用 `last_used_at` 替代 `updated_at` |
| `KGNode`, `KGEdge`, `QuizItem`, `LearningPathItem` | 无任何时间戳列 |

## 六、低危：其他问题

### 6.1 Agent prompt 大量硬编码

`backend/agents/*.py` 中各 Agent 的 system prompt 直接硬编码在代码中（如 `graph.py`），不便于调优和多语言支持。

### 6.2 雪花算法生成 0 值 ID

最新提交 `872536d` 中 `generate_id()` 的起始序列号从 1 改为了 0，同一毫秒内的第一个 ID 序列号为 0。虽不影响唯一性，但如果前端或其他系统对 ID=0 有特殊判断逻辑，可能导致边界问题。
