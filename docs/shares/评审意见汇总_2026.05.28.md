## 一、技术问题与解答（提问环节）

### 1. 画像更新机制

| 项目 | 内容 |
|------|------|
| 问题 | 用户与 AI 的问答如何促使学习画像更新？更新机制是什么？ |
| 当前状态 | 已实现：每次对话时，画像 Agent 先从历史上下文和当前输入中判断 8 个字段哪些需要更新，完成更新后再进入路由 |
| 改进方向 | 答辩表述清晰，无需改动逻辑；可在 PPT 中用流程图更直观地展示更新触发链路 |

---

### 2. 防幻觉机制的层次

| 项目 | 内容 |
|------|------|
| 问题 | 防幻觉"双闸"中，一个是 RAG，另一个是什么？ |
| 当前状态 | 实际是三层：事前 RAG 知识库构建 → 事中相似度阈值过滤 → 事后安全 Agent 智能校验；答辩时只提到两层 |
| 改进方向 | PPT/视频中补充完整的三层防幻觉架构，避免被追问时描述前后不一致 |

---

### 3. RAG 降级机制

| 项目 | 内容 |
|------|------|
| 问题 | 用户问题无法在教材中找到准确答案时怎么处理？ |
| 当前状态 | 已实现降级：LLM 基于自身知识回答，前端提示"未检索到相关文档片段，内容由 LLM 生成，可能存在错误" |
| 追问 | 降级后还有安全校验吗？**目前没有。** |
| 改进方向 | 考虑为降级场景补充 WebSearch 工具调用能力（见下条），或在 PPT 中坦诚标注当前局限并列为 Future Work |

---

### 4. WebSearch 能力扩展

| 项目 | 内容 |
|------|------|
| 问题 | 能否给 AI 加上 WebSearch 工具调用能力，自行搜索网页？ |
| 现状 | 系统已有 Video Search 工具调用先例（对话 Agent 可搜索互联网视频讲解） |
| 改进方向 | 可用相同模式为安全 Agent 加 WebSearch，或直接调用 LLM 内置的 WebSearch 能力；作为加分项实现，并在演示中展示 |

---

### 5. 多模态资源生成

| 项目 | 内容 |
|------|------|
| 问题 | 除文档/知识图谱/练习题/代码外，有无图片、视频、动画等多模态资源？ |
| 当前答复 | 直接生成图片/视频可靠性低，事实校验难度大；规划使用 Manim 等动画代码库，AI 生成动画代码，前端自行渲染 |
| 改进方向 | 将 Manim 动画渲染模块列为近期 roadmap，在 PPT"未来规划"中展示；如能 Demo 出效果，是较强的差异化亮点 |

---

### 6. 个性化资源推送

| 项目 | 内容 |
|------|------|
| 问题 | 具体如何实现个性化推送？ |
| 当前状态 | 推荐 Agent 将多轮对话 + 知识图谱作为输入，从知识点列表中选取 3-5 个知识点构成路径推送 |
| 改进方向 | 在演示视频/PPT 中用可视化图示说明推荐路径的生成逻辑，增强说服力 |

---

### 7. 项目驱动型学习支持

| 项目 | 内容 |
|------|------|
| 问题 | 目前系统基于一门教材。实践类课程"用到什么学什么"，需跨学科、多教材，如何应对？ |
| 当前答复 | 坦诚承认当前系统设计以"教材驱动"为核心，与"项目驱动"的底层数据逻辑不同，尚未涉及 |
| 老师观点 | AI + X 跨学科融合学习是大势所趋，建议引入项目驱动的知识构建体系，以解决实际问题为出发点 |
| 改进方向 | 可在 PPT"系统扩展性"或"未来规划"中增加一段：说明如何将当前架构扩展至多教材/多学科场景，展示架构前瞻性 |

## 二、老王评审意见

### 8. 前端页面质量

| 项目 | 内容 |
|------|------|
| 问题 | 前端页面做的太差 |
| 改进方向 | 系统性优化 UI：统一设计语言、提升视觉层次感、参考竞品做交互细节打磨 |
| 目标效果 | 让评委在看演示视频时第一眼有"专业感"，不因界面粗糙分散对功能亮点的注意力 |

---

### 9. Agent 包装表述

| 项目 | 内容 |
|------|------|
| 问题 | 不要说"接入 Agent"，要强调如何运用外部 Agent 并在其基础上构建自己的系统/中枢 |
| 改进方向 | PPT 和答辩话术中，将表述从"调用别人的 Agent"改为"以 X 框架为基础，封装并构建了自有的多智能体调度中枢"；突出自研包装层的价值 |

---

### 10. 演示视频质感

| 项目 | 内容 |
|------|------|
| 问题 | 视频没有配音；BGM 太吵、太阴森 |
| 改进方向 | 重新录制演示视频：加入清晰的旁白配音（或字幕 + 轻音乐）；替换为舒适、专业的背景音乐 |

---

### 11. 架构图设计规范

| 项目 | 内容 |
|------|------|
| 建议 | 图铺满页面，内部层级简洁清晰，同层级元素对齐整齐 |
| 层次建议 | **基础能力层**：知识库 + 基础工具接口 + LLM API 封装 + RAG 工具链 → 打包为"垂直领域模型基座引擎" |
| | **智能体中枢层**：LangGraph 状态机，强调通信和交互原理；屏蔽前后端路由细节 |
| | **功能层**：按赛题功能点划分多个"智能体驱动的服务模块"；合并过多的 Agent，归类呈现 |
| 改进方向 | 按此三层结构重绘系统架构图，确保一眼能读出层级逻辑 |

---

### 12. 用户画像字段描述

| 项目 | 内容 |
|------|------|
| 问题 | PPT 上的八位画像特征描述太古板、生硬，措辞不当 |
| 改进方向 | 用更自然、用户友好的语言重新描述画像字段，配合真实用户画像卡片的可视化展示 |

---

### 13. 创新点表述与数量

| 项目 | 内容 |
|------|------|
| 问题 | 创新点罗列太多，滥竽充数；描述用原始说法，缺乏包装 |
| 建议 | 创新点最多保留 **3 个核心**：① 自定义知识库（教材驱动的 RAG 知识库搭建）；② 垂直领域模型基座引擎；③ 智能体中枢（LangGraph 多 Agent 调度） |
| 改进方向 | 每个创新点单独用 1-2 页深入讲解，最后一页做汇总；语言上"包装"升级，避免技术白话直译 |

---

### 14. 演示结构

| 项目 | 内容 |
|------|------|
| 建议 | 展示采用**总-分结构**：先总述系统全貌和核心价值，再逐一展开各功能模块 |

## 三、江老师评审意见

### 15. PPT AI 痕迹

| 项目 | 内容 |
|------|------|
| 问题 | PPT 是豆包做的吗？AI 痕迹过重 |
| 改进方向 | 手动优化 PPT 版式：调整字体、配色、排版，去除模板感；重写文案，降低 AI 生成痕迹 |

---

### 16. PPT 结构与逻辑

| 项目 | 内容 |
|------|------|
| 问题 | 第一页标题写得不对；整体像记流水账，缺乏大纲意识 |
| 建议 | 第二页应直接回应赛题要求：赛题要求什么 → 我们做了什么；整体要有章节意识，在 PPT 顶部标记当前页属于第几章 |
| 改进方向 | 重构 PPT 提纲：封面 → 赛题响应概览 → 系统架构 → 核心创新点（每点 1-2 页）→ 演示亮点 → 总结 |

---

### 17. 竞争环境与差异化

| 项目 | 内容 |
|------|------|
| 问题 | A3 赛题参与人数多，评委有审美疲劳；国赛阶段功能差距不大，比的是展示效果 |
| 改进方向 | 鲜明展示对赛题各要求点的响应，并突出 2-3 个**核心亮点**（不宜过多）；PPT 和视频都要围绕亮点做重点设计 |

---

### 18. 演示视频节奏

| 项目 | 内容 |
|------|------|
| 问题 | 视频整体节奏太拖沓，不展示完整使用流程，等待环节未裁剪 |
| 改进方向 | 重新剪辑：展示完整用户使用流程（注册 → 上传教材 → 对话 → 生成资源 → 查看画像/学习路径）；AI 生成的等待过渡用快进或剪辑处理；总时长控制在合理范围 |

---

### 19. 用户体验与服务意识

| 项目 | 内容 |
|------|------|
| 建议 | 演示要直观展示用户的完整体验过程和使用效果，体现"服务意识"；可设计一个生活化的使用场景故事线 |
| 加分项 | 从用户体验角度做优化设计，并在演示中直观呈现；如有余力，可拓展至 App/小程序移动端 |

---

### 20. 缺少竞品分析

| 项目 | 内容 |
|------|------|
| 问题 | PPT 缺少竞品分析 |
| 改进方向 | 增加竞品对比页：选取 2-3 个市面上类似产品（如学而思 AI、文心一言教育版等），从功能维度做对比表格，突出本系统差异化优势 |
