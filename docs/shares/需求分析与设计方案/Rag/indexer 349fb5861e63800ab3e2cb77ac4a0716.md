# indexer

# indexer.py 调用关系详解

> 文件路径：`backend/rag/indexer.py`
职责：接收 `loader.py` 产出的 `TextChunk` 列表，调用 `llm.get_embedding()` 批量嵌入后写入 ChromaDB 向量库。
> 

---

## 一、`index_chunks()` — 批量嵌入并写入 ChromaDB

### 函数签名

```python
async def index_chunks(
    chunks: list[TextChunk],
    collection_name: Optional[str] = None,   # None 使用 ChromaDB 默认集合
    batch_size: int = 32,
    progress_callback: Optional[Callable[[int, int], None]] = None,
    user_id: Optional[str] = None,s's's's's's's's's's's's's's's's's's
) -> int   # 返回成功写入的 chunk 数量
```

### 调用方：`index_file()` 和 `index_directory()`

| 项目 | 内容 |
| --- | --- |
| **输入 chunks** | `loader.load_file()` 或 `loader.load_directory()` 返回的 `TextChunk` 列表 |
| **批处理逻辑** | 每批 32 个 chunk，调用内部 `_embed_batch()` 并发嵌入（最多 8 并发），再调用 `upsert_documents()` 写入 ChromaDB |
| **写入内容** | `ids=chunk_id`，`documents=text`，`embeddings=向量`，`metadatas={doc_id, source, page, section}` |
| **输出** | 成功写入的 chunk 总数（整数），返回给调用方用于日志记录 |
| **输出用途** | ChromaDB 中持久化的向量数据供 `retriever.retrieve()` 做语义检索 |

**数据流**：

```
list[TextChunk]（来自 loader）
  → 按 batch_size=32 分批循环
    → _embed_batch([chunk.text for chunk in batch])
        → asyncio.Semaphore(8) 限流
          → get_embedding(text) × N（最多 8 并发）
            → list[list[float]]（每块的向量）
      → upsert_documents(
            ids=[chunk_id, ...],
            documents=[text, ...],
            embeddings=[vector, ...],
            metadatas=[{doc_id, source, page, section}, ...]
        )
        → ChromaDB 持久化（chunk_id 已存在则覆盖，支持增量更新）
  → total += len(batch)
→ 返回 total（写入总数）
```

## 二、`index_file()` — 一键索引单文件

### 函数签名

```python
async def index_file(
    file_path: str,
    collection_name: Optional[str] = None,
) -> int
```

### 调用方：外部脚本或管理接口

| 项目 | 内容 |
| --- | --- |
| **输入 file_path** | 单个文件路径，如 `"knowledge_base/ai_intro/chapters/chapter_01.pdf"` |
| **内部操作** | 串联 `loader.load_file(file_path)` → `index_chunks(chunks)` |
| **输出** | 写入的 chunk 数量 |
| **输出用途** | 用于单文件增量更新知识库，无需重新索引整个目录 |

**数据流**：

```
index_file("chapter_01.pdf")
  → loader.load_file("chapter_01.pdf") → list[TextChunk]
    → index_chunks(chunks) → int（写入数量）
```

## 三、`index_directory()` — 一键索引目录

### 函数签名

```python
async def index_directory(
    dir_path: str,
    collection_name: Optional[str] = None,
) -> int
```

### 调用方 1：首次初始化脚本（CLAUDE.md setup 命令）

```python
asyncio.run(index_directory('knowledge_base/ai_intro/chapters'))
```

### 调用方 2：外部管理脚本

| 项目 | 内容 |
| --- | --- |
| **输入 dir_path** | 知识库目录路径 |
| **内部操作** | 串联 `loader.load_directory(dir_path)` → `index_chunks(chunks)` |
| **输出** | 写入的 chunk 总数 |
| **输出用途** | 知识库全量初始化或重建的主入口 |

**数据流**：

```
index_directory("knowledge_base/ai_intro/chapters")
  → loader.load_directory(dir_path) → list[TextChunk]（所有文件合并）
    → index_chunks(chunks, batch_size=32) → int（写入总数）
```

## 四、内部辅助：`_embed_batch()`

```python
async def _embed_batch(texts: list[str]) -> list[list[float]]:
    """并发嵌入一批文本（最多 8 个并发调用）。"""
    semaphore = asyncio.Semaphore(8)
```

| 项目 | 内容 |
| --- | --- |
| **输入** | 一批文本字符串列表（最多 32 条，来自 `index_chunks` 的单批次） |
| **并发控制** | `asyncio.Semaphore(8)`，同时最多 8 个 `get_embedding()` 调用，避免 API 限流 |
| **输出** | `list[list[float]]`，与输入列表等长，每项为对应文本的嵌入向量 |
| **输出用途** | 传入 `upsert_documents(embeddings=...)` 写入 ChromaDB |

---

## 五、整体数据流

```
【知识库初始化 / 增量更新】

index_directory(dir_path)
  → loader.load_directory() → list[TextChunk]
    → index_chunks(chunks, batch_size=32)
        → 分批（每批32个）
          → _embed_batch([text, ...])
              → get_embedding(text) × N（Semaphore 限流，最多8并发）
                → list[list[float]]
          → upsert_documents(ids, documents, embeddings, metadatas)
              → ChromaDB 持久化
        → 返回写入总数

【后续检索由 retriever.py 负责，直接查询 ChromaDB】
```
