# loader

# loader.py 调用关系详解

> 文件路径：`backend/rag/loader.py`
职责：将本地知识库文件（PDF/DOCX/Markdown/TXT）解析为带元数据的纯文本块，供 `indexer.py` 嵌入入库。
> 

---

## 一、`load_file()` — 加载单个文件

### 函数签名

```python
def load_file(
    file_path: str | Path,
    doc_id: Optional[str] = None,   # 默认使用文件名（无扩展名）
) -> list[TextChunk]
```

### 调用方：`indexer.index_file()`

**文件**：`backend/rag/indexer.py:64`

| 项目 | 内容 |
| --- | --- |
| **输入 file_path** | 单个知识库文件的路径，如 `knowledge_base/ai_intro/chapters/chapter_01.pdf` |
| **内部路由** | 按扩展名分发：`.pdf` → `_load_pdf()`，`.docx/.doc` → `_load_docx()`，`.md` → `_load_markdown()`，`.txt` → `_load_txt()` |
| **输出** | `list[TextChunk]`，每个 TextChunk 含 `chunk_id`（`{doc_id}_{index}`）、`text`（纯文本，约 512 字符）、`source_path`、`page`、`section` |
| **输出用途** | 传入 `indexer.index_chunks()` 进行嵌入和入库 |

**数据流**：

```
indexer.index_file("chapter_01.pdf")
  → load_file("chapter_01.pdf", doc_id="chapter_01")
    → 按扩展名路由 → _load_pdf(path, "chapter_01")
      → 解析每页文本 → split_text(page_text)
        → list[str]（每项约512字符）
          → 包装为 TextChunk(chunk_id="chapter_01_0", text=..., page=1, ...)
            → list[TextChunk]
              → 返回给 index_chunks()
```

## 二、`load_directory()` — 递归加载目录

### 函数签名

```python
def load_directory(
    dir_path: str | Path,
    glob_pattern: str = "**/*",
    recursive: bool = True,
) -> list[TextChunk]
```

### 调用方 1：`indexer.index_directory()`

**文件**：`backend/rag/indexer.py:74`

| 项目 | 内容 |
| --- | --- |
| **输入 dir_path** | 知识库目录路径，如 `knowledge_base/ai_intro/chapters` |
| **内部操作** | `Path(dir_path).glob("**/*")` 递归扫描，对每个支持格式（`.pdf/.docx/.doc/.md/.txt`）的文件调用 `load_file()`，解析失败的文件跳过并打印日志 |
| **输出** | 所有文件的 `TextChunk` 合并列表 |
| **输出用途** | 传入 `index_chunks()` 批量入库 |

### 调用方 2：首次初始化脚本

```python
# CLAUDE.md 中的 setup 命令
asyncio.run(index_directory('knowledge_base/ai_intro/chapters'))
```

**数据流**：

```
load_directory("knowledge_base/ai_intro/chapters")
  → glob("**/*") → [chapter_01.pdf, chapter_02.md, ...]
    → load_file(chapter_01.pdf) → list[TextChunk]
    → load_file(chapter_02.md)  → list[TextChunk]
    → ...（失败的文件跳过，打印日志）
      → 合并所有 TextChunk → list[TextChunk]
        → 返回给 index_chunks()
```

## 三、`split_text()` — 文本切分

### 函数签名

```python
def split_text(
    text: str,
    chunk_size: int = 512,   # 每块最大字符数
    overlap: int = 64,       # 相邻块重叠字符数
) -> list[str]
```

### 调用方：各私有解析函数（`_load_pdf` / `_load_docx` / `_load_markdown` / `_load_txt`）

| 项目 | 内容 |
| --- | --- |
| **输入 text** | 单页/单段落/单章节的原始文本字符串，由各解析器从文件中提取后传入 |
| **切分逻辑** | 按 `chunk_size` 步进，每步后退 `overlap` 字符，保证相邻块有上下文重叠，避免语义在边界处断裂 |
| **输出** | `list[str]`，每项约 512 字符；若原文本 ≤ 512 字符则直接返回单元素列表 |
| **输出用途** | 各解析函数将切分结果包装为 `TextChunk` 对象（附加 doc_id/page/section 元数据） |

### 测试覆盖

**文件**：`tests/test_rag.py`

```python
split_text(text, chunk_size=512)           # 短文本不切分 → [text]
split_text(text, chunk_size=200, overlap=50)  # 验证 overlap 保留
split_text(text, chunk_size=50, overlap=10)   # 验证块数量正确
```

`split_text` 是 RAG 管道中唯一有单元测试覆盖的纯函数，无外部依赖，可直接运行。

## 四、私有解析函数

均为 stub，实现后各自调用 `split_text()` 完成切分：

| 函数 | 依赖库 | 切分策略 | 填充的元数据字段 |
| --- | --- | --- | --- |
| `_load_pdf` | `pypdf` | 按页提取文本 → `split_text()` | `page=页码` |
| `_load_docx` | `python-docx` | 按段落聚合 → `split_text()` | `section=段落标题` |
| `_load_markdown` | 正则 | 按 `##` 标题切章节 → `split_text()` | `section=标题文本` |
| `_load_txt` | 内置 | `read_text()` → `split_text()` | 无 |

## 九、整体数据流

### **【单文件索引】**

```
indexer.index_file("chapter_01.pdf")
  → load_file("chapter_01.pdf")
    → _load_pdf(path, "chapter_01")
      → PyPDFLoader.load() → list[Document]
        → 按页读取 PDF 内容，返回 Document 列表
        → 每页内容存储在 Document.page_content，元数据包含 page 编号
      → docs_to_chunks(docs, "chapter_01")
        → 遍历每页 Document
        → 去掉首尾空白字符（strip）
        → 调用 split_text(page_text) 按字符数切分（每块约 512 字符，相邻块重叠 64 字符保持上下文连贯）
        → 为每个子块创建 TextChunk 对象，分配 chunk_id（如 "chapter_01_0"、"chapter_01_1"...）
        → TextChunk 携带元数据：doc_id、source_path（原始文件路径）、page（页码）、section（章节标题，PDF 始终为 None）
        → 返回 list[TextChunk]
    → list[TextChunk]（本章所有页的块合并）
  → indexer.index_chunks(chunks)
    → 分批处理（每批 32 个 TextChunk）
    → _embed_batch([text, ...])
      → 对每批文本调用 get_embedding() 获取向量（最多 8 并发，避免 API 限流）
      → 返回 list[list[float]]（每个文本块对应的嵌入向量）
    → upsert_documents(ids, documents, embeddings, metadata)
      → 写入 ChromaDB 向量库
      → chunk_id 已存在时自动覆盖（支持增量更新）
      → metadata 中包含 doc_id、source、page、section、user_id
    → 返回本次写入的 chunk 总数
```

### **【目录全量索引】**

```
indexer.index_directory("knowledge_base/ai_intro/chapters")
  → load_directory("knowledge_base/ai_intro/chapters")
    → Path.glob("**/*") 遍历目录下所有文件（支持递归子目录）
    → 筛选支持的文件格式（.pdf、.docx、.doc、.md、.txt）
    → 对每个文件调用 load_file() 逐个加载
      → 加载成功的文件 → list[TextChunk] → 追加到结果列表
      → 加载失败的文件 → logger.warning 记录跳过（不中断整体流程）
    → 返回 list[TextChunk]（所有文件的所有块合并为一个列表）
  → indexer.index_chunks(chunks, batch_size=32)
    → 同上：分批 → 并发嵌入 → 批量写入 ChromaDB
```

### **【Markdown 特殊处理流程】**

```
load_file("intro.md")
  → _load_markdown(path, "intro")
    → TextLoader 读取原始 Markdown 文本（UTF-8 编码）
    → _split_markdown_by_headers(full_text)
      → 第一步：去除代码块（临时替换为 [CODE_BLOCK] 占位符），避免代码块内的 ## 干扰标题识别
      → 第二步：正则匹配 ^##\s+(.+)$ 找到所有二级标题（## 标题行）
      → 第三步：按标题位置切分，每节包含"标题 + 标题到下一个标题之间的内容"
      → 第四步：还原代码块占位符，恢复原始代码块内容
      → 返回 [(章节标题, 章节内容), ...] 列表
      → 若无任何 ## 标题，返回 [("无标题", 整篇文本)]
    → 遍历每个章节
      → doc.metadata["section"] = 章节标题（为后续 TextChunk 携带章节信息）
      → split_text(章节文本) 按字符数切分（每块约 512 字符）
      → 为每个子块创建 TextChunk，section 字段 = 所属章节标题
      → 返回 list[TextChunk]（每个块都知道自己属于哪个章节）
```

### **【PDF 目录提取（独立功能）】**

```
extract_toc("intro.pdf")
  → PdfReader 打开 PDF 文件
    → 读取 outline（书签/目录树结构）
    → 若无 outline → 返回 None
  → 递归遍历 outline
    → 对每个书签项提取 title（标题文本）和 destination（跳转目标页）
    → 解析目标页为 0-based 页码（处理 IndirectObject 引用）
    → 返回 [{"title": "注意力机制", "page": 42, "level": 2}, ...]
  → 前端可据此渲染 PDF 目录导航
```
