# 项目工作流与数据流分析

## 一、项目概述

### 1.1 项目类型与定位

这是一个**Python 全栈 AI 应用**，参赛作品（第十五届中国软件杯 A3 赛题），基于多智能体（Multi-Agent）架构的**个性化学习资源生成系统**。

### 1.2 技术栈

| 层级 | 技术 |
| --- | --- |
| 前端 | Streamlit 1.35+ |
| 后端 | FastAPI + Uvicorn |
| Agent 框架 | LangGraph + LangChain |
| LLM | 讯飞星火（兼容 OpenAI SDK） |
| 向量库 | ChromaDB |
| 关系数据库 | MySQL（生产）/ SQLite（开发） |
| ORM | SQLAlchemy 2.x 异步 |

## 三、数据模型关系

**文件位置**: `backend/db/models.py`

### 3.1 核心实体（13 张数据库表）

```
User (用户)
    ├── StudentProfile (学生画像) ──── ProfileHistory (历史快照)
    ├── ChatSession (对话会话) ──── ChatMessage (消息记录)
    └── ResourceMeta (资源元数据)
            ├── GenerationTask (生成任务)
            └── QuizItem (题目) ──── QuizAttempt (答题记录)

KnowledgeGraph (知识图谱)
    ├── KGNode (知识点节点)
    └── KGEdge (知识点关系)

LearningPath (学习路径)
    └── LearningPathItem (路径节点)

LearningRecord (学习记录)
```

### 3.2 主要模型说明

| 模型 | 表名 | 关键字段 | 关系 |
| --- | --- | --- | --- |
| **User** | user | id, username, hashed_password | 1:1 StudentProfile, 1:N ChatSession, 1:N ResourceMeta |
| **StudentProfile** | student_profile | id, user_id, major, learning_goal, cognitive_style, knowledge_mastered, knowledge_weak | 属于 User, 1:N ProfileHistory |
| **ProfileHistory** | profile_history | id, profile_id, snapshot (JSON) | 属于 StudentProfile |
| **ChatSession** | chat_session | id, user_id, title | 属于 User, 1:N ChatMessage |
| **ChatMessage** | chat_message | id, session_id, role, content | 属于 ChatSession |
| **KGNode** | kg_node | id, name, node_type, description | 1:N KGEdge (out/in) |
| **KGEdge** | kg_edge | id, source_id, target_id, relation | 属于 KGNode |
| **ResourceMeta** | resource_meta | id, user_id, kp_id, resource_type, title, content_json | 属于 User, 1:1 GenerationTask, 1:N QuizItem |
| **GenerationTask** | generation_task | id, resource_id, status, progress | 属于 ResourceMeta |
| **QuizItem** | quiz_item | id, resource_id, question_type, stem, options, answer | 属于 ResourceMeta, 1:N QuizAttempt |
| **QuizAttempt** | quiz_attempt | id, quiz_item_id, user_id, user_answer, is_correct | 属于 QuizItem, User |
| **LearningPath** | learning_path | id, user_id, title | 属于 User, 1:N LearningPathItem |
| **LearningPathItem** | learning_path_item | id, path_id, kp_id, order_index, is_completed | 属于 LearningPath |
| **LearningRecord** | learning_record | id, user_id, resource_id, action, duration_seconds | 属于 User, ResourceMeta |

### 3.3 向量数据库 (ChromaDB)

**文件位置**: `backend/db/vector.py`

```python
CHROMA_PERSIST_DIR = "./chroma_data"  # 持久化目录
COLLECTION_NAME = "knowledge_base"     # 默认集合名
```

向量数据库存储结构：
- **ids**: 文档块唯一标识 (格式: `{doc_id}_{chunk_index}`)
- **documents**: 原始文本内容
- **embeddings**: BGE-M3 模型生成的 1024 维向量
- **metadatas**: 包含 doc_id, source, page, section

## 四、RAG 管道

**文件位置**: `backend/rag/`

### 4.1 数据加载器

**文件位置**: `backend/rag/loader.py`

```
load_file(file_path) → list[TextChunk]
    ├── .pdf → _load_pdf() (pypdf)
    ├── .docx/.doc → _load_docx() (python-docx)
    ├── .md → _load_markdown() (按 ## 章节切分)
    └── .txt → _load_txt()

load_directory(dir_path) → 递归加载目录下所有支持格式

split_text(text, chunk_size=512, overlap=64) → 按字符数滑动窗口切分
```

### 4.2 索引构建器

**文件位置**: `backend/rag/indexer.py`

```
index_chunks(chunks, collection_name, batch_size=32) → 写入向量库
    └── _embed_batch(texts) → 并发嵌入（最多8并发）

index_file(file_path) → 加载并索引单个文件
index_directory(dir_path) → 递归扫描并全量索引
```

### 4.3 检索器

**文件位置**: `backend/rag/retriever.py`

```
retrieve(query, n_results=5, score_threshold=0.5)
    ├── get_embedding(query) → 获取查询向量
    ├── query_documents() → ChromaDB 相似度搜索
    └── _parse_results() → 转换为 RetrievedChunk 列表

retrieve_by_kp(kp_name, n_results=8) → 按知识点名称检索

format_context(chunks, max_tokens=3000) → 格式化检索结果为 prompt 上下文
    格式：[1] （来源：xxx.pdf, 第2页）
          文本内容...
```

### 7.2 Chat 端点详细流程

```python
# main.py:158-175
@app.post("/chat/{session_id}")
async def chat(session_id, user_id, body: ChatMessageIn, stream=False):
    if stream:
        # 流式响应 (SSE)
        async def event_generator():
            async for event in stream_invoke(str(user_id), str(session_id), body.content):
                yield f"data:{event}\n\n"
        return StreamingResponse(event_generator(), media_type="text/event-stream")

    # 非流式响应
    result = await invoke(str(user_id), str(session_id), body.content)
    return {"content": result.final_content, "metadata": result.metadata}
```

## 九、完整数据流动路径

### 场景：用户请求生成一份关于”梯度下降”知识点的思维导图

### 路径1：对话式请求 (Chat 接口)

```
1. 用户在前端输入: "请帮我生成梯度下降的思维导图"

2. streamlit_app 调用后端 API:
   POST /chat/{session_id}?user_id=xxx
   body: {"content": "请帮我生成梯度下降的思维导图"}

3. FastAPI main.py:158-175
   → invoke(user_id, session_id, message)

4. LangGraph Agent 系统启动 (graph.py:98-113):
   ┌─────────────────────────────────────────────────────┐
   │ AgentState(                                         │
   │     user_id="xxx",                                   │
   │     session_id="yyy",                                │
   │     user_message="请帮我生成梯度下降的思维导图"        │
   │ )                                                    │
   └─────────────────────────────────────────────────────┘
                           │
                           ▼
5. profile_agent.run(state) - 提取/更新画像
   └─ 从 user_message 提取学生信息
   └─ 更新 StudentProfile 表
   └─ state.profile = StudentProfileOut(...)
                           │
                           ▼
6. planner_agent.run(state) - 解析意图
   └─ 调用 LLM 分析: resource_type="mindmap", kp_id="kp_梯度下降"
   └─ state.resource_type = ResourceType.mindmap
   └─ state.kp_id = "kp_梯度下降"
                           │
                           ▼
7. 条件路由 → "mindmap_agent" (planner_agent.py:42)
                           │
                           ▼
8. mindmap_agent.run(state) - RAG 生成
   ┌─ retriever.py:62 retrieve_by_kp("梯度下降")
   │   └─ get_embedding("知识点：梯度下降")
   │   └─ query_documents(embedding, n_results=8)
   │   └─ 返回 list[RetrievedChunk]
   │
   ├─ format_context(chunks, max_tokens=3000)
   │   └─ 格式化检索结果
   │
   └─ llm.chat_completion([SYSTEM_PROMPT, user_message + context])
       └─ state.draft_content = ECharts tree JSON
                           │
                           ▼
9. safety_agent.run(state) - 安全审核
   └─ 对比 draft_content 与 retrieved_docs
   └─ 若通过: state.final_content = state.draft_content
   └─ 若不通过: state.final_content = revised_content
                           │
                           ▼
10. recommend_agent.run(state) - 推荐知识点
    └─ 根据画像和已学知识点推荐下一步
    └─ state.metadata["recommendations"] = [...]
                           │
                           ▼
11. 返回 AgentState 给 FastAPI
    └─ return {"content": result.final_content, "metadata": result.metadata}

12. 前端收到响应，渲染思维导图:
    mindmap.py:19 render_mindmap(tree_data)
    └─ st_echarts(option) 使用 ECharts 渲染
```

### 路径2：直接生成请求 (Generate 接口)

```
1. 用户在 pages/2_generate.py 选择:
   - 知识点: "梯度下降"
   - 资源类型: "mindmap"
   - 点击 "开始生成"

2. 前端调用: POST /generate?user_id=xxx
   body: {"kp_id": "kp_梯度下降", "resource_type": "mindmap"}

3. FastAPI main.py:204-217
   → resource_svc.create_generation_task()
   → 创建 GenerationTask(status=pending)
   → 返回 task_id

4. 前端轮询: GET /generate/{task_id}/status
   → pages/2_generate.py:113-140
   → st.progress() 实时显示进度

5. 后端 BackgroundTasks 执行:
   → 调用对应的 Agent (mindmap_agent)
   → 更新 GenerationTask(status=running, progress=50)
   → 生成完成: GenerationTask(status=done, result_id=resource_id)

6. 前端获取结果:
   GET /resources/{result_id}
   → render_mindmap(resource.content_json)
```
