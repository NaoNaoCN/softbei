# tests/test_rag.py 测试文档

## 一、测试概述

本测试文件位于 `tests/test_rag.py`，负责对 `backend/rag/loader.py` 模块进行单元测试和集成测试，覆盖文档加载器、文本切分器、Markdown 解析器以及 `TextChunk` 数据类的全部核心功能。

**运行命令：**

```bash
pytest tests/test_rag.py -v
```

**测试结果：** 23 个测试全部通过。

---

## 二、被测模块

### 2.1 模块位置

```
backend/rag/loader.py
```

### 2.2 核心接口一览

| 函数/类 | 说明 |
| --- | --- |
| `split_text(text, chunk_size, overlap)` | 按字符数滑动窗口切分文本 |
| `_split_markdown_by_headers(text)` | 按 `##` 标题分割 Markdown 章节 |
| `load_file(file_path, doc_id)` | 加载单个文件，根据扩展名选择解析器 |
| `load_directory(dir_path, glob_pattern, recursive)` | 递归/非递归加载目录下所有支持的文件 |
| `TextChunk` | 文档块数据结构，包含 chunk_id、text、doc_id、source_path、page、section、metadata |
| `TextChunk.to_langchain_doc()` | 转换为 LangChain Document |
| `TextChunk.from_langchain_doc(doc, doc_id, chunk_index)` | 从 LangChain Document 转换 |

### 2.3 支持的文件格式

| 格式 | 加载器 | 切分策略 |
| --- | --- | --- |
| `.pdf` | `PyPDFLoader` | 按页加载，再按字符数切分 |
| `.docx` / `.doc` | `UnstructuredWordDocumentLoader` | 按段落加载，再按字符数切分 |
| `.md` | `TextLoader` + 自定义解析 | 先按 `##` 标题分章节，章节内再切分 |
| `.txt` | `TextLoader` | 直接按字符数切分 |

## 四、测试用例详解

### 4.1 TestSplitText

`split_text` 是最核心的文本切分函数，共有 6 个测试用例。

| 用例 | 输入 | 期望输出 | 测试目的 |
| --- | --- | --- | --- |
| `test_short_text_no_split` | `"这是一段短文本。"`, chunk_size=512 | `["这是一段短文本。"]` | 短于 chunk_size 的文本不应被切分 |
| `test_long_text_splits_correctly` | `"A" * 1000`, chunk_size=200, overlap=50 | 切分为 6+ 块，每块 ≤200 字符 | 长文本正确切分 |
| `test_overlap_preserved` | `"0123456789" * 20`, chunk_size=50, overlap=10 | `chunks[0][-10:] == chunks[1][:10]` | 相邻块之间的 overlap 正确保留 |
| `test_exact_size_text` | `"A" * 500`, chunk_size=500 | `["A" * 500]`（1块） | 长度等于 chunk_size 时不切分 |
| `test_empty_text` | `""`, chunk_size=500 | `[]` | 空文本返回空列表（**Bug修复**：之前返回 `[""]`） |
| `test_overlap_clamped_to_chunk_size` | `"A" * 1000`, chunk_size=100, overlap=150 | 正常切分，不无限循环 | overlap 超过 chunk_size 时应被限制为 chunk_size-1（**Bug修复**：之前无限循环） |

**关键 Bug 修复记录：**

1. **空文本返回 `[""]`**：修复前 `split_text("", 500)` 返回 `[""]`，修复后返回 `[]`
2. **overlap > chunk_size 无限循环**：修复前 `overlap=150, chunk_size=100` 会导致 `start += 100 - 150 = -50`，游标永不前进，修复后 `overlap` 被限制为 `min(overlap, chunk_size - 1)`

### 4.2 TestSplitMarkdownByHeaders

负责 Markdown 标题解析，共 5 个测试用例。

| 用例 | 输入 | 期望输出 | 测试目的 |
| --- | --- | --- | --- |
| `test_single_section_no_headers` | 无 `##` 的 Markdown | `("无标题", 全文)` | 无标题时整篇作为”无标题”章节 |
| `test_multiple_headers` | 3 个 `##` 标题 | 3 个章节，标题和内容正确分离 | 多个标题正确分割 |
| `test_header_with_code_blocks` | `## 标题` + 代码块（含 `##`） | 1 个章节，代码块内的 `##` 不被识别 | 代码块内标题正确忽略（占位符策略） |
| `test_consecutive_headers` | 两个标题之间有正文 | 2 个章节，正文内容正确归入各章节 | 有内容时正确处理 |
| `test_deeply_nested_headers` | `## 主标题` + `### 子标题` | 1 个章节，子标题作为正文内容 | 仅识别 `##`，不识别 `###` 及更深层级 |

**设计细节：**

```python
# 解析策略：先用占位符替换代码块，再匹配 ## 标题
code_block_pattern = re.compile(r'```[\s\S]*?```')
text_without_code = code_block_pattern.sub('[CODE_BLOCK]', text)
# 再对 text_without_code 进行标题匹配
header_pattern = re.compile(r'^##\s+(.+)$', re.MULTILINE)
```

### 4.5 TestTextChunk

测试 `TextChunk` 数据类及其与 LangChain Document 的互转，共 3 个用例。

| 用例 | 测试内容 |
| --- | --- |
| `test_chunk_creation` | 直接构造 `TextChunk` 实例，验证各字段赋值正确 |
| `test_to_langchain_doc` | 调用 `to_langchain_doc()`，验证转换为 LangChain Document 的 metadata 包含所有字段 |
| `test_from_langchain_doc` | 从 LangChain Document 反向转换，验证 `doc_id`、`chunk_id`、额外 metadata 正确 |

**Bug 修复记录：**

`TextChunk` 最初缺少 `@dataclass` 装饰器，导致所有构造参数被当作类属性声明而非构造函数参数，引发 `TypeError: TextChunk() takes no arguments`。修复方法：

```python
# 修复前
class TextChunk:
    chunk_id: str
    text: str
    ...

# 修复后
@dataclass
class TextChunk:
    chunk_id: str
    text: str
    ...
    metadata: dict = field(default_factory=dict)
```

def test_load_txt_file(self, tmp_path):

    test_file.write_text("第一段。\n\n第二段。", encoding="utf-8")

def test_load_epub_file(self, tmp_path):

    test_file.write_bytes(b"...")

### 6.3 边界条件检查清单

新增 `split_text` 相关功能时，建议覆盖以下边界：

- [ ]  空字符串输入
- [ ]  `chunk_size=1`（最小切分）
- [ ]  `overlap=0`（无重叠）
- [ ]  `overlap >= chunk_size`（应被限制）
- [ ]  文本长度等于 chunk_size
- [ ]  文本长度小于 chunk_size
