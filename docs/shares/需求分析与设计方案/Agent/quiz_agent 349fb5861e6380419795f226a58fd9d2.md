# QuizAgent - 测验题目生成智能体

## 概述

QuizAgent 负责生成多题型的测验题目集合。它是一位出题专家，能够根据知识点和学生画像，生成适配难度和题型的选择题、填空题等题目。

## 核心职责

1. **题目生成** - 根据知识点检索资料，调用 LLM 生成题目 JSON 数组
2. **难度控制** - 结合学生画像决定题目难度分布
3. **数据持久化** - 将题目列表批量写入 `quiz_item` 表
4. **题型配比控制** - 支持用户指定或按画像自动分配单/多/填空题数量
5. **数据持久化** - 独立函数 `save_quiz_items()` 批量写入 `quiz_item` 表
6. **异常兜底** - JSON 解析失败时写入 `[]`，不中断状态机

## System Prompt

```
你是一位出题专家。
请为以下知识点出 {count} 道题目，题型分布：
- 单选题（single）：{single_count} 道
- 多选题（multi）：{multi_count} 道
- 填空题（fill）：{fill_count} 道

以 JSON 数组返回，每道题格式：
{
  "question_type": "single/multi/fill",
  "difficulty": 1-5,
  "stem": "题干",
  "options": ["A. ...", "B. ..."],  // 填空题为 null
  "answer": "A" 或 ["A","C"] 或 "答案文本",
  "explanation": "解析"
}

参考资料：{context}
知识点：{kp_name}
```

## 输入与输出

### 输入（AgentState）

| 字段 | 说明 |
| --- | --- |
| `kp_id` | 目标知识点 ID |
| `profile` | 学生画像（用于确定难度分布） |
| `retrieved_docs` | 检索到的参考文档 |
| `user_id` | 用户 ID（RAG 检索过滤） |
| `num_questions` | 总题目数量（用户指定） |
| `question_type_counts` | 题型配比（`{"single": 2, "multi": 1, "fill": 1}`） |

### 输出（AgentState 更新）

| 字段 | 说明 |
| --- | --- |
| `draft_content` | 题目列表的 JSON 字符串 |
| `retrieved_docs` | 更新为本次检索到的文档文本列表 |

## 题目格式

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `question_type` | QuestionType | 题型（single/multi/fill） |
| `difficulty` | int | 难度等级（1-5） |
| `stem` | str | 题干 |
| `options` | list[str] | null | 选项列表（填空题为 null） |
| `answer` | str | list[str] | 答案 |
| `explanation` | str | 解析 |

## 题型分布策略

**优先级顺序**（从高到低）：

1. **用户指定题型配比**（`state.question_type_counts`）：
    - 前端可传入 `{"single": 3, "multi": 2, "fill": 1}` 精确控制
2. **用户指定总题数**（`state.num_questions`）：
    - 按比例分配：单选 50%、多选 25%、填空 25%
    - 例如 `num_questions=4` → `single=2, multi=1, fill=1`
3. **根据画像自动分配**（`_get_question_counts(profile)`）：
    - 薄弱知识点 > 5 个 → `3单 + 2多 + 2填 = 7题`
    - 薄弱知识点 3-5 个 → `2单 + 1多 + 1填 = 4题`
    - 薄弱知识点 ≤ 2 个 → `2单 + 1多 + 1填 = 4题`
4. **默认值**：`2单 + 1多 + 1填 = 4题`

## **执行流程**

1. 通过 `resolve_kp_name` 从 `kp_id` 获取知识点名称 `kp_name`
2. 决定题目数量分布（4 级优先级：用户指定配比 → 用户指定总数 → 画像自动 → 默认）
3. 记录日志：打印 `kp_name`、`total`、`single`、`multi`、`fill`
4. 检索 context（优先检索包含代码的文档块，`n_results=5`） 
5. RAG 检索到文档时记录日志（条数），未检索到时记录 warning，检索异常时记录 warning 并降级
6. 构造 `context = format_context(chunks, max_tokens=3000)`
7. 填充 SYSTEM_PROMPT 中的 `{count}`、`{single_count}`、`{multi_count}`、`{fill_count}`、`{context}`、`{kp_name}`
8. 调用 `chat_completion` 生成题目（`temperature=0.6`, `max_tokens=3000`）
9. 处理 Markdown 代码块包裹的 JSON
10. JSON 解析：
    - 成功：序列化后写入 `draft_content`
    - JSONDecodeError：记录 warning + raw_preview，写入 `"[]"`
    - 其他异常：记录 error，写入 `"题目生成失败：{e}"`

## **题目持久化**

**`save_quiz_items(resource_id, kp_id, questions, db) -> None`**

将题目列表批量写入 `quiz_item` 表，供生成资源后持久化使用。

**参数**：

- `resource_id: str` — 资源 ID
- `kp_id: str` — 知识点 ID
- `questions: list[dict]` — 题目列表（LLM 生成的 JSON 数组）
- `db: AsyncSession` — 数据库会话

**写入字段**：

```jsx
{
    "resource_id": resource_id,
    "kp_id": kp_id,
    "question_type": q.get("question_type", "single"),
    "stem": q.get("stem", ""),
    "options": q.get("options"),
    "answer": str(q.get("answer", "")),
    "explanation": q.get("explanation"),
    "order_index": i,  # 题目序号
}
```

**异常处理**：`insert_many` 失败时直接 `raise`，由调用方处理。
