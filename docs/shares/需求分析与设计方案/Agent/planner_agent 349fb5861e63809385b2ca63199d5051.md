# PlannerAgent - 计划调度智能体

## 概述

PlannerAgent 是整个 Agent 流水线的调度中心，负责解析用户意图，决定生成哪种类型的学习资源，并确定目标知识点。它是连接用户请求与具体执行 Agent 的桥梁。

## 核心职责

1. **意图分析** - 结合 `user_message` 和 `profile` 分析用户想要的学习资源类型
2. **意图分类** - 区分 `generate`（资源生成）和 `clarify`（追问/解释），追问走 clarify_agent
3. **知识定位** - 从知识图谱节点中选择目标知识点（`kp_id`）
4. **多资源意图支持** - 检测用户是否要求多种资源（如"文档和测验"），解析 `extra_types`
5. **路由决策** - 通过 `route_by_resource_type` 函数决定下一个执行的 Agent

## System Prompt

```
你是一个学习计划分析助手。
根据学生的问题和画像，判断：
1. 学生想要生成什么类型的学习资源：
   - doc: 学习文档（默认，当学生想学习某个知识点时）
   - mindmap: 思维导图（当学生想要知识结构概览时）
   - quiz: 测验题目（当学生想测试自己时）
   - code: 代码示例（当学生想看代码实现时）
   - summary: 知识总结（当学生想要复习总结时）
   - kg: 知识图谱构建（当学生想构建知识图谱、分析知识结构时）
2. 目标知识点名称（从学生消息中提取）
3. 如果学生明确要求多种资源（如"帮我生成文档和测验"），将主资源放在 resource_type，其余放在 extra_types 数组中

{kp_list_section}

以 JSON 格式返回：{"resource_type": "doc", "kp_id": "知识点名称", "extra_types": []}
resource_type 不能为 null，如果无法判断具体类型，默认使用 "doc"。
kp_id 使用学生提到的知识点名称，如"多层感知机"、"反向传播"等。
extra_types 仅当学生明确要求多种资源时才填写，否则为空数组。例如学生说"生成文档和测验题"，则 resource_type="doc", extra_types=["quiz"]。
只返回 JSON，不要包含其他内容。
```

## **意图分类 Prompt**

```
判断学生的消息属于哪种类型：
1. "generate" — 学生想要生成新的学习资源（学习某个知识点、生成文档/思维导图/测验/代码/总结/知识图谱）
2. "clarify" — 学生在对之前的对话内容进行追问、请求解释、要求展开某个部分、询问细节

判断依据：
- 如果消息中包含"你提到的"、"上面的"、"刚才的"、"第X部分"、"详细解释"、"展开说说"等指代之前回答的表述 → clarify
- 如果消息是一个新的知识点学习请求或资源生成请求 → generate
- 如果不确定，默认 generate

只返回 JSON：{"intent": "generate"} 或 {"intent": "clarify"}
不要包含其他内容。
```

## 输入与输出

### 输入（AgentState）

| 字段 | 说明 |
| --- | --- |
| `user_message` | 用户原始输入 |
| `profile` | 学生画像信息 |
| `chat_history` | 多轮对话历史（用于意图分类和指代理解） |
| `resource_type` | 预设资源类型（跳过 LLM 分析时使用） |
| `kp_id` | 预设知识点 ID（跳过 LLM 分析时使用） |

### 输出（AgentState 更新）

| 字段 | 说明 |
| --- | --- |
| `intent_type` | 意图类型（`generate` / `clarify`） |
| `resource_type` | 资源类型枚举（ResourceType） |
| `kp_id` | 目标知识点 ID（名称） |
| `metadata["extra_resource_types"]` | 多资源意图时存储额外资源类型列表 |

## 条件路由（route_by_resource_type）

根据 `intent_type` 和 `resource_type` 决定下一个 Agent 节点：

| 条件 | 目标 Agent |
| --- | --- |
| `intent_type == "clarify"` | `clarify_agent`（追问/解释） |
| `resource_type == doc` | `doc_agent` |
| `resource_type == mindmap` | `mindmap_agent` |
| `resource_type == quiz` | `quiz_agent` |
| `resource_type == code` | `code_agent` |
| `resource_type == summary` | `summary_agent` |
| `resource_type == kg` |  `kg_agent`（知识图谱构建） |
| `null` / 其他 | `recommend_agent`（降级到推荐） |

## 执行流程

```
1.预设检查 - 若 state.resource_type 和 state.kp_id 已预设，直接返回（跳过 LLM）
2.构建画像上下文 - profile_ctx = build_profile_context(state.profile)
3.意图分类（仅在有 chat_history 时执行）：
  取最近 6 轮历史 + 当前消息
  调用 LLM 判断 generate vs clarify
  若为 clarify，写入 intent_type="clarify"，返回（路由到 clarify_agent）
  否则写入 intent_type="generate"，继续
4.获取可用知识点列表 - 从 KGNode 表查询，注入到 Prompt 帮助 LLM 选择
5.调用 LLM 分析意图：
  构造 System Prompt（含知识点列表）
  注入 chat_history，帮助理解"再来一个"、"换成代码"等指代
  注入 profile_ctx + user_message
  LLM 返回 {"resource_type": "...", "kp_id": "...", "extra_types": [...]}
6.解析 LLM 输出：
  设置 resource_type（解析失败默认 doc）
  设置 kp_id（空则截取 user_message[:50]）
  解析 extra_types：验证合法性，存入 metadata["extra_resource_types"]
7.记录日志 - 打印 resource_type 和 kp_id
```

## **独立功能：智能资源规划**

**`plan_resource_types(user_id, kp_id, db) -> list[ResourceType]`**

独立于 LangGraph 的 LLM 调用，根据用户画像和知识点推荐 2-3 种资源类型组合。

- 获取用户画像（专业/目标/认知风格/薄弱点）
- 获取知识点名称（从 KGNode 查询）
- 调用 SMART_PLAN_PROMPT LLM 推荐
- 返回 `ResourceType` 列表（默认 `[doc, quiz]`）

**推荐规则**：

- 认知风格 → 视觉型优先 mindmap，阅读型优先 doc，动手型优先 code
- 薄弱知识点 → 优先 quiz + doc
- 复习阶段 → 优先 summary + mindmap
- 编程相关 → 优先 code

## 依赖关系

- **上游**：ProfileAgent（提供 profile 信息）
- **下游**：
    - `intent_type="clarify"` → clarify_agent
    - `intent_type="generate"` → 根据 resource_type 路由到具体生成 Agent / kg_agent / recommend_agent
