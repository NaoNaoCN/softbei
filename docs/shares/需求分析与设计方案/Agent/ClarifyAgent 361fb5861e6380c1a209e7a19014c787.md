# **ClarifyAgent - 追问澄清智能体**

## **概述**

ClarifyAgent 负责回答学生的追问和解释请求。当学生对之前的对话内容进行追问时，PlannerAgent 会将其路由到 ClarifyAgent，而不是重新生成资源。

## **核心职责**

1. **上下文理解** - 结合对话历史理解学生的追问意图
2. **精准回答** - 调用 LLM 生成针对性的解释和补充
3. **对话延续** - 保持对话连贯性，不中断学习流程

## **System Prompt**

```
你是一位智能学习助手。学生正在对之前的对话内容进行追问或要求解释。
对话历史：{chat_history}
学生的最新问题：{user_message}
请根据对话历史，回答学生的最新问题。要求：- 紧密结合之前的对话上下文- 回答简洁清晰，适合学习场景- 如果学生询问某个知识点，请提供简明扼要的解释- 不要重新生成完整的学习资源（文档/测验等），只回答问题
```

## **输入与输出**

### **输入（AgentState）**

| 字段 | 说明 |
| --- | --- |
| `user_message` | 学生的最新追问 |
| `chat_history` | 完整对话历史 |
| `profile` | 学生画像（可选，用于调整回答风格） |

### **输出（AgentState 更新）**

| 字段 | 说明 |
| --- | --- |
| `final_content` | 回答内容 |
| `clarify_message` | 回答内容（与 final_content 一致） |

## **执行流程**

1. **提取对话历史**：
    - 从 `state.chat_history` 获取完整对话上下文
2. **构造 Prompt**：
    - 填充 `chat_history` 和 `user_message`
    - 强调"不要重新生成资源，只回答问题"
3. **调用 LLM**：
    - `temperature=0.7`（适度随机性，回答更自然）
    - `max_tokens=1000`（控制回答长度）
4. **写入 state**：
    - `final_content` = 回答内容
    - `clarify_message` = 回答内容
5. **异常兜底**：
    - LLM 调用失败 → 写入友好提示

## **依赖关系**

- **上游**：PlannerAgent（意图判断为 clarify 时路由）
- **下游**：图的终点（END，直接返回给用户）
