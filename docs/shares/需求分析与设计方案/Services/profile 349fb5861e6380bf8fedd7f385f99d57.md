# profile.py 调用关系详解

> 文件路径：`backend/services/profile.py`
本文档说明其中五个公开函数的**输入来源、输出去向、以及每个调用方的具体使用方式**。

## 涉及的数据库表

| 表名 | ORM 类 | 说明 |
| --- | --- | --- |
| `student_profile` | `StudentProfile` | 每个用户一条记录，存储当前最新画像（`user_id` 唯一约束） |
| `profile_history` | `ProfileHistory` | 每次更新时插入一条快照，`snapshot` 字段为 JSON，`version` 通过历史条数推算 |

## 一、`get_profile()` — 查询当前画像

### 函数签名

```python
async def get_profile(
    user_id: uuid.UUID,   # 目标用户 ID
    db: AsyncSession,     # SQLAlchemy 异步会话
) -> Optional[StudentProfileOut]
# 返回：当前画像对象，若用户尚未建立画像则返回 None
```

### 调用方：`GET /profile` 路由

**文件**：`backend/main.py:124`

| 项目 | 内容 |
| --- | --- |
| **输入 user_id** | 来自 HTTP 查询参数 `?user_id=<uuid>`，由前端 Streamlit 在登录后从 session_state 中读取并附带 |
| **输入 db** | FastAPI `Depends(get_session)` 注入的异步数据库会话 |
| **输出** | `StudentProfileOut`（含 id/user_id/version/updated_at 等完整字段），若为 None 则路由抛出 404 |
| **输出用途** | 直接序列化为 JSON 返回给前端；Streamlit 的画像页面（`streamlit_app/pages/profile.py`）用此数据渲染 8 维画像表单 |

**数据流**：

```
前端 GET /profile?user_id=<uuid>
  → main.py:get_profile()
    → profile_svc.get_profile(user_id, db)
      → SELECT * FROM student_profile WHERE user_id = ?
        → StudentProfileOut 或 None
          → 若 None → HTTP 404
          → 若有值 → JSON 响应给前端
```

## 二、`create_or_update_profile()` — 手动创建或更新画像

### 函数签名

```python
async def create_or_update_profile(
    user_id: uuid.UUID,
    data: StudentProfileIn,   # 用户提交的画像字段（全量或部分）
    db: AsyncSession,
) -> StudentProfileOut
# 返回：更新后的完整画像对象
```

### 调用方：`PUT /profile` 路由

**文件**：`backend/main.py:135`

| 项目 | 内容 |
| --- | --- |
| **输入 user_id** | 来自 HTTP 查询参数，同上 |
| **输入 data** | 请求体 `StudentProfileIn`，由前端画像编辑表单提交，包含 8 个可选字段（major/learning_goal/cognitive_style/daily_time_minutes/knowledge_mastered/knowledge_weak/error_prone/current_progress） |
| **输入来源** | Streamlit 画像页面的表单控件（下拉框、文本输入、多选标签等），用户手动填写后点击”保存” |
| **内部操作** | UPSERT `student_profile` 表（若已存在则更新，否则插入）；同时向 `profile_history` 插入一条快照（`snapshot` = 当前画像的 JSON 序列化，`version` 自增） |
| **输出** | 更新后的 `StudentProfileOut`（含新的 `version` 和 `updated_at`） |
| **输出用途** | 路由直接返回给前端，Streamlit 用于刷新页面上的画像展示 |

**数据流**：

```
前端 PUT /profile  body: {"major":"计算机","learning_goal":"掌握深度学习",...}
  → main.py:update_profile()
    → profile_svc.create_or_update_profile(user_id, StudentProfileIn(...), db)
      → UPSERT student_profile SET major=?, learning_goal=?, ... WHERE user_id=?
      → INSERT INTO profile_history (profile_id, snapshot) VALUES (?, ?)
        → StudentProfileOut（含最新 version）
          → JSON 响应给前端
```

## 三、`get_profile_history()` — 查询画像历史版本

### 函数签名

```python
async def get_profile_history(
    user_id: uuid.UUID,
    db: AsyncSession,
    limit: int = 10,   # 最多返回条数
) -> list[StudentProfileOut]
# 返回：按时间倒序的历史画像列表
```

### 调用方：`GET /profile/history` 路由

**文件**：`backend/main.py:145`

| 项目 | 内容 |
| --- | --- |
| **输入 user_id** | 来自 HTTP 查询参数 |
| **输入 limit** | 路由目前使用默认值 10，未暴露为查询参数 |
| **内部操作** | 查询 `profile_history` 表，按 `created_at DESC` 排序，将每条 `snapshot` JSON 反序列化为 `StudentProfileOut` |
| **输出** | `list[StudentProfileOut]`，每项代表一个历史版本快照 |
| **输出用途** | 前端画像页面的”历史版本”面板，用于展示画像演变时间线，支持用户回溯或对比不同时期的学习状态 |

**数据流**：

```
前端 GET /profile/history?user_id=<uuid>
  → main.py:get_profile_history()
    → profile_svc.get_profile_history(user_id, db, limit=10)
      → SELECT * FROM profile_history
          WHERE profile_id = (SELECT id FROM student_profile WHERE user_id=?)
          ORDER BY created_at DESC LIMIT 10
        → list[StudentProfileOut]（历史快照列表）
          → JSON 数组响应给前端
```

## 四、`merge_chat_updates()` — 对话驱动的画像增量更新

### 函数签名

```python
async def merge_chat_updates(
    user_id: uuid.UUID,
    updates: dict,       # 从对话中提取的画像字段（仅含非 None 字段）
    db: AsyncSession,
) -> StudentProfileOut
# 返回：合并后的最新画像对象
```

### 调用方：`profile_agent.run()`

**文件**：`backend/agents/profile_agent.py:43`

| 项目 | 内容 |
| --- | --- |
| **输入 user_id** | `UUID(state.user_id)`，从 LangGraph `AgentState` 中取出，最初由 `/chat/{session_id}` 路由传入 |
| **输入 updates** | `json.loads(raw_json)` 的结果，即 `chat_completion` 从用户消息中提取的画像字段 dict，例如 `{"major": "计算机", "knowledge_weak": ["反向传播"], "learning_goal": null}` |
| **关键逻辑** | 只更新 `updates` 中值不为 `None` 的字段，保留数据库中已有的其他字段不变（增量合并，而非全量覆盖） |
| **内部操作** | 先 `get_profile()` 读取当前画像 → 用updates中的非 None 字段覆盖 → 调用 `create_or_update_profile()` 保存（同时写入历史快照） |
| **输出** | 合并后的 `StudentProfileOut` |
| **输出用途** | 写回 `state.profile`，供后续 `planner_agent` 和各生成 Agent 使用（通过 `build_profile_context` 注入 prompt） |

**数据流**：

```
用户输入："我是计算机专业大三，反向传播学得不好"
  → profile_agent: chat_completion(messages, temperature=0.3)
    → {"major":"计算机","knowledge_weak":["反向传播"],"learning_goal":null,...}
      → json.loads() → updates dict（仅含非 None 字段）
        → merge_chat_updates(user_id, updates, db)
          → get_profile() → 当前画像
          → 合并：只覆盖 major 和 knowledge_weak，其余字段保持不变
          → create_or_update_profile() → UPSERT + 写历史快照
            → StudentProfileOut（最新合并结果）
              → state.profile（供后续 Agent 使用）
```

## 五、`build_profile_context()` — 画像序列化为 Prompt 字符串

### 函数签名

```python
async def build_profile_context(
    profile: StudentProfileOut,   # 当前画像对象
) -> str
# 返回：自然语言描述的画像摘要字符串
```

### 调用方 1：`planner_agent.run()`

**文件**：`backend/agents/planner_agent.py:34`

| 项目 | 内容 |
| --- | --- |
| **输入 profile** | `state.profile`，来自 profile_agent 更新后的最新画像 |
| **输出示例** | `"学生专业：计算机，学习目标：掌握深度学习基础，认知风格：visual，薄弱点：反向传播、梯度消失"` |
| **输出用途** | 拼接到 `planner_agent` 的 user message 中，让 LLM 在判断资源类型时能感知学生背景，例如对 `practice` 风格的学生优先推荐 `code` 类型资源 |

**数据流**：

```
state.profile (StudentProfileOut)
  → build_profile_context(profile)
    → "学生专业：计算机，薄弱点：反向传播..."
      → messages = [system_prompt, user_message + profile_ctx]
        → chat_completion(messages)
          → {"resource_type":"code","kp_id":"kp_05"}
```

### 调用方 2：`code_agent.run()`

**文件**：`backend/agents/code_agent.py:42`

| 项目 | 内容 |
| --- | --- |
| **输入 profile** | `state.profile`，同上 |
| **输出用途** | 注入 `code_agent` 的 `SYSTEM_PROMPT` 中的 `{profile_summary}` 占位符，让 LLM 根据学生专业和认知风格调整代码示例的语言选择、注释详细程度和难度 |

**数据流**：

```
state.profile
  → build_profile_context(profile) → profile_summary 字符串
    → SYSTEM_PROMPT.format(context=context, kp_name=..., profile_summary=profile_summary)
      → chat_completion(messages)
        → 适配该学生的代码示例 Markdown
          → state.draft_content
```

## **六、`refresh_learning_goal()` — 后台异步刷新学习目标**

### **函数签名**

```python
async def refresh_learning_goal(    
		user_id: uuid.UUID,    
		questions: Optional[list[str]] = None,
) -> None
```

### **调用方**

**文件**：`backend/services/profile.py:297`

| 项目 | 内容 |
| --- | --- |
| **触发时机** | `merge_chat_updates()` 发现 `goal_questions` 有新增时自动触发 |
| **输入 user_id** | 用户 UUID |
| **输入 questions** | 可选。若传入则直接使用（绕过事务可见性）；否则从 DB 重读 |
| **内部操作** | 调用 `_summarize_learning_goal()` → LLM 概括历史提问为一句话学习目标 → 写回 `student_profile.learning_goal` |
| **输出** | 无（内部写入 DB） |
| **输出用途** | 异步将历史提问列表概括为一句话学习目标，写回 `student_profile.learning_goal`，不阻塞对话接口 |

**数据流**：

```
merge_chat_updates(user_id, updates, user_message)
  → 检测 goal_questions 有新增
    → _schedule_refresh_learning_goal(user_id, new_questions)
      → loop.create_task(refresh_learning_goal(user_id, questions))
        → fire-and-forget，不阻塞主流程

refresh_learning_goal(user_id, new_questions)
  → 0.2 秒延迟（等待调用方 session 提交）
  → SELECT student_profile WHERE user_id = ?
  → 获取 goal_questions 历史列表
  → _summarize_learning_goal(final_questions)
    → 构建 prompt（历史提问编号列表）
    → chat_completion([{"role": "user", "content": prompt}], temperature=0.3)
    → LLM 输出一句话概括（如 "掌握深度学习核心算法"）
  → UPDATE student_profile SET learning_goal = "掌握深度学习核心算法"
  → commit
```

## 七、整体数据流总览

```
用户手动填写画像表单
  → PUT /profile (body: StudentProfileIn)
    → create_or_update_profile()
      → UPSERT student_profile + INSERT profile_history
        → StudentProfileOut → 前端刷新展示

用户发送对话消息
  → POST /chat/{session_id}
    → profile_agent
      → chat_completion() → 提取画像字段 dict
        → merge_chat_updates()
          → 读当前画像 → 增量合并 → UPSERT + 写历史快照
            → state.profile (StudentProfileOut)
              ├─→ planner_agent: build_profile_context() → 注入意图分析 prompt
              └─→ code_agent:   build_profile_context() → 注入代码生成 prompt

用户查看历史
  → GET /profile/history
    → get_profile_history()
      → SELECT profile_history ORDER BY created_at DESC
        → list[StudentProfileOut] → 前端时间线展示
```
