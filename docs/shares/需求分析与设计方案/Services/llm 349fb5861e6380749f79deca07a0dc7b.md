## 一、`chat_completion()` — 非流式 LLM 调用

### 函数签名

```python
async def chat_completion(
    messages: list[dict],   # OpenAI 格式消息列表
    model: Optional[str],   # 模型名，None 则用 provider 默认值
    temperature: float,     # 默认 0.7
    max_tokens: int,        # 默认 2048
    provider: Optional[str] # "spark"|"deepseek"|"qwen"|"openai"，None 读环境变量
) -> str                    # 返回模型输出的纯文本
```

### 被哪些 Agent 调用

所有生成类 Agent 都通过 `chat_completion` 驱动 LLM，目前代码以 TODO 注释形式标注，实现时取消注释即可。

### 1. `profile_agent.run()` — 提取学生画像

**文件**：`backend/agents/profile_agent.py:41`

| 项目 | 内容 |
| --- | --- |
| **输入 messages** | `[{"role":"system","content":SYSTEM_PROMPT}, {"role":"user","content":state.user_message}]` |
| **输入来源** | `state.user_message` = 用户在聊天框输入的自然语言（如”我是计算机专业大三，想学深度学习”） |
| **调用参数** | `temperature=0.3`（低温，保证 JSON 格式稳定） |
| **输出** | 一段 JSON 字符串，包含 8 个画像字段（major/learning_goal/cognitive_style 等） |
| **输出用途** | `json.loads(raw_json)` 解析后调用 `profile_service.merge_chat_updates()` 更新数据库，并写回 `state.profile` |

**数据流**：

```
用户输入 → state.user_message
  → chat_completion(messages, temperature=0.3)
    → JSON字符串 {"major":"...", "learning_goal":"...", ...}
      → json.loads() → dict
        → merge_chat_updates() → 写入 student_profile 表
          → state.profile (StudentProfileOut)
```

### 2. `planner_agent.run()` — 解析意图，规划资源类型

**文件**：`backend/agents/planner_agent.py:36`

| 项目 | 内容 |
| --- | --- |
| **输入 messages** | `[system_prompt, user_message + profile_ctx]`，其中 `profile_ctx` 是学生画像的文本摘要 |
| **输入来源** | `state.user_message`（用户请求）+ `state.profile`（当前画像，来自 profile_agent 或数据库） |

**数据流**：

```

  → chat_completion(messages)
    → JSON字符串 {"resource_type":"quiz","kp_id":"kp_05"}
      → state.resource_type = ResourceType.quiz
      → state.kp_id = "kp_05"
        → route_by_resource_type() → 路由到 quiz_agent
```

### 3. `doc_agent.run()` — 生成学习文档

**文件**：`backend/agents/doc_agent.py:43`

| 项目 | 内容 |
| --- | --- |
| **输入 messages** | `[{"role":"system","content": SYSTEM_PROMPT.format(context=context, kp_name=...)}, {"role":"user","content":"请生成文档"}]` |
| **输入来源** | `context` = `retriever.format_context(chunks)`，即从 ChromaDB 检索到的相关文档片段（已格式化为带编号引用的字符串） |
| **调用参数** | 默认 temperature=0.7，max_tokens=2048 |
| **输出** | Markdown 格式的学习文档字符串（含标题、正文、例子、小结、引用编号） |
| **输出用途** | 写入 `state.draft_content`，传递给 `safety_agent` 做幻觉检测 |

**数据流**：

```
state.kp_id
  → retrieve_by_kp(kp_id) → list[RetrievedChunk]
    → format_context(chunks) → context 字符串（含[1][2]引用）
      → chat_completion([system+context, user])
        → Markdown 文档字符串
          → state.draft_content
            → safety_agent
```

### 8. `safety_agent.run()` — 幻觉检测与内容审核

**文件**：`backend/agents/safety_agent.py:50`

| 项目 | 内容 |
| --- | --- |
| **输入 messages** | `[system_prompt.format(context=retrieved_docs前3条, draft=state.draft_content)]` |
| **输入来源** | `state.draft_content`（上游生成 Agent 的输出）+ `state.retrieved_docs`（RAG 检索的原始文本，作为”真实参考”） |
| **调用参数** | `temperature=0.1`（极低温，保证审核结论稳定、不随机）      `max_tokens300`只需返回 passed + issues，300 token 足够 |
| **输出** | JSON 字符串：`{"passed": true/false, "issues": [...], "revised_content": "...或null"}` |
| **输出用途** | `json.loads()` 后：`state.safety_passed = result["passed"]`；`state.final_content = revised_content or draft_content`；`final_content` 最终返回给前端 |

**文件：`backend/agents/recommend_agent.py`**

| 项目 | 内容 |
| --- | --- |
| **输入来源** | `state.profile`（画像）、`state.kp_id`（当前知识点）、`state.user_id`（用户 ID，用于 KG 查询过滤） |
| **输入 messages** | `[{"role": "user", "content": prompt（含 profile/mastered/weak/goal/available_kps）}]` |


## 二、`stream_chat_completion()` — 流式 LLM 调用

### 函数签名

```python
async def stream_chat_completion(
    messages: list[dict],
    model: Optional[str],
    temperature: float,
    max_tokens: int,
    provider: Optional[str]
) -> AsyncGenerator[str, None]   # 逐 token yield 文本片段
```

### 调用链

目前 Agent 层尚未实现流式调用，但 FastAPI 路由已搭好完整的 SSE 框架：

```
用户请求 POST /chat/{session_id}?stream=true
  → main.py:chat() (backend/main.py:169)
    → stream_invoke(user_id, session_id, body.content)
      → agents/graph.py:stream_invoke()
        → （各 Agent 实现后，内部调用 stream_chat_completion）
          → AsyncGenerator[str]
            → event_generator() 包装为 SSE 格式 "data: {token}\n\n"
              → FastAPI StreamingResponse(media_type="text/event-stream")
                → Streamlit 前端 st.write_stream() 实时渲染
```

**输入**：与 `chat_completion` 完全相同的 `messages` 列表

**输出**：不是一次性返回完整字符串，而是每次 `yield` 一个 token 片段（如 `"深"` `"度"` `"学"` `"习"`），前端拼接后显示打字效果

**与 `chat_completion` 的选择原则**：
- 需要解析 JSON 结构（profile_agent、planner_agent、safety_agent）→ 用 `chat_completion`，等完整输出后再 `json.loads()`
- 需要实时展示给用户（doc/mindmap/code/summary 的对话场景）→ 用 `stream_chat_completion`

## 三、`get_embedding()` — 文本向量化

### 函数签名

```python
async def get_embedding(text: str) -> list[float]
# 返回：768 或 1024 维浮点向量（取决于模型）
```

### 调用方 1：`indexer._embed_batch()` — 知识库入库

**文件**：`backend/rag/indexer.py:83`

| 项目 | 内容 |
| --- | --- |
| **输入 text** | 单个文本块的内容字符串（来自 `TextChunk.text`，由 `loader.split_text()` 切分，每块约 512 字符） |
| **输入来源** | `index_directory(dir_path)` → `load_directory()` → `split_text()` → `TextChunk` 列表 |
| **并发控制** | `asyncio.Semaphore(8)`，最多 8 个并发嵌入请求，避免 API 限流 |
| **输出** | `list[float]`，即该文本块的语义向量 |
| **输出用途** | 传入 `upsert_documents(embeddings=[...])` 写入 ChromaDB，与文本内容、元数据一起持久化 |

**数据流**：

```
knowledge_base/ai_intro/chapters/*.pdf|md|docx
  → load_directory() → list[TextChunk]（每块约512字符）
    → _embed_batch([chunk.text, ...])
      → get_embedding(text) × N（最多8并发）
        → list[list[float]]（每个文本块的向量）
          → upsert_documents(ids, documents, embeddings, metadatas)
            → ChromaDB 持久化存储
```

---

### 调用方 2：`retriever.retrieve()` — 语义检索

**文件**：`backend/rag/retriever.py:52`

| 项目 | 内容 |
| --- | --- |
| **输入 text** | 用户的查询字符串，或 `"知识点：{kp_name}"` 格式的检索词 |
| **输入来源** | 各生成 Agent 调用 `retrieve_by_kp(state.kp_id)` 时传入知识点名称 |
| **输出** | `list[float]`，查询向量 |
| **输出用途** | 传入 `query_documents(query_embedding=embedding, n_results=5)` 在 ChromaDB 中做余弦相似度搜索，返回最相关的文本块 |

**数据流**：

```
state.kp_id（如 "kp_03"）
  → retrieve_by_kp("知识点：反向传播")
    → retrieve(query="知识点：反向传播")
      → get_embedding("知识点：反向传播")
        → list[float]（查询向量）
          → query_documents(query_embedding=..., n_results=5)
            → ChromaDB 余弦相似度搜索
              → list[RetrievedChunk]（按相似度降序，过滤 score < 0.5）
                → format_context(chunks) → context 字符串
                  → 注入各生成 Agent 的 SYSTEM_PROMPT
```

## 四、整体数据流总览

```
用户输入 (user_message)
    │
    ▼
profile_agent ──── chat_completion(temperature=0.3) ──→ 更新 state.profile
    │
    ▼
planner_agent ──── chat_completion() ──────────────────→ state.resource_type, state.kp_id
    │
    ▼ (按 resource_type 路由)
┌───┴────────────────────────────────────────────┐
│  doc/mindmap/quiz/code/summary _agent           │
│    ├─ retrieve_by_kp(kp_id)                     │
│    │    └─ get_embedding(query) → ChromaDB 检索 │
│    └─ chat_completion(context+prompt)           │
│         └─→ state.draft_content                 │
└───────────────────────────────────────────────-┘
    │
    ▼
safety_agent ───── chat_completion(temperature=0.1) ──→ state.final_content
    │
    ▼
recommend_agent
    │
    ▼
FastAPI 返回 / SSE 流式推送 → Streamlit 前端渲染
```
