# 知识图谱渲染与显示逻辑分析

> 分析对象：`frontend/pathway.html` 知识图谱展示页面
> 渲染引擎：ECharts `graph` 类型 + `force` 力导向布局
> 后端接口：`backend/main.py` `GET /kg/graph`

## 一、总体架构

知识图谱位于 `frontend/pathway.html`，与「学习路径」「学习计划」共用一个页面，通过 tab 切换。数据流如下：

```
后端 /kg/graph  →  api.js getKgGraph()  →  loadKgGraph()  →  applyFilters()  →  renderGraph()  →  ECharts
```

| 阶段 | 函数 / 位置 | 职责 |
|------|------------|------|
| 数据获取 | `getKgGraph()` `api.js:207` | 拼接 query 参数请求 `/kg/graph` |
| 数据加载 | `loadKgGraph()` `pathway.html:1230` | 读取工具栏参数、填充根节点选择器、触发过滤 |
| 过滤 | `applyFilters()` `pathway.html:1277` | 按搜索词过滤节点与边 |
| 渲染 | `renderGraph()` `pathway.html:1532` | 构建 ECharts option |
| 缩放自适应 | `updateVisibilityByZoom()` `pathway.html:1476` | 按缩放级别控制节点显隐 |

## 二、数据来源（后端 `GET /kg/graph`，`backend/main.py:1008`）

返回 `KGGraphOut { nodes, edges }`，源自 `KGNode` / `KGEdge` 两张表。

### 节点层级（5 层）

```
Course → Chapter → KnowledgePoint → SubPoint → Concept
```

### 关键查询逻辑

- **`depth` 参数下推到 DB**：`allowed_types = type_levels[:depth]`，只查所需层级，避免全量加载。
- **用户隔离**：`KGNode.user_id == user_id OR user_id IS NULL`（私有节点 + 公共节点）。
- **两种查询路径**：
  - 有 `root_id`：加载全部节点建邻接表 → 沿 `IS_PART_OF`/`CONTAINS` 关系 BFS 找整棵子树 → 再按 `depth` 类型过滤。
  - 无 `root_id`：直接按 `node_type IN allowed_types` 过滤（更省）。
- **边过滤**：只保留两端节点都在可见集合（`reachable`）内的边。

### 字段链路注意点

`KGNodeOut` 中 `difficulty=None`、`is_core=False` 是写死的，`extra` 只塞了 `description`。因此前端拿不到难度/核心标记，无法据此调整视觉权重。

## 三、前端渲染核心（`renderGraph` `pathway.html:1532`）

### 视觉编码映射表（`pathway.html:1155`–`1206`）

| 类型 | 颜色 | 尺寸 | 边宽 | zoom 阈值 |
|------|------|------|------|-----------|
| Course | 蓝 `#5B8DB8` | 90 | 7 | 0.0（始终显示）|
| Chapter | 绿 `#6BA389` | 55 | 4 | 0.1 |
| KnowledgePoint | 橙 `#D4956A` | 30 | 2.0 | 0.3 |
| SubPoint | 紫 `#9B85B2` | 20 | 1.2 | 0.5 |
| Concept | 红 `#C27E7E` | 10 | 0.5 | 1.0 |

### 节点构建

- 按类型上色（`nodeTypeColor`）+ 阴影发光（`nodeTypeShadow`）。
- `category` 字段用于 ECharts 图例分组。
- 记录原始状态字段：`_baseSize`、`_baseOpacity`、`_learned` —— 用于多次 `setOption` 时保持状态不丢失。

### 边构建

- **边长按关系类型差异化**（`edgeLengthByRelation` `pathway.html:1624`）：

  | 关系 | 边长策略 |
  |------|---------|
  | `IS_PART_OF` → Course | 380（让章节集群分散）|
  | `IS_PART_OF` → Chapter | 160（KP/子点贴近章节）|
  | `REQUIRES` | 220 |
  | `RELATED_TO` | 260 |
  | `CONTAINS` | 160 |

- 用差异化边长制造层次感与集群分布。
- 有向图：`edgeSymbol: ['circle', 'arrow']`。

### 力导向参数

```js
force: {
    repulsion: 500,
    gravity: 0.05,
    edgeLength: [80, 380],
    friction: 0.6,
    layoutAnimation: true,
}
```

## 四、四个交互维度（叠加在 renderGraph 上）

1. **类型过滤（图例 chips）**：靠 ECharts `legendToggleSelect` action，`toggleLegendType()` `pathway.html:1146`。
2. **已学习高亮（`kg-learned-toggle`）**：`learnedKpIds` 来自学习记录（action 为 `complete`/`quiz`）。已学节点用 `boostColor()` 提亮加描边，未学节点 `opacity:0.15` 弱化。
3. **学习路径叠加（`kg-pathway-overlay`）**：把某条路径的节点标成 `completed`（绿）/`current`（橙放大）/`planned`（棕），非路径节点 `opacity:0.4`。
4. **明/暗背景切换（`kg-bg-toggle`）**：影响 label 颜色与画布渐变背景。

## 五、Zoom 自适应可见性（`updateVisibilityByZoom` `pathway.html:1476`）

这是最精巧、也最易出 bug 的部分。每次缩放/漫游触发：

- 按 `currentZoom` 与 `zoomThresholds` 比较，决定每个节点是否「可见」。
- 缩小时低层级节点（Concept/SubPoint）渐隐：缩小尺寸 + 降透明度 + 隐藏 label。
- 连接到隐藏节点的边 `opacity:0`。
- 用 `_baseSize`/`_baseOpacity`/`_learned` 等下划线字段记住原始状态，避免反复 `setOption` 时状态丢失。

> **风险点**：`currentZoom` 是手动维护的（`graphRoam` 事件里 `currentZoom *= params.zoom` 累乘），与 ECharts 内部 zoom 可能漂移，导致状态不同步。

## 六、搜索与聚焦（`pathway.html:1327`–`1474`）

- `performSearch()`：名称匹配 → `highlightSearchResults()`（橙色描边放大 + 其余 dim 到 0.3）→ `focusOnNode()` 平移到第一个匹配 → 弹出详情面板。
- `applyFilters()` 里搜索会**带出直接邻居**（`pathway.html:1294`），保证匹配点不孤立。
- `clearSearchHighlight()` 用 `_searchHighlight` 标记位还原样式。

## 七、节点详情面板（`showDetailPanel` `pathway.html:1818`）

点击节点（`handleNodeClick`）或点表格行（`_handleNodeGridClick`）触发，侧滑面板展示：

- 名称、类型、ID、描述。
- **关联关系**：从 edges 反查，带 →/← 方向。
- **关联资源**：异步 `getResources({kp_id})`，按 `resource_type` 配图标，quiz 跳 `evaluate.html`、其他跳 `library.html`。
- 底部动作：「生成学习资源」（跳 `generate.html`）、「加入学习路径」。

## 八、值得关注的问题

1. **双重过滤冗余**：后端已按 `depth` 过滤类型，前端 `applyFilters` 又用 `categoryList` 全集过滤（`pathway.html:1281` `allTypes` 永远是全部），实际类型隐藏完全交给了 ECharts 图例，这层 filter 是空操作。

2. **`difficulty`/`is_core` 字段链路断裂**：后端写死，前端 `nodeTypeSize` 纯按类型，无法体现知识点重要度。

3. **`currentZoom` 手动累乘**与 ECharts 内部缩放可能不一致，缩放层级显隐在极端操作下可能错位。

4. **大图性能**：`updateVisibilityByZoom` 每次 roam 都 `getOption()` + 全量 `map` + `setOption`，节点多时（数百+）漫游会卡顿。

5. **搜索 dim 的还原色**依赖 `kg-bg-toggle` 当前值，若搜索期间切背景再清除高亮，label 颜色可能不对。
