## 五、力导向参数错误（忽略动态自适应逻辑）

文档声称参数为静态值：

```js
force: {
    repulsion: 500,
    gravity: 0.05,
    edgeLength: [80, 380],
    friction: 0.6,
    layoutAnimation: true,
}
```

实际代码（`pathway.html:1583-1587, 1622`）根据节点数量**动态调整** repulsion 和 gravity，其余参数也与文档不符：

```
nCount < 50:   repulsion = 180, gravity = 0.12
nCount < 150:  repulsion = 280, gravity = 0.08
nCount < 300:  repulsion = 400, gravity = 0.05
nCount >= 300: repulsion = 600, gravity = 0.03

固定值: edgeLength = [40, 120], friction = 0.5
```

文档中 `edgeLength: [80, 380]` 和 `friction: 0.6` 均不存在。

## 六、边长度策略完全错误

文档声称存在 `edgeLengthByRelation` 对象，按关系类型设置不同边长：

| 关系 | 文档声称边长 |
|------|------------|
| IS_PART_OF -> Course | 380 |
| IS_PART_OF -> Chapter | 160 |
| REQUIRES | 220 |
| RELATED_TO | 260 |
| CONTAINS | 160 |

**实际代码中根本不存在 `edgeLengthByRelation`**（grep 全文件无匹配）。

实际逻辑（`pathway.html:1572`）仅按两端节点是否同类型区分：

```js
edgeLength: sameType ? 60 : 100
```

即同类型节点边长 60，跨类型节点边长 100，与关系类型无关。

## 八、确认正确的部分

1. **总体架构**：数据流 `/kg/graph` -> `getKgGraph()` -> `loadKgGraph()` -> `applyFilters()` -> 渲染 -> ECharts，架构描述正确

5. **用户隔离**：`user_id IS NULL OR user_id == user_id` 逻辑正确
6. **BFS 子树查询**：有 root_id 时通过邻接表 BFS 找全部子孙节点，再按 depth 类型过滤，逻辑正确
7. **两种查询路径**（有 root_id / 无 root_id）的描述正确
8. **`difficulty=None`、`is_core=False` 在后端写死**：`main.py:1136-1137` 确实硬编码，文档对此问题的分析正确

10. **Zoom 自适应概念**和 `_baseSize` / `_baseOpacity` / `_learned` 等下划线字段的状态保持机制描述正确
11. **第四节四个交互维度**（类型过滤、已学习高亮、路径叠加、明暗背景切换）对应实际功能
