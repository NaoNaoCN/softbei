# 学习计划表（Study Plan）功能设计文档

> 最后更新：2026-06-04 | 代码：`backend/services/study_plan/` | 测试：`tests/test_study_plan.py` | 迁移：`migrations/versions/c3d4e5f6a7b8_add_study_plan.py`

---

## 一、一句话概述

学习计划表（学习计划表 / Study Plan）基于**学生画像**和**已有学习路径**，自动生成一份按日期排程的个性化学习安排——汇总待学知识点，用 LLM 排出学习顺序并预估时长，再按每日学习时间预算把任务铺到连续日期上，并为每个任务关联用户已生成的学习资源。形态是"日期 + 可选时段"的混合结构：有时段时像课表，无时段时像任务清单。

---

## 二、为什么需要它？

系统已经能生成单个知识点的学习资源（doc/quiz/mindmap…），也能维护知识点序列（`LearningPath`），但缺少一个把"学什么、什么时候学、用什么资源学"串起来的**时间维度规划**。学生面对一堆零散的知识点和资源，仍然不知道今天该学哪个、要花多久。

学习计划表填补的就是这一层：

| 已有能力 | 缺口 | 学习计划表的补充 |
|----------|------|------------------|
| 资源生成（`/generate`） | 不知道何时学、按什么顺序学 | 把知识点排程到具体日期 |
| 学习路径（`LearningPath`） | 只有顺序，无时间、无时长 | 按每日预算装箱 + 时长预估 |
| 学生画像（`StudentProfile`） | 薄弱点/每日时长未被利用 | 薄弱点优先 + 按 `daily_time_minutes` 排程 |
| 学习资源（`ResourceMeta`） | 资源与计划脱节 | 计划项自动关联已有资源 |

---

## 三、设计决策

四个核心决策（决定了数据模型与模块边界）：

| 维度 | 选择 | 理由 |
|------|------|------|
| **计划表形态** | 日期 + 可选时段（混合） | 同一份数据，有时段按课表渲染、无时段按清单渲染，最灵活 |
| **生成算法** | LLM + 确定性排程（混合） | LLM 负责排序/时长（智能），纯代码负责日历装箱（可控、可测） |
| **资源关联** | 匹配已有 + 按需懒生成 | 建表只关联已生成资源，缺失的标记"待生成"，点击时再触发，避免建表时大批量生成开销 |
| **知识点来源** | 汇总已有路径 + 画像补全 | 聚合用户全部学习路径知识点（去重），再用画像薄弱点补全缺口 |

---

## 四、数据模型

新增两张表，字段命名严格遵循项目规范（`created_at`/`updated_at`/`id`/`kp_id`/`title`）。

### `StudyPlan`（study_plan）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BigInteger PK | Snowflake ID |
| `user_id` | BigInteger FK→user.id | indexed |
| `title` | String(256) | 计划标题，如"个性化学习计划 · 数据结构" |
| `description` | Text? | 描述 |
| `goal` | Text? | 生成时 `learning_goal` 快照 |
| `start_date` / `end_date` | Date | 计划起止日期（end 由排程算出） |
| `daily_time_minutes` | Integer? | 生成时所用的每日学习预算快照 |
| `status` | String(16) | `active` / `archived` / `completed` |
| `source_path_ids` | JSON | 本计划聚合自哪些 `LearningPath` |
| `created_at` / `updated_at` | DateTime | |

### `StudyPlanItem`（study_plan_item）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | BigInteger PK | |
| `plan_id` | BigInteger FK→study_plan.id | indexed |
| `kp_id` | String(64) FK→kg_node.id, **可空** | 画像薄弱点可能尚未进入知识图谱 |
| `kp_name` | String(256) **必填** | 知识点名称快照，不依赖 KG 可解析性 |
| `scheduled_date` | Date | 该任务安排的日期 |
| `start_time` / `end_time` | String(5)? | "09:00"，可选时段 |
| `estimated_minutes` | Integer? | LLM 预估学习时长 |
| `order_index` | Integer | 当天内排序键 |
| `is_completed` | Boolean | 完成状态 |
| `resource_ids` | JSON | 已匹配的 `ResourceMeta` id 列表 |
| `missing_resource_types` | JSON | 待懒生成的类型，如 `["doc","quiz"]` |
| `notes` | Text? | LLM 给的学习提示/排序理由 |

> **关键设计**：`kp_id` 设为可空外键 + `kp_name` 必填快照。这让计划既能关联知识图谱节点，又能容纳画像里那些尚未进入图谱的薄弱点名称，二者不互斥。

## 五、生成流水线

`generate_study_plan()` 编排五个阶段，每个阶段是一个职责单一、可独立测试的子模块：

```
collect_candidates   →  sequence_candidates  →  schedule_items  →  link_resources  →  持久化
（候选知识点收集）        （LLM 排序+时长预估）     （确定性日历装箱）    （匹配已有资源）     （StudyPlan + Items）
   collector.py            sequencer.py            scheduler.py       resource_linker.py    service.py
```

### 1. collector.py — 候选知识点收集

- 汇总用户全部 `LearningPath` 的知识点（按 `order_index`，**去重保序**），已完成项标记 `is_mastered`。
- 画像 `knowledge_weak` 补全：按名称查 `KGNode`（本人优先、其次公共），匹配到则带 `kp_id`，否则保留纯名称（`kp_id=None`），标记 `is_weak`。
- `source="path"` 时只汇总指定路径，不做画像补全。
- 输出统一的 `CandidateKP` 列表。

### 2. sequencer.py — LLM 智能排序

- 用提示词 `agents.study_plan.sequence`（遵循 Role/Rules/Output 结构 + 防捏造规则）调用 LLM。
- 输入：画像上下文（复用 `profile_svc.build_profile_context`）+ 候选 KP 列表（带 mastered/weak 标记）。
- 输出严格 JSON：`[{kp_id, kp_name, estimated_minutes, priority, tip}]`，基础知识点排前、薄弱点优先、已掌握降权。
- **防捏造**：过滤 `kp_id` 不在候选集中的项；时长钳制到 `[min_kp_minutes, max_kp_minutes]`。
- **回退机制**：LLM 不可用或 JSON 解析失败 → 回退到确定性顺序（薄弱点提前、已掌握靠后）+ 默认时长，**不依赖 LLM 也能产出可用计划**；LLM 漏掉的候选会被补齐，知识点不丢失。

### 3. scheduler.py — 确定性日历装箱（纯函数）

- 不依赖 DB/LLM，是单测的重点对象。
- 贪心装箱：逐天累加 `estimated_minutes` 直到日预算，超出滚到下一天。
- **单点原子性**：单个知识点不跨天切分，单点时长超过日预算则独占一天。
- 指定 `days` 时按 `ceil(总时长 / 天数)` 抬高日预算，把计划压缩到目标天数。
- 给定 `default_start_hour` 时按当天累计偏移生成 `start_time`/`end_time`；否则时段留空（纯日期清单）。

### 4. resource_linker.py — 资源关联

- 单次 `IN` 查询批量拉取所有相关 `ResourceMeta`（同 user + kp_id），避免逐条查询。
- 每个知识点：已有资源 id → `resource_ids`；目标类型集 - 已有类型 → `missing_resource_types`。

### 5. service.py — 编排与持久化

- 批量 `insert` plan + `insert_many` items，单事务提交。
- 提供完整 CRUD + 序列化辅助（解析 `resource_ids` → 轻量资源引用）。

## 六、调用接口

模块通过 `backend/services/study_plan/__init__.py` 导出 6 个异步函数。所有函数接收 `db: AsyncSession`，并用 `user_id` 校验归属。

```python
import backend.services.study_plan as sp
```

| 函数 | 签名（省略 `db`） | 返回 | 说明 |
|------|-------------------|------|------|
| `generate_study_plan` | `(user_id, req: StudyPlanGenerateRequest)` | `StudyPlanOut?` | 跑完整流水线；候选为空返回 `None` |
| `get_study_plan` | `(plan_id, user_id)` | `StudyPlanOut?` | 单份计划（校验归属） |
| `list_study_plans` | `(user_id)` | `list[StudyPlanOut]` | 按创建时间倒序 |
| `update_study_plan` | `(plan_id, user_id, data: StudyPlanUpdate)` | `StudyPlanOut?` | 改标题/描述/状态 |
| `delete_study_plan` | `(plan_id, user_id)` | `bool` | 先删 items 再删 plan |
| `update_study_plan_item` | `(plan_id, item_id, user_id, data: StudyPlanItemUpdate)` | `StudyPlanItemOut?` | 改期/时段/完成/备注 |

### `StudyPlanGenerateRequest`

| 字段 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `source` | str | `"aggregate"` | `aggregate`=汇总全部路径+画像补全；`path`=只用指定路径 |
| `path_ids` | list[int] | `[]` | `source="path"` 时指定的路径 id |
| `start_date` | date? | 今天 | 计划起始日期 |
| `days` | int? | None | 目标天数，给定则均摊每日预算 |
| `daily_time_minutes` | int? | None | 覆盖画像里的每日时长；都没有则用配置兜底 |
| `default_start_hour` | str? | None | 如 `"19:00"`；给定才生成时段，否则纯日期清单 |
| `title` | str? | None | 自定义标题 |

### 典型用法

```python
from backend.models.schemas import StudyPlanGenerateRequest
import backend.services.study_plan as sp

plan = await sp.generate_study_plan(
    user_id,
    StudyPlanGenerateRequest(default_start_hour="19:00", days=7),
    db,
)
if plan is None:
    ...  # 没有候选知识点，提示用户先建立学习路径或完善画像
```

> `update_study_plan_item` 在标记完成（`is_completed=True`）且该项有 `kp_id` 时，会自动写一条 `LearningRecord(action="complete")`，接入系统已有的"已学习视图"。

### 返回结构

`StudyPlanOut` 含 `items: list[StudyPlanItemOut]`（已按 `(scheduled_date, order_index)` 排序）。每个 item 的 `resources` 是已匹配资源的轻量引用（`resource_id / resource_type / title`，不含正文），`missing_resource_types` 是待懒生成的类型列表。

## 七、配置

配置段 `study_plan`（`configs/config.yaml` + `backend/config.py` 的 `StudyPlanConfig`）：

| 配置项 | 默认 | 说明 |
|--------|------|------|
| `default_daily_minutes` | 60 | 画像未设置每日时长时的兜底值 |
| `default_start_hour` | "19:00" | 默认每日起始时刻（仅在要求生成时段时使用） |
| `default_horizon_days` | 14 | 未指定 days 时的排程跨度参考 |
| `min_kp_minutes` / `max_kp_minutes` | 20 / 180 | 单知识点时长钳制区间 |
| `default_kp_minutes` | 45 | LLM 未给出预估时的默认单点时长 |
| `target_resource_types` | `[doc, mindmap, quiz]` | 计划项默认匹配/补全的资源类型 |
| `sequence.temperature` / `sequence.max_tokens` | 0.3 / 2048 | 排序 LLM 参数 |

排序提示词位于 `configs/prompts.yaml` 的 `agents.study_plan.sequence`；其中 `{min_kp_minutes}`/`{max_kp_minutes}` 由 `PromptsConfig.get()` 在加载时解析。

## 八、测试与验证

`tests/test_study_plan.py`（`asyncio_mode=auto`，16 个用例全过）：

- **scheduler（纯函数）**：日预算不超限、放满滚下一天、单点超预算独占日、时段连续不重叠、`days` 压缩、`order_index` 按天重置、空输入。
- **sequencer 回退**：薄弱点提前/已掌握靠后、回退保留全部候选。
- **sequencer（mock LLM）**：解析 JSON、过滤编造知识点、JSON 失败回退、漏项补齐、时长钳制。

端到端验证（真实 DB + mock LLM）已确认：流水线串通、薄弱点被排到首位、每日不超预算、时段不重叠、已有资源正确匹配、list/complete/delete 全部正常。迁移已验证 downgrade/re-upgrade 可逆。
